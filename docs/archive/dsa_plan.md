# DSA with Python — Section Plan

> A complete "zero → big-tech ready" Data Structures & Algorithms track for Python Central Hub.
> Teaches DSA for **competitive programming (CP)** and **cracking big-tech interviews**, with
> in-browser problem solving, rich visualizations, and graded exercises.

---

## 1. Context & Goals

**Why:** The site already covers Python, Data Analytics, ML/DL, Math-for-ML, Flask, and Testing.
There is no DSA track. DSA is the single most-requested topic for interview prep and CP, and it
pairs perfectly with the site's existing interactive tooling.

**Outcome — a learner can:**
- Go from complexity basics to advanced CP topics (segment trees, DP-on-trees, flows).
- **Solve LeetCode-style problems in-page** (real Python runs in the browser).
- Master the ~15 named interview patterns and the classic CP toolkit.
- Understand *why* Python is sometimes too slow, and how to beat TLE.

**Confirmed scope decisions:**
| Decision | Choice |
|---|---|
| In-page solving | **Both** — Pyodide playground for CP/problem sets, `DataCampExercise` (SCT-graded) inside lessons |
| Depth | **Zero → big-tech ready** (full breadth incl. advanced CP) |
| Sidebar | **One section**, ordered tracks (phases) inside |
| CP extras | Python speed/TLE tricks • Big-O deep dive (p5 viz) • Templates/snippets library • Contest strategy |

### Content location & naming rules (repo gotchas)
- Top folder: `src/content/docs/DSA with Python/` (spaces OK for the top folder, matches
  `Data Analytics`, `Machine Learning`).
- Sub-folders: `Phase-01-Foundations`, `Phase-02-…` — **hyphen-joined, zero-padded**, matching the
  Data Analytics convention. Controls sidebar order + route slug.
- **Never use `" - "` (space-hyphen-space) in file/folder names** — it collapses to `---` in the
  route slug (known bug). Use single hyphens.
- Avoid Windows-invalid filename chars (`: \ / * ? " < > |`). Use ` ```python ` blocks, never
  `is:inline` scripts, per repo conventions.
- Ordering: prefer `Phase-NN` folder prefixes for track order + `sidebar: order:` within a folder.

## 3. Page anatomy (the standard template every topic page follows)

Each algorithm/DS page follows the same repeatable spine so the section feels uniform:

1. **Intro & intuition** — what/why, real-world analogy, where it shows up in interviews/CP.
2. **Visual** — a `p5` animation *or* `mermaid` diagram of the core idea.
3. **How it works** — step-by-step, with a mermaid recursion/state diagram where useful.
4. **Complexity** — time/space table + Big-O in KaTeX; note the *Python constant-factor* reality.
5. **Reference implementation** — clean, idiomatic ` ```python ` block (runnable in-page).
6. **Python specifics** — stdlib shortcuts (`bisect`, `heapq`, `deque`, `Counter`, `functools`)
   and TLE/fast-I/O notes where relevant.
7. **Common pitfalls** — `:::caution` callouts (off-by-one, mutable defaults, recursion limit…).
8. **Practice** — 2–4 `DataCampExercise` drills (graded) + a "Try it" python playground block.
9. **LeetCode problem set** — curated list (Easy→Hard) with problem numbers + pattern tags; each
   solvable in the in-page playground; annotated solutions in collapsible ` <details> `.
10. **Cheatsheet recap** — key template + complexities in one glance.

## 6. Exercise & problem-solving strategy

- **Inside lessons** → `DataCampExercise` blocks: short, graded (`sct`), with progressive `hint`s.
  Use for "implement this function", "fix the bug", "complete the template".
- **Free experimentation / CP** → plain ` ```python ` blocks (auto-runnable Pyodide). Use for
  "try it yourself", full solutions, and Phase-11 problem sets.
- **LeetCode solving experience** → problem statement + constraints + an editable python block
  pre-seeded with a signature stub + sample tests the learner can run; full editorial hidden in
  ` <details> `. (Pyodide is stdlib-only — no `leetcode` runtime — so we ship our own sample
  asserts rather than pretending to hit LeetCode's judge; note this limitation in Phase-01.)
- Difficulty labels (Easy/Medium/Hard) + pattern tags on every problem for filterable grinding.
