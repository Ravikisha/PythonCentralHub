### The five real gaps

**1. The walkthrough does not match the shipped code — 183 of 203 pages.**
This is the one that matters, and it is a correctness bug rather than a polish
issue. Each page has a `## Code Breakdown` section presenting numbered snippets
"from" the project file, and on 183 pages at least one snippet defines a
function or class that **does not exist in the file the page ships**.

`Advance/customer_segmentation_ml.mdx` walks the reader through:

```python
def segment_customers(df):
    kmeans = KMeans(n_clusters=3)
    ...
def main():
    print("[Demo] Segmentation logic here.")
```

while `projects/advance/customer_segmentation_ml.py` actually contains a
`class CustomerSegmentationML` with `fit`, `predict` and `plot_clusters`, and a
`__main__` block that generates random data and plots it. A reader following
the page cannot arrive at the file, and the file's real design is never
explained. No amount of added visualisation fixes a page that explains code
that does not exist.

**2. The Advance tier is one template filled in 117 times.** 113 of the 117
pages share a byte-identical heading skeleton (Abstract → Prerequisites →
Before you Start → Getting Started → Create a Project → Write the Code →
Example Usage → Explanation → Features → Next Steps → Educational Value →
Real-World Applications → Conclusion). Worse, **24 pages across 5 groups have
identical prose once the project name is stripped out**:

- `real_time_demand_forecasting`, `real_time_inventory_management`,
  `real_time_price_optimization`, `real_time_product_classification`,
  `real_time_sales_forecasting`
- `real_time_image_classification`, `real_time_image_extraction`,
  `real_time_image_generation`, `real_time_image_segmentation`,
  `real_time_image_translation`
- `automated_code_review_system` / `automated_code_review_tool`
- `real_time_credit_scoring` / `real_time_risk_assessment`

Those groups are not five projects each; they are one project each, renamed.
The sections that should carry the teaching — Features, Educational Value,
Real-World Applications, Conclusion — are generic filler in every case
("Modular Design", "Production-Ready", "Business Intelligence").

**3. Nothing on any page is verified, and nothing is measured.** 264 project
files parse cleanly, which is the only thing currently checked. Nothing runs
them. `## Example Usage` shows the command but never its output, so a reader
has no way to tell a working project from a broken one — and neither does the
author. 57 of 153 Advance files are under 30 lines, several of which cannot do
what their page claims.

**4. Nothing is interactive or visual.** Zero figures, zero quizzes, zero
exercises across 203 pages, and 41 mermaid diagrams spread over 41 of them.
Every one of these projects *produces* something — a clustering, a plot, a
detection, a latency number — and none of that output appears on its page.

**5. The sidebar is broken and the MDX has real hazards.**

claimed by three pages, 63 by three more, and so on for 62 collisions), and 29
brace warnings in intermediate — `showLineNumbers{150}` and bare dict literals
in prose, which MDX evaluates as JavaScript.

## 2. Target shape for a project page

The Deep Learning contract, adapted. A project page's equivalent of "every
number is measured" is **the project actually runs, and the page shows what it
produced**.

- `## What you'll build` — 3–5 bullets naming the concrete artefact and the
  measurable thing it does, not "demonstrates best practices".
- `## What it does` — the real output. A captured run, a produced image, a
  timing, a score. Generated by the runner, not written by hand.
- **The design, in a mermaid diagram** — modules, data flow, where the state
  lives. One per page, drawn from the actual file.
- `## The code, walked through` — snippets **extracted from the shipped file**
  rather than retyped, so the two cannot drift. Anchored by function or class
  name and checked in CI.
- **1–2 generated figures** (`<Figure>`, dark + light SVG from
  `scripts/figures/projects/…`) showing something the project measures: the
  clusters it found, the latency curve, the accuracy against a baseline, the
  memory profile.
- **1 p5 sketch** for anything with a knob — number of clusters, threshold,
  window size, difficulty setting.
- `## Try it` — a `<DataCampExercise>` with one blank, using the project's own
  code and a verified expected output.
- `## Pitfalls` — the failure modes of *this* project, ideally ones hit while
  making it run.
- `## Extend it` — three concrete, sized extensions, each naming what would
  have to change.
- `## Recap` — 4–6 lines, each carrying a number or a name.
- A `<Quiz>` of 3–5 questions about decisions in the code, not trivia.

Beginner pages keep their `## Common Mistakes` and `## Variations to Try`
sections, which already do part of this job well.

## 5. Tooling (wave 0 — built 2026-08-08)

```
scripts/projects_audit.py        # per-page contract report + progress log
scripts/projects_run.py          # headless execution ledger
scripts/extract_snippets.py      # walkthrough generated from the shipped file
scripts/figures/projects/        # figure group, reading the run ledger
```

`projects_run.py` executes each file as a subprocess in a scratch directory
with stdin closed and `MPLBACKEND=Agg`, records stdout, stderr, wall clock and
any artifact left behind, and writes `docs/projects_run_ledger.json`. Module
availability is probed against the live interpreter rather than hardcoded, so
the classifier stays correct as dependencies come and go.

**First full run: 264 files, 60 ran, 14 failed, 190 skipped with a stated
reason.** By tier:

| Tier | Ran | Failed | Needs stdin | Needs a display | Module missing | Other |
| --- | --- | --- | --- | --- | --- | --- |
| beginners | 3 | 4 | 25 | 8 | 12 | 0 |
| intermediate | 1 | 0 | 2 | 19 | 35 | 2 |
| advance | 56 | 10 | 24 | 4 | 57 | 2 |

Three things that changes about the plan:

**The 14 failures are real bugs, not environment gaps**, and several are
one-line fixes: `real_time_inventory_management` calls `DataFrame.append`,
removed in pandas 2; `credit_card_fraud_detection` and `wordcounter` open data
files that are not in the repo; `automatic_file_organizer` and
`bulk_image_compressor_and_resizer` have required argparse arguments and no
defaults, so they cannot be demonstrated at all.

**60 projects ran and produced exactly one artifact between them.** Every
matplotlib project calls `plt.show()`, which under `Agg` draws nothing and
saves nothing. Changing those calls to `savefig` is the single cheapest change
in this plan: it converts roughly 35 projects from "runs silently" into "runs
and produces the figure its page should show".

**The missing-module tail is longer than the plan assumed** — 104 files, not
the 18 estimated from `cv2` alone:

| Module | Files blocked | | Module | Files blocked |
| --- | --- | --- | --- | --- |
| cv2 | 25 | | nltk | 8 |
| flask | 19 | | schedule | 7 |
| bs4 | 11 | | googletrans | 6 |
| speech_recognition | 9 | | pygame | 6 |

`bs4`, `flask`, `nltk`, `schedule`, `seaborn` and `plotly` are ordinary pip
installs that would unblock roughly 50 files between them. `cv2`,

`extract_snippets.py` was validated against the section and reproduces the
183-page figure independently. Applying it is wave 1; a dry run on

## 7. Wave 1 — what it fixed, and what it found (2026-08-08)

`scripts/check_docs.py` on the projects section: **91 problems → 0.**
Stale walkthrough snippets: **570 → 336.**

Four fixes:

- **117 templated Advance walkthroughs regenerated from their source files.**
  Every snippet now quotes real code with its true line numbers, and
  `extract_snippets.py` can regenerate them whenever a project changes.
  Advance pages carrying a stale snippet: 115 → 0.
- **`content-management-system.mdx` had an unterminated code fence.** Line 125
  used ```` ```bash ```` as a closing fence, which paired every later fence
  wrongly and left the last block open to end of file. That single bug produced
  17 of the 29 brace warnings.
- **16 real `sidebar.order` collisions** in Beginners and intermediate, fixed by
  renumbering those two folders sequentially. The other 70 reported collisions
  were across folders, which Starlight cannot act on — both `check_docs.py` and
  `projects_audit.py` now scope the check per folder.
- **Two checker bugs.** `check_docs.py` did not blank single-line self-closing
  components, so `showLineNumbers={1}` on a one-line `<FileCode … />` read as a
  prose brace. Fixing it removed 44 false positives **site-wide** (270 → 53
  problems across all modules), none of them in the projects section.

### The finding that changes waves 3 and 4

The 336 snippets still stale are all on the **85 bespoke pages** in Beginners
and intermediate — the ones with hand-written, project-specific walkthroughs
rather than the Advance template. Those must not be swept, because the drift
runs in two opposite directions:

| Direction | Pages | What it means | The fix |
| --- | --- | --- | --- |
| **Page ahead of file** | **42** | The page teaches code that was never written | Write the code |
| Page behind file | 26 | The file moved on without the page | Update the page |

`Beginners/fibonaccisequence` is the clearest case. The page teaches five
implementations — iterative, recursive, memoised, a generator and Binet's
formula — with complexity analysis for each. The file it ships is 23 lines with
a bare `input()` and no functions at all. Running the extractor on that page
would replace five algorithms with a `while` loop: the page is *better than the
code*, and mechanically enforcing agreement would destroy the teaching.

The same holds at scale: `file-encryption-tool` documents 57 symbols against a
file defining 13; `rest-api-auth` 65 against 28; `morse-code-audio-player` 59
against 30.

So waves 3 and 4 gain a task the plan did not have: **for 42 pages, bring the
project file up to what the page already teaches.** That is more work than
editing prose, but it is the version that leaves a reader able to run what they
just read — and it doubles as the fix for several `needs stdin` skips in the
run ledger, since a file with functions can be imported and tested where a bare
script cannot.

## 8. Wave 2 — the duplicate groups, rewritten rather than deleted (2026-08-08)

§6 asked whether to delete the 19 redundant pages. The measurement answered it:
**they were not duplicate projects, they were duplicate prose over distinct but
hollow code.** `real_time_image_extraction` "extracted features" by returning
`np.mean(image)`; `real_time_image_translation` was a single `np.roll`. The
titles were fine; the implementations were placeholders, several carrying an
explicit `# Dummy ... for demo` comment.

So nothing was deleted. The ten files behind the two largest groups were
rewritten into projects that do what their titles claim, run headlessly and
produce a figure:

| Project | What it now measures |
| --- | --- |
| demand forecasting | walk-forward MAE **5.202** against a persistence baseline's 7.726 |
| sales forecasting | seasonal decomposition, MAE **15.5** vs 28.1; naive promotion lift is off by 52 units, de-seasonalised by 16 |
| inventory management | stockouts per reorder policy: **21 at point 10, zero at point 40**, from a 138-event log |
| price optimization | optimum **18.00**; elasticity estimated at 1.829 from 12 noisy points, costing 0.03% of profit |
| product classification | prequential accuracy **0.9990**, dropping to 0.9600 when a category appears, recovering to within 0.0010 |
| image extraction | a 51-number descriptor scores **1.0000** where the mean pixel scores 0.3200 against chance 0.3333 |
| image translation | whole-pixel round trip RMSE **0.000000**; 20 half-pixel shifts leave **46.4%** of edge energy |
| image segmentation | IoU **0.9447** against pixel accuracy 0.9848 — and 0.3650 IoU on the disc at 0.8250 accuracy |
| image generation | **~3,400 fps**, plus a variety measurement that catches a generator repeating one frame at full speed |
| image classification | latency against accuracy at four sizes, 0.334 ms to 1.472 ms, all inside a 33.3 ms budget |

Four bugs were found and fixed while making them run, each of the kind that
produces a plausible number rather than an error:

- the weekly profile was indexed by position **within the window** rather than
  by absolute day, so it silently returned a flat, shifted seasonality
- the promotion lift was a raw difference in means, confounded by which weekday
  promotions happened to fall on
- segmentation's timing included the first KMeans call in the process, making
  the cheapest configuration look 200x slower than the others
- segmentation's pixel accuracy compared raw cluster ids against truth ids,
  reporting 0.9979 for a segmentation whose real accuracy was 0.9848

Two experiments had to be redesigned because they proved nothing as first
written: the feature descriptor beat a single mean pixel 1.0000 to 1.0000 until
the classes were normalised to equal brightness **and** equal spread, and the
classifier scored 1.0000 at every input size until the two stripe classes were
moved close enough to the sampling limit to alias.

Section-wide, `plt.show()` was changed to save a file first in **38 projects**.
That is the change §5 predicted would be the cheapest in the plan, and it was:
a full run now produces **31 artifacts** against 1 before.

`## Explanation` bodies that were byte-identical once names were stripped:
**5 groups covering 24 pages → 0.**

## 9. Wave 3, first pass — making the projects runnable (2026-08-08)

Wave 3 is the Beginners tier, and it could not start where the plan said it
would. Only **3 of 46** beginner projects appeared in the run ledger, so there
was no real output for any page to show. The first pass therefore went at the
blocker rather than at the prose.

**Seven beginner projects now run unattended.** The pattern is three lines: an
`ask(prompt, default)` wrapper that catches `EOFError` and states the default
it fell back to. This is not a workaround for the test harness — a script that
dies the moment nobody is typing cannot be scheduled, tested, or demonstrated
either, and the fallback is visible in the captured output rather than hidden.

**`fibonacci_sequence_generator.py` was rewritten to match its page**, the
flagship "page ahead of file" case from §7. The page taught five
implementations with complexity analysis against a 23-line script with a bare
`input()` and no functions. The file now ships all seven the page discusses,
checks that they agree, and times them:

```
fib_rec (naive)     88.911 ms          1x
fib_memo             0.047 ms      1,888x
fib (loop)           0.006 ms     15,070x
```

and measures the claim the page makes about Binet's formula — exact to F(70),
off by 1 at F(71), off by 8,584 at F(90).

**Three classifier bugs** surfaced once projects started handling EOF, each of
which was skipping files that were perfectly runnable:

- a file containing the `ask()` helper still *mentions* `input(`, so the static
  check skipped it. It now exempts files that handle `EOFError`.
- `while True` inside a **generator** is bounded by whoever consumes it; it was
  being treated as a blocking loop.
- a `while True` that breaks on an EOF default terminates, so the loop check
  now only applies to files with no fallback. The per-file timeout is the
  backstop.

Together those took the ledger from 60 projects running to **68**.

**`scripts/projects_capture.py`** is new: it re-runs the projects that emit an
image and keeps the file under `public/images/projects/`. **30 images
captured.** A `<Figure>` on a project page is now the output of the program the
page ships, not an illustration drawn for it — and if the project stops
producing the image, `check_docs.py` reports the missing asset.

**67 pages gained a `## What it produces` section** carrying the real stdout
and, where there is one, that figure. Section figures: **0 → 31**.

### Still to do in wave 3

## 10. Wave 3, second pass — diagrams from code, contract on grounded pages

**`scripts/projects_mermaid.py`** generates a page's call-flow diagram from the
shipped file's AST: the entry point, the classes and functions it defines, and
which of them calls which. A hand-drawn diagram goes stale the moment the code
changes and a generic one ("Input → Process → Output") says nothing; this one
cannot drift, because it is read from the code each time it is regenerated.

**23 Beginners pages gained a diagram**, taking the tier from 12 to 35 of 46.
The remaining 10 are straight-line scripts with no functions at all — they get
no diagram, because inventing a call flow for code that has none would be worse
than leaving it out.

Section mermaid diagrams: **41 → 62.**

**Two pages now meet the full contract**, authored rather than templated:
`reversestring` and `tempconv`. They were chosen because their projects run, so
every claim traces to measured output:

- `reversestring` — Pitfalls covering the O(n²) recursion, `+=` on immutable
  strings, and that reversal works on code points rather than on what a reader
  sees; an exercise that times the three approaches and prints **111x, 283x,
  1,094x, 2,281x** as the string grows from 1,000 to 200,000 characters.
- `tempconv` — Pitfalls on the missing offset, `9//5` silently converting
  100 °C to 132 °F, and the difference between handling a *missing* answer and

Both exercises were run before being written down, which is how the numbers in
them got there.

## 11. Wave 3, third pass — installing the blockers (2026-08-08)

§6 asked whether to install OpenCV. The same trade as `torch` in the Deep

`opencv-python-headless`, `flask`, `beautifulsoup4`, `nltk`, `schedule`,

That did not translate into 49 more runs, and the reason is worth recording.
Many of the newly-importable projects **block instead of finishing**: a Flask

`projects_run.py` now recognises those calls statically and skips them with the

serves one request or reads one frame, and exits.

Net: **68 → 73 projects running**, and the sweep is back to about 3 minutes.

**Three more Beginners pages meet the full contract**, each grounded in its own
measured run:

- `randompasswordgenerator` — Pitfalls leading with `random` being the wrong
  module for a credential (`secrets` is the one-word fix). The exercise
  measures the length-versus-alphabet question rather than asserting it:
  16 characters from 52 letters is **469 billion times** more possibilities
  than 8 from 94 symbols.
- `dicerolling` — `randint` includes both endpoints where `randrange` does not,
  and the loop rolls before it asks. The exercise rolls up to 600,000 times and
  finds that in 10,000 sets of six rolls, **98.6% were missing at least one
  face** — so seeing all six is the surprising outcome, not the expected one.
- `binarytodecimal` — `bin()` returns `'0b1011'` rather than `'1011'`, and the
  shipped loop accepts `1021` as binary without complaint where `int(x, 2)`
  raises. The exercise implements both directions and demonstrates the
  rejection.

All three exercises were run before their numbers were written down; one quiz
explanation was corrected afterwards because the measured ratio was 469 billion
rather than the 300 billion first written.

Section totals: quizzes **2 → 5**, exercises **2 → 5**, mermaid **62 → 64**,
projects running **67 → 71** pages.

## 12. Wave 3, fourth pass — a Flask project that finishes (2026-08-08)

`scripts/projects_flask_smoke.py` gives Flask projects a run that returns.
`app.run()` never does, which is why they sat in the ledger as "blocks until
stopped" — untestable, unschedulable, and impossible to capture output from.

The fix is not to remove the server but to add what a web project should have
anyway: **a smoke path that dispatches one request per route through Flask's
test client** and prints what came back. No socket, no port, and the request
goes through the real application object, so the output is the app's actual
behaviour rather than a mock.

Serving became **opt-in**, behind `--serve`. That inversion is deliberate: with
no arguments the file now does something visible and finite, which is what a
reader running a teaching project wants, and the server is one flag away.

```
smoke test: dispatching one request per route

  GET /                          200  Hello, World!

1 route(s) answered. Pass --serve to start the real server instead.
```

**A platform trap worth recording.** The first version guarded on
`sys.stdin.isatty()` — start the server for a person, smoke-test for a
harness. Under Git Bash on Windows `isatty()` returns **True even with stdin
redirected from `/dev/null`**, so the guard silently did nothing and every
project still hung. An explicit flag has no such ambiguity.

Six projects rewritten; **"blocks until stopped" 28 → 23**, projects running
**73 → 77**, pages carrying real output **71 → 74**.

Fifteen Flask projects were *not* rewritten, because they do not create their
app as a module-level `app = Flask(...)` — they build it inside a class or a
factory. Those need reading one at a time rather than a sweep, and the script
reports them rather than guessing.

## 13. Wave 3, fifth pass — the projects that were actually broken (2026-08-08)

The 13 runtime failures were the only category that was *wrong* rather than
merely unrunnable here. **13 → 5.** Four were genuine bugs in the code:

- **`portfoliowebsite`** imported `MimeText` and `MimeMultipart`. The stdlib
  spells them `MIMEText` and `MIMEMultipart`, so the file could never have run.
  Fixing it uncovered a second bug underneath: a `null` in a Python dict
  literal, pasted from JSON.
- **`automatic_file_organizer`** crashed with `FileExistsError` on a file
  named `no_extension`, because that is exactly the name of the folder it
  creates for extensionless files. Found by giving it a demo folder to
  organise — the collision does not occur unless someone actually runs it.
- **`wordcounter`** opened `text.txt` and died if it was absent. It now writes
  a sample when the file is missing, and checks its hand-written tally against
  `collections.Counter`.
- **`credit_card_fraud_detection`** read a 150 MB Kaggle CSV that is not in the
  repo. It now generates a set with the property that matters — 0.17% fraud —
  and the result is worth more than the fix: **99.85% accuracy while catching
  0 of 6 frauds**. The project now says so, because that is the entire lesson
  of an imbalanced problem.

Two more were unblocked rather than fixed:
`automatic_file_organizer`, `bulk_image_compressor_and_resizer` and
`image_segmentation` declared `required=True` arguments, so running them
produced `error: the following arguments are required` and nothing else. Each
now builds its own sample — a scratch folder of files, three generated JPEGs,
a scene with known regions — when given no arguments.

**`cv2.imshow` and `cv2.waitKey` were rewritten in 19 projects.** Headless
OpenCV has no GUI, and neither does a container or an SSH session, so both
raise. They now save the frame and print the path, with the window behind
`--show` — the same change `plt.show()` needed in wave 2, for the same reason.

Projects running **77 → 85**. Pages carrying real output **74 → 80**. Section
figures **31 → 34**.

### The five that remain, and why

| Project | Cause | Honest status |
| --- | --- | --- |
| `advanced_image_processing_with_opencv` | required `--input` | needs a sample image, same pattern as the other three |
| `object_detection_tensorflow` | wants a SavedModel that is not in the repo | needs a download, or a smaller model trained here |
| `automatedfilemover` | hardcoded Windows path | needs the demo-folder treatment |
| `basicwebscrapper` | the page it scrapes changed its markup | brittle by nature; needs a fixture or a stated live dependency |
| `amazon_price_drop_email_notifier` | the product URL 404s | same |

The last two are worth saying plainly: a project that scrapes a live site will
break whenever that site changes, and no amount of local fixing prevents it.
The right answer is a saved fixture for the test and a clear note that the live
version depends on someone else's HTML.

### What can be generated honestly, and what cannot

**Diagrams can.** `scripts/projects_mermaid.py` reads the shipped file and draws
what is actually in it. **130 pages can take one right now**; 8 more have no
functions at all and correctly get none. This is the single biggest remaining
win and it costs one command.

**A second visualisation can, for the pages that run.** 80 projects now execute
and 34 of them draw a figure. The other 46 print measured output — timings,
counts, comparisons — and that is enough for a p5 sketch of the same kind the
Deep Learning module uses: the project's own numbers, explorable, with the
conclusions computed from the data at runtime so the sketch cannot claim
anything the run did not produce.

**Pitfalls cannot, mostly.** A static pass over all 264 files finds real issues
on only **70** of them — 30 missing a `__main__` guard, 20 mutable default

pages. The rest has to be written.

**Quizzes and exercises cannot at all.** A generated quiz is the Advance
template problem again in a new costume: uniform, plausible, and empty. These
are authored, at roughly three pages per session, and the pages whose projects
run come first because their claims can be grounded in real output.

One change, and it is a correction rather than a concession: **a figure is
required only where the project produces one.** Demanding a matplotlib plot
from a text-based CLI tool would mean inventing a picture, which is exactly what
this section is being cured of. Every page still gets a diagram and a
visualisation; for the 169 without a natural figure, that visualisation is a p5
sketch built from the project's own run.

## 15. Wave 4 done, wave 5 abandoned — and why (2026-08-08)

**Wave 4 shipped.** `scripts/projects_mermaid.py` ran across all three tiers:
**mermaid diagrams 64 → 193**, on every page whose file defines a function. The
9 that got none are straight-line scripts with no call flow to draw. It also
surfaced a pre-existing bug: `realtime-chat.mdx` had a sample transcript pasted
after its Conclusion with **no opening fence**, leaving the file ending inside a
code block. Fixed.

**Wave 5 was attempted and dropped.** The idea was a p5 sketch built
automatically from each project's captured stdout — the project's own numbers,
explorable, on the 46 pages that run but draw nothing. It does not work, and
the failure is worth recording because it is the same failure this section was
being cured of.

A first version took the trailing number from each output line. On the
Fibonacci page that produced a bar reading **`fib (loop) ms  15971`** — where
15,971 was the *speedup ratio* from the neighbouring column and had nothing to
do with milliseconds. Plausible, well-formatted, and wrong.

Tightening the rule to lines carrying exactly one number fixed the mislabelling
and left two problems that cannot be fixed mechanically:

- **Mixed units on one axis.** The sales-forecasting page yields 180 days,
  15.458 MAE, 45.0 percent and 0.859 (a weekday multiplier). A bar chart over
  those is meaningless, and the "largest / smallest" line the sketch computes
  would compare a day count against a ratio.
- **Prose that parses as data.** `recovered weekly profile (1.00 = an average
  day):` yields a row labelled "recovered weekly profile" with value 1.0. That
  is a legend, not a measurement.

Yield after tightening was **9 pages of 203**. Nine pages is not worth a
mechanism that can silently mislabel, so `scripts/projects_sketch.py` was
deleted rather than left in the tree.

**What this means for the plan.** Visualisation on a project page comes from
one of two places, and there is no third:

1. **The project draws it.** 34 pages, already done, and the only route that
   scales without judgement.
2. **Someone writes it.** Everything else — which puts sketches in wave 7 with
   the quizzes and exercises rather than in a sweep of their own.

Wave 5 is struck from the plan. Wave 6 (code-smell Pitfalls on the 70 files
with real findings) still stands, and wave 7 grows to include authored sketches.

## 16. Unblocking the input-driven projects (2026-08-08)

The constraint on wave 7 is not writing speed, it is that a page whose project
does not run has nothing honest to put in Recap. 56 projects were stopping at
`EOFError`, so this went at those before writing another page.

`scripts/projects_demo_input.py` rewrites every `input(...)` into
`ask(..., default)` and inserts the wrapper. The default is inferred from the
prompt — a `(y/n)` question gets `n`, `how many` gets a small number, a filename
prompt gets one — and the fallback prints what it substituted, so the captured
output never hides an assumed answer.

**Inference is a guess, so nothing is trusted.** Every rewritten file is
executed and **any file that does not then run is reverted**. What survives is
only what was demonstrated to work.

The first pass kept **6 of 52**, and the reason 14 of the rest failed is
instructive: a menu-driven program answered `1` forever never reaches its exit
branch, so it ran until the timeout. The default for a menu has to be the option
that *leaves*, and the program advertises which that is — it prints it. Reading
the exit option out of the menu the program itself displays (`print("E. Exit")`,
`print("6. Exit")`) took the pass to **13 kept of 46 attempted**.

Combined with the classifier already exempting files that handle `EOFError`,
projects running went **85 → 102**, and pages carrying real output **80 → 94**.

A tooling note worth keeping: the exit-option regex silently matched nothing
for an hour because a `` written inside a shell heredoc arrived in the file as
an actual **backspace character (0x08)**. It parsed, it compiled, and it matched
nothing. Writing the pattern through a file rather than a heredoc avoids it.
