## Goal

Fraud datasets are usually highly imbalanced.

You will:

- Explore class imbalance
- Check feature distributions
- Build a baseline model evaluation plan

## Analysis pipeline

```mermaid title="Fraud detection analysis pipeline" desc="From raw transactions to a metric that actually matters for imbalanced data."
flowchart LR
  A["Raw transactions"] --> B["Check imbalance<br/>(value_counts)"]
  B --> C["Compare<br/>(feature dist. by class)"]
  C --> D["Visualize<br/>(kde/overlap)"]
  D --> E["Pick metric<br/>(precision/recall/AUC)"]
```

:::tip[From the book]
McKinney's frequency-table pattern — `value_counts()` or `Counter.most_common()` —
is exactly how you should first look at a fraud label. `df["fraud"].value_counts(normalize=True)`
often reveals something like 99.8% legit vs 0.2% fraud. A model that just predicts
"never fraud" would score 99.8% accuracy while being completely useless — which is
why accuracy alone is the wrong metric here.
:::

## Step 3: Visualize distributions


## Visualize it

```p5 title="Class imbalance: legit vs fraud" desc="The fraud bar is intentionally tiny - that is the whole challenge of this dataset." height="240"
function setup() {
  createCanvas(600, 240);
  textFont("monospace");
  noLoop();
}
function draw() {
  background(13, 17, 23);
  const gx = 80, gy = 20, gw = 400, gh = 170;
  stroke(60, 70, 84);
  line(gx, gy + gh, gx + gw, gy + gh);
  noStroke();
  const bw = 120;
  // legit: huge bar
  fill(75, 139, 190);
  rect(gx + 40, gy + gh - gh * 0.98, bw, gh * 0.98);
  fill(205);
  textAlign(CENTER, TOP);
  textSize(12);
  text("legit ~99.8%", gx + 40 + bw / 2, gy + gh + 8);
  // fraud: tiny sliver
  fill(255, 211, 67);
  const fraudH = Math.max(4, gh * 0.005);
  rect(gx + 240, gy + gh - fraudH, bw, fraudH);
  text("fraud ~0.2%", gx + 240 + bw / 2, gy + gh + 8);
}
```

## Step 4: Baseline modeling note

For fraud, accuracy is misleading.

Prefer:

- Precision / Recall
- F1 score
- ROC-AUC
- PR-AUC
