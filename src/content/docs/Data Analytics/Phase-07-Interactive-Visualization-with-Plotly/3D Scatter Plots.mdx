## Use 3D carefully

3D plots can look impressive but are often harder to interpret than they seem — a screen is 2D, so any 3D chart is really a **projection**, and projections distort distance and depth judgment. Two points that look close together might be far apart along the axis pointing "into" the screen.

Use 3D when:

- You genuinely need three continuous numeric variables plotted together
- Interaction (rotate/zoom) helps understanding, and the reader will actually rotate it
- Two 2D scatter plots (or a bubble chart) can't tell the same story

If you just want to add a third variable to a 2D scatter, prefer color or bubble size (see the previous two pages) — it's usually clearer than forcing a third spatial axis.

## Example

```python title="3D Scatter" showLineNumbers{1}
import pandas as pd
import plotly.express as px

df = pd.DataFrame({
    "x": [1, 2, 3, 4, 5],
    "y": [10, 6, 8, 4, 7],
    "z": [100, 120, 90, 150, 110],
    "group": ["A", "A", "B", "B", "A"],
})

fig = px.scatter_3d(df, x="x", y="y", z="z", color="group", title="3D scatter")
fig.show()
```

In the rendered chart, dragging rotates the camera and scrolling zooms — that interactivity is what makes a 3D plot usable at all; a static screenshot of the same figure often hides more than it reveals.

```p5 title="A 3D scatter, projected onto a 2D screen" desc="Points sit at (x, y, z); depth (z) is faked here with an isometric-style projection and size/brightness falloff." height="300"
const pts = [
  { x: 1, y: 10, z: 100, g: 0 },
  { x: 2, y: 6, z: 120, g: 0 },
  { x: 3, y: 8, z: 90, g: 1 },
  { x: 4, y: 4, z: 150, g: 1 },
  { x: 5, y: 7, z: 110, g: 0 },
];
const cols = [[255, 211, 67], [75, 139, 190]];
function setup() {
  createCanvas(600, 300);
  textFont("monospace");
  noLoop();
}
function project(p) {
  // simple isometric-ish projection: x/y form the ground plane, z lifts up-left
  const scale = 30;
  const gx = (p.x - 3) * scale;
  const gy = (p.y - 7) * scale;
  const iso = (gx - gy) * 0.6;
  const isoY = (gx + gy) * 0.3;
  const zLift = (p.z - 90) * 0.6;
  return { sx: width / 2 + iso, sy: height / 2 + isoY - zLift, depth: p.z };
}
function draw() {
  background(13, 17, 23);
  stroke(60);
  strokeWeight(1);
  line(60, height - 40, width - 60, height - 40);
  line(60, height - 40, width / 2 - 60, 40);
  noFill();

  const proj = pts.map(project).map((p, i) => ({ ...p, g: pts[i].g }));
  proj.sort((a, b) => a.depth - b.depth); // painter's algorithm: far first

  for (const p of proj) {
    const closeness = map(p.depth, 85, 155, 0.5, 1.5);
    const r = 14 * closeness;
    const c = cols[p.g];
    noStroke();
    fill(c[0], c[1], c[2], 220);
    circle(p.sx, p.sy, r);
    fill(255, 255, 255, 160);
    circle(p.sx, p.sy, 3);
  }

  fill(150);
  noStroke();
  textAlign(LEFT, TOP);
  textSize(11);
  text("bigger/higher = larger z (depth faked by size + lift)", 10, 10);
}
```

## Tips

- Rotate before you conclude anything — a single static angle can hide clusters or trends.
- Prefer `scatter_3d` only when a 2D-plus-color/size chart genuinely loses information.
- Heavy point counts get cluttered fast in 3D; consider sampling or aggregating first.

:::tip[Analyst's tip]
Interactivity does real work here: a 3D scatter plot is nearly useless as a still image, because any single camera angle can accidentally hide a cluster behind another. If you must share a 3D chart as a static export, first rotate to the angle that best shows the pattern — don't just export the default view.
:::
