## Why animations

Animations are useful when you want to show change over time as motion, not just as a static trend line:

- GDP vs life expectancy by year
- Covid cases by month

Under the hood, Plotly builds one **frame** per value of your animation column, then adds Play/Pause controls and a slider that swap between frames. It's not "real" motion — it's the same trick as a flipbook, just automated.

## Animated scatter (classic example)

```python title="Animated scatter" showLineNumbers{1}
import plotly.express as px

df = px.data.gapminder()

fig = px.scatter(
    df,
    x="gdpPercap",
    y="lifeExp",
    size="pop",
    color="continent",
    hover_name="country",
    log_x=True,
    size_max=60,
    animation_frame="year",
    animation_group="country",
    title="Gapminder: GDP vs Life Expectancy (animated)",
)

fig.show()
```

`animation_frame="year"` tells Plotly to build one frame per year; `animation_group="country"` tells it *which points in different frames are "the same point"* so a bubble smoothly moves/resizes instead of popping to a new spot each frame.

```p5 title="Animation = swapping between precomputed frames" desc="Each 'year' is a frame; points move smoothly between their positions in consecutive frames, like a flipbook." height="280"
const frames = [
  [{ x: 10, y: 40, r: 14 }, { x: 30, y: 60, r: 20 }, { x: 55, y: 30, r: 10 }],
  [{ x: 20, y: 50, r: 18 }, { x: 45, y: 55, r: 24 }, { x: 60, y: 35, r: 12 }],
  [{ x: 35, y: 65, r: 22 }, { x: 55, y: 45, r: 28 }, { x: 65, y: 40, r: 14 }],
  [{ x: 50, y: 75, r: 26 }, { x: 60, y: 35, r: 32 }, { x: 70, y: 48, r: 16 }],
];
const cols = [[255, 211, 67], [75, 139, 190], [165, 214, 164]];
let frameLen = 90;
function setup() {
  createCanvas(600, 280);
  textFont("monospace");
}
function draw() {
  background(13, 17, 23);
  const total = frames.length;
  const t = (frameCount % (total * frameLen)) / frameLen;
  const i0 = Math.floor(t) % total;
  const i1 = (i0 + 1) % total;
  const frac = t - Math.floor(t);

  const padL = 60, padB = 40, padT = 30;
  const w = width - padL - 40, h = height - padT - padB;

  stroke(90);
  line(padL, padT, padL, padT + h);
  line(padL, padT + h, padL + w, padT + h);

  for (let k = 0; k < frames[i0].length; k++) {
    const a = frames[i0][k], b = frames[i1][k];
    const x = padL + lerp(a.x, b.x, frac) / 80 * w;
    const y = padT + h - lerp(a.y, b.y, frac) / 80 * h;
    const r = lerp(a.r, b.r, frac);
    noStroke();
    fill(...cols[k], 200);
    circle(x, y, r);
  }

  fill(255, 211, 67);
  noStroke();
  textAlign(LEFT, TOP);
  textSize(12);
  text("frame " + (i0 + 1) + " / " + total, padL, 6);
}
```

## Tips

- Animations work best with fewer points (or aggregation) — dozens of moving bubbles read clearly, thousands become a blur.
- Add `animation_group` so Plotly tracks each entity across frames instead of treating every frame as unrelated data.
- Consider facets if animation is too visually busy — sometimes seeing all years at once, side by side, communicates the trend faster than watching it play out.

:::tip[Analyst's tip]
An animation is easy to watch once and hard to compare precisely — by the time frame 10 plays, the viewer has usually forgotten exactly where a point was in frame 1. If the real question is "how much did X change from start to end," a static before/after chart (or a line chart of the metric over time) usually communicates the change more reliably than motion does.
:::

```mermaid title="How Plotly animation frames work" desc="One data slice per animation value becomes one frame; animation_group links the same entity across frames."
flowchart LR
  A["DataFrame with a time/category column"] --> B["animation_frame=col<br/>one frame built per unique value"]
  B --> C["animation_group=id<br/>links the same entity across frames"]
  C --> D["Play / Pause / slider controls<br/>swap between precomputed frames"]
```
