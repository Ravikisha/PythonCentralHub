## When to use sunburst charts

Sunburst charts are for hierarchical breakdowns, where each level nests inside the one before it:

- Region → City → Store
- Category → Subcategory → Product

The center ring is the top of the hierarchy; each ring further out is one level deeper. A segment's **angle (arc width)** is proportional to its value, so you can see both "how big is this branch" and "how does it split further" in one picture. Use sunbursts when the hierarchy itself is part of the story — not just as a fancier pie chart.

## Example

```python title="Sunburst" showLineNumbers{1}
import pandas as pd
import plotly.express as px

df = pd.DataFrame({
    "region": ["West", "West", "North", "North"],
    "city": ["Pune", "Mumbai", "Delhi", "Chandigarh"],
    "sales": [120, 90, 180, 60],
})

fig = px.sunburst(df, path=["region", "city"], values="sales", title="Sales hierarchy")
fig.show()
```

`path=["region", "city"]` tells Plotly the nesting order (outermost group first); `values="sales"` sizes every arc. Clicking a ring segment in the rendered chart zooms into that branch — a built-in drill-down for free.

```p5 title="Sunburst = concentric rings, one per hierarchy level" desc="The inner ring is region, the outer ring is city — each arc's width is proportional to its sales value." height="320"
const data = [
  { region: "West", city: "Pune", sales: 120 },
  { region: "West", city: "Mumbai", sales: 90 },
  { region: "North", city: "Delhi", sales: 180 },
  { region: "North", city: "Chandigarh", sales: 60 },
];
const regionCols = { West: [255, 211, 67], North: [75, 139, 190] };
function setup() {
  createCanvas(600, 320);
  textFont("monospace");
  noLoop();
  angleMode(DEGREES);
}
function draw() {
  background(13, 17, 23);
  const cx = width / 2, cy = height / 2 + 10;
  const total = data.reduce((s, d) => s + d.sales, 0);

  // group by region for the inner ring
  const regions = {};
  for (const d of data) regions[d.region] = (regions[d.region] || 0) + d.sales;

  let a = -90;
  noStroke();
  for (const [region, val] of Object.entries(regions)) {
    const sweep = (val / total) * 360;
    fill(...regionCols[region], 200);
    arc(cx, cy, 130, 130, a, a + sweep, PIE);
    a += sweep;
  }

  // outer ring: city detail
  a = -90;
  for (const d of data) {
    const sweep = (d.sales / total) * 360;
    const c = regionCols[d.region];
    fill(c[0], c[1], c[2], 110);
    stroke(13, 17, 23);
    strokeWeight(2);
    arc(cx, cy, 240, 240, a, a + sweep, PIE);
    const mid = a + sweep / 2;
    const lx = cx + cos(mid) * 100, ly = cy + sin(mid) * 100;
    noStroke();
    fill(255);
    textAlign(CENTER, CENTER);
    textSize(11);
    text(d.city, lx, ly);
    a += sweep;
  }

  fill(150);
  noStroke();
  textAlign(LEFT, TOP);
  textSize(11);
  text("inner ring = region, outer ring = city", 10, 10);
}
```

## Tip

If your hierarchy is large, sunburst can become cluttered — thin outer rings become unreadable slivers. Consider bar charts (or a treemap) for top-level summaries, and reserve the sunburst for cases where the drill-down interaction genuinely helps.

:::tip[Analyst's tip]
Nested hierarchies are exactly the kind of "spatial" relationship a static table hides and a sunburst reveals instantly — but only if every level has a handful of children. Once a ring holds more than ~8-10 segments, switch to a treemap or a sorted bar chart; rectangles use screen space more efficiently than thin arc slivers.
:::
