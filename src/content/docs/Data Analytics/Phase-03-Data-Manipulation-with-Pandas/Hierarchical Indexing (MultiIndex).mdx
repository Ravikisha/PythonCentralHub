## Why stack more than one index level

Sometimes one label isn't enough to describe a row — "city" alone doesn't tell you
*which year*; "year" alone doesn't tell you *which city*. A **MultiIndex** lets a
single axis carry two or more levels at once, so you can keep working with a Series
or DataFrame instead of juggling nested dictionaries.

```python title="A Series with a MultiIndex" showLineNumbers{1}
import pandas as pd
import numpy as np

data = pd.Series(
    np.arange(9),
    index=[
        ["a", "a", "a", "b", "b", "c", "c", "d", "d"],
        [1, 2, 3, 1, 3, 1, 2, 2, 3],
    ],
)
print(data)
```

The blank-looking gaps in the printed output mean "same as the label directly above" —
it's just a display convenience, the index itself has no gaps.

## Partial indexing

With a hierarchical index, you can select using just the **outer** level:

```python title="Partial indexing on the outer level" showLineNumbers{1}
print(data["b"])         # every row where the outer level is "b"
print(data.loc["b":"c"]) # a slice across outer-level labels
```

You can also reach into the **inner** level directly:

```python title="Selecting from the inner level" showLineNumbers{1}
print(data.loc[:, 2])  # every row where the inner level equals 2
```

## Reshaping with unstack

A hierarchically indexed Series can be pivoted into a DataFrame with `unstack` —
the inner level becomes columns:

```python title="unstack turns levels into columns" showLineNumbers{1}
print(data.unstack())
```

Missing combinations (like `"b"` + `2`, which never existed) become `NaN`.

## Building a MultiIndex from DataFrame columns: set_index

More often, you'll have plain columns that you want to *promote* into a hierarchical
row index:

```python title="set_index builds a MultiIndex" showLineNumbers{1}
frame = pd.DataFrame({
    "city": ["pune", "pune", "delhi", "delhi"],
    "year": [2023, 2024, 2023, 2024],
    "sales": [100, 120, 200, 220],
})

frame2 = frame.set_index(["city", "year"])
print(frame2)
```

`reset_index` does the reverse — it moves the index levels back into ordinary columns:

```python title="reset_index undoes set_index" showLineNumbers{1}
print(frame2.reset_index())
```

## Reordering and sorting levels

```python title="swaplevel and sort_index(level=...)" showLineNumbers{1}
print(frame2.swaplevel("city", "year"))       # levels interchanged, data untouched
print(frame2.sort_index(level="year"))        # sort using just one level
```

## Aggregating by level

Many summary methods accept a `level` argument, so you can aggregate across just one
part of the index without unstacking first:

```python title="groupby(level=...) for level-wise stats" showLineNumbers{1}
print(frame2.groupby(level="city").sum())
```

## Common pitfalls

- Partial indexing performance is much better when the index is sorted starting from
  the **outermost** level — call `sort_index()` after building a MultiIndex if you'll
  be slicing it a lot.
- `set_index` **drops** the columns you passed by default; pass `drop=False` if you
  still want them available as regular columns too.
- Selecting an inner level directly (`data.loc[:, 2]`) uses a different syntax than
  selecting the outer level (`data["b"]`) — easy to mix up at first.

## Visualize it

```mermaid title="From flat columns to a MultiIndex tree" desc="set_index promotes ordinary columns into hierarchical row-index levels; reset_index moves them back to being plain columns."
flowchart LR
  A["Flat columns:<br/>city, year, sales"] -->|"set_index(['city','year'])"| B["MultiIndex rows:<br/>city -> year -> sales"]
  B -->|"reset_index()"| A
  B -->|"groupby(level='city')"| C["Aggregated by outer level"]
```

```p5 title="A MultiIndex as a nested tree" desc="Each city branches into its years; sales values live at the leaves — this is what a two-level MultiIndex looks like structurally." height="280"
function setup() {
  createCanvas(600, 280);
  textFont("monospace");
  noLoop();
}
function draw() {
  background(13, 17, 23);
  const rootX = 60, rootY = 140;

  noStroke();
  fill(255, 211, 67);
  ellipse(rootX, rootY, 16, 16);
  fill(230);
  textAlign(LEFT, CENTER);
  textSize(12);
  text("index", rootX + 14, rootY);

  const cities = [
    { name: "pune", y: 70, years: [{ y: 2023, sales: 100 }, { y: 2024, sales: 120 }] },
    { name: "delhi", y: 210, years: [{ y: 2023, sales: 200 }, { y: 2024, sales: 220 }] },
  ];

  for (const city of cities) {
    const cx = 220;
    stroke(90, 100, 116);
    line(rootX + 8, rootY, cx - 8, city.y);
    noStroke();
    fill(75, 139, 190);
    ellipse(cx, city.y, 16, 16);
    fill(230);
    textAlign(LEFT, CENTER);
    text(city.name, cx + 14, city.y);

    const n = city.years.length;
    for (let i = 0; i < n; i++) {
      const leafX = 400;
      const leafY = city.y + (i - (n - 1) / 2) * 40;
      stroke(90, 100, 116);
      line(cx + 8, city.y, leafX - 40, leafY);
      noStroke();
      fill(120, 200, 140);
      ellipse(leafX - 40, leafY, 12, 12);
      fill(230);
      textAlign(LEFT, CENTER);
      textSize(11);
      text(city.years[i].y + "  →  sales=" + city.years[i].sales, leafX - 25, leafY);
    }
  }
}
```

:::tip[From the book]
McKinney frames hierarchical indexing as "a way for you to work with higher
dimensional data in a lower dimensional form" — a two-level MultiIndex Series
behaves like a small 2D table without needing a full DataFrame. This is exactly why
`groupby` on a duplicate-timestamp Series (covered earlier in this phase) and
`set_index` on multiple columns both lean on the same underlying MultiIndex machinery.
:::
