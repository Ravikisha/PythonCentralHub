## What is Jupyter Notebook?

**Jupyter Notebook** is an interactive environment where you can mix:

- **Code** (Python)
- **Text/notes** (Markdown)
- **Outputs** (tables, charts, images)

It’s widely used for:

- Exploratory data analysis (EDA)
- Learning and experimentation
- Quick visualization
- Sharing analysis as a single document

:::note
Jupyter Notebook vs JupyterLab
- **Notebook**: classic interface, simple and beginner-friendly.
- **Lab**: modern interface with tabs, file browser, terminals.

Both are great. Many people start with Notebook and later switch to Lab.
:::

## Launching Jupyter Notebook

### With Anaconda

1. Open **Anaconda Navigator**
2. Choose your environment (optional)
3. Click **Launch** on Jupyter Notebook

### From terminal

Activate your environment first, then run:

```bash title="command" showLineNumbers{1}
jupyter notebook
```

A browser tab opens with the Notebook dashboard.

## The Notebook dashboard (files home)

The first screen usually shows:

- A list of files/folders
- Buttons to create new notebooks

Recommended structure for your data analytics projects:

- A folder per project (e.g., `titanic-eda/`)
- A `data/` folder for CSV files
- A `notebooks/` folder for `.ipynb` notebooks
- A `reports/` folder for exported HTML/PDF (optional)

## Creating a new notebook

From the dashboard:

- Click **New** → **Python 3 (ipykernel)** (or similar)

A new `.ipynb` opens in a new tab.

## Understanding cells

Cells are the core concept of notebooks.

### Code cell

- Runs Python code
- Produces outputs

Example:

```python title="example" showLineNumbers{1}
import math
math.sqrt(81)
```

### Markdown cell

- Used for notes and documentation
- Supports headings, lists, links, tables, etc.

Example (Markdown cell):

```markdown
# Titanic EDA
This notebook explores passenger survival factors.
```

## Running cells

- Run current cell: `Shift + Enter`
- Run and insert new cell below: `Alt + Enter`
- Run without moving: `Ctrl + Enter`

When a cell runs:

- `In [1]:` indicates the execution order
- Outputs appear below the cell

## Kernels (the “engine” behind the notebook)

A **kernel** is the process that runs your code.

Key idea:

- If you restart the kernel, you lose variables in memory.
- You must run cells again to recreate them.

Common kernel actions:

- **Restart**: clears memory and restarts Python
- **Interrupt**: stops long-running code

In the menu:

- `Kernel` → `Interrupt`
- `Kernel` → `Restart`

## Saving notebooks

A notebook is stored as a `.ipynb` file (JSON-based format).

- Save: `Ctrl + S`
- Rename: click the title at the top

:::caution
Be careful with Git + notebooks
Notebooks store output in the file. This can cause large diffs.
Common practice:
- Clear outputs before committing (optional)
- Or keep outputs if the site wants them
:::

## Visualize it

Each time you run a cell, the kernel executes it and hands the result back to the notebook document.

```mermaid title="Notebook cell execution flow" desc="What happens between pressing Shift+Enter and seeing output"
flowchart LR
  A["Write code in a cell"] --> B["Press Shift+Enter"]
  B --> C["Kernel executes code"]
  C --> D["Kernel returns result"]
  D --> E["Output shown below the cell"]
  D --> F["In [n] execution count updates"]
```

:::tip[From the book]
McKinney describes IPython/Jupyter as encouraging an **"execute-explore" workflow instead of the typical edit-compile-run workflow** of many other languages. Because the notebook keeps your variables alive in the kernel between cells, you can inspect intermediate results (like `df.head()`) at any point instead of re-running an entire script — this is exactly why notebooks are so well suited to the trial-and-error nature of data analysis.
:::

## A recommended data analytics notebook workflow

1. **Import libraries** (NumPy, Pandas, Matplotlib)
2. **Load data** (CSV/Excel/SQL)
3. **Inspect data** (`head()`, `info()`, `describe()`)
4. **Clean data** (missing values, duplicates, types)
5. **Analyze** (groupby, aggregates)
6. **Visualize** (plots)
7. **Summarize findings** (Markdown cells)

## Helpful settings

### Auto-reload imports (optional)

In a notebook, you can auto-reload local modules:

```python title="autoreload" showLineNumbers{1}
%load_ext autoreload
%autoreload 2
```

### Exercise 1 – Track the Execution Counter

<DataCampExercise
  lang="python"
  hint={`Increment \`execution_count\` by 1 each time a cell "runs", just like Jupyter's In [n]:.`}
  code={`# Task: Exercise 1 – Track the Execution Counter
execution_count = 0

def run_cell(execution_count):
    execution_count ___ 1        # replace ___ with +=
    print(f"In [{execution_count}]:")
    return execution_count

execution_count = run_cell(execution_count)
execution_count = run_cell(execution_count)

# ── Expected Output ───────────────────────────────────────────
# In [1]:
# In [2]:
# ──────────────────────────────────────────────────────────────`}

def run_cell(execution_count):
    execution_count += 1
    print(f"In [{execution_count}]:")

execution_count = run_cell(execution_count)
execution_count = run_cell(execution_count)`}

success_msg("That's exactly how the In [n]: counter climbs as you run cells!")`}

### Exercise 2 – Classify a Cell as Code or Markdown

<DataCampExercise
  lang="python"
  hint={`If the text starts with "#", treat it as a Markdown heading; otherwise it's code.`}
  code={`# Task: Exercise 2 – Classify a Cell as Code or Markdown
cells = ["# Titanic EDA", "import pandas as pd", "df.head()"]

for cell in cells:
    if cell.___("#"):              # replace ___ with startswith
        print("markdown:", cell)
    else:
        print("code:", cell)

# code: import pandas as pd
# code: df.head()
# ──────────────────────────────────────────────────────────────`}

for cell in cells:
    if cell.startswith("#"):

    else:
        print("code:", cell)`}
