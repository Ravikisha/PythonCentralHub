## Aggregation functions

Common analytics aggregations:

- `COUNT(*)`: number of rows
- `COUNT(DISTINCT user_id)`: unique users
- `SUM(amount)`: total revenue
- `AVG(amount)`: average order amount
- `MIN()`, `MAX()`

```sql title="Total orders and revenue" showLineNumbers{1}
SELECT
  COUNT(*) AS orders,
  SUM(amount) AS revenue,
  AVG(amount) AS avg_order_value
FROM orders;
```

## GROUP BY

Group by a dimension:

```sql title="Revenue by country" showLineNumbers{1}
SELECT
  u.country,
  COUNT(*) AS orders,
  SUM(o.amount) AS revenue
FROM orders o
JOIN users u ON u.user_id = o.user_id
GROUP BY u.country
ORDER BY revenue DESC;
```

## HAVING

`HAVING` filters **groups** (after aggregation).

```sql title="Only countries with 100+ orders" showLineNumbers{1}
SELECT
  u.country,
  COUNT(*) AS orders
FROM orders o
JOIN users u ON u.user_id = o.user_id
GROUP BY u.country
HAVING COUNT(*) >= 100
ORDER BY orders DESC;
```

## Tip: avoid common mistakes

- Every selected non-aggregated column must be in `GROUP BY`.
- `WHERE` filters rows before grouping; `HAVING` filters after.

## Mental model: split → aggregate → combine

`GROUP BY` works the same way in every SQL dialect: rows are split into buckets by the
grouping column, an aggregate function collapses each bucket to one number, and the buckets
are combined back into a result table — one row per group.

```mermaid title="GROUP BY pipeline" desc="Rows are split into buckets by the grouping column, each bucket is collapsed by an aggregate, then combined into one row per group."
flowchart LR
  A["All rows"] --> B{"GROUP BY country"}
  B --> C["Bucket: IN"]
  B --> D["Bucket: US"]
  C --> E["SUM(amount) per bucket"]
  D --> E
  E --> F["One row per group"]
```

```p5 title="Rows collapsing into grouped totals" desc="Each colored dot is one order row; rows with the same country collapse into a single aggregated bar." height="260"
function setup() {
  createCanvas(600, 260);
  textFont("monospace");
  noLoop();
}
function draw() {
  background(13, 17, 23);
  const rows = [
    { country: "IN", amount: 40 },
    { country: "US", amount: 70 },
    { country: "IN", amount: 60 },
    { country: "IN", amount: 30 },
    { country: "US", amount: 50 },
  ];
  const colors = { IN: [255, 211, 67], US: [75, 139, 190] };

  fill(200);
  textAlign(LEFT, CENTER);
  textSize(11);
  text("rows", 20, 20);
  text("groups", 420, 20);

  let y = 45;
  for (const r of rows) {
    const c = colors[r.country];
    fill(c[0], c[1], c[2]);
    noStroke();
    circle(40, y, 14);
    fill(220);
    textAlign(LEFT, CENTER);
    text(r.country + "  " + r.amount, 55, y);

    stroke(c[0], c[1], c[2], 90);
    const targetY = r.country === "IN" ? 150 : 210;
    line(48, y, 440, targetY);
    y += 35;
  }

  noStroke();
  const totals = { IN: 130, US: 120 };
  let gy = 130;
  for (const key of Object.keys(totals)) {
    const c = colors[key];
    fill(c[0], c[1], c[2]);
    rect(440, gy - 12, map(totals[key], 0, 150, 0, 120), 24);
    fill(230);
    textAlign(LEFT, CENTER);
    textSize(11);
    text(key + ": SUM = " + totals[key], 570, gy);
    gy += 60;
  }
}
```

:::tip[Analyst's tip]
`COUNT(*)` counts rows, `COUNT(column)` skips `NULL` values in that column, and
`COUNT(DISTINCT column)` counts unique values. These three often give different numbers on
the same table — pick the one that actually answers your question (e.g. "how many orders"
vs. "how many unique customers").
:::
