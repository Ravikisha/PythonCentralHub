## Why window functions

Window functions let you compute metrics **across related rows** while keeping each row.

Common uses:

- Rank customers by revenue
- Running totals over time
- Moving averages

## ROW_NUMBER and RANK

```sql title="Rank orders by amount per user" showLineNumbers{1}
SELECT
  user_id,
  order_id,
  amount,
  ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY amount DESC) AS rn
FROM orders;
```

## Running total

```sql title="Running revenue by date" showLineNumbers{1}
SELECT
  order_date,
  daily_revenue,
  SUM(daily_revenue) OVER (ORDER BY order_date) AS running_revenue
FROM (
  SELECT
    DATE(order_ts) AS order_date,
    SUM(amount) AS daily_revenue
  FROM orders
  GROUP BY DATE(order_ts)
) t
ORDER BY order_date;
```

## PARTITION BY

- Splits data into groups
- Window function works within each group

Example: running revenue by country.

## Window functions vs GROUP BY

The key difference from `GROUP BY`: a window function does **not** collapse rows. Every input
row stays in the result, but each row also gets a computed value based on the rows around it
(its "window").

```mermaid title="How OVER (PARTITION BY ...) works" desc="PARTITION BY splits rows into windows; the function computes a value per row using only the rows in its own window."
flowchart LR
  A["All rows"] --> B{"PARTITION BY user_id"}
  B --> C["Window: user 1's rows"]
  B --> D["Window: user 2's rows"]
  C --> E["ROW_NUMBER / SUM ... per row"]
  D --> E
  E --> F["Same row count as input, plus a new column"]
```

```p5 title="Partitions computed independently" desc="Rows are grouped into colored partitions; RANK restarts at 1 inside each partition instead of continuing across the whole table." height="260"
function setup() {
  createCanvas(600, 260);
  textFont("monospace");
  noLoop();
}
function draw() {
  background(13, 17, 23);
  const partitions = [
    { color: [255, 211, 67], rows: [90, 60, 30] },
    { color: [75, 139, 190], rows: [80, 55] },
  ];

  let y = 30;
  for (const p of partitions) {
    fill(p.color[0], p.color[1], p.color[2]);
    noStroke();
    textSize(11);
    textAlign(LEFT, TOP);
    text("partition", 20, y);
    y += 24;

    const sorted = [...p.rows].sort((a, b) => b - a);
    for (let i = 0; i < sorted.length; i++) {
      fill(p.color[0], p.color[1], p.color[2], 60);
      rect(90, y - 4, map(sorted[i], 0, 100, 0, 220), 18);
      fill(230);
      textAlign(LEFT, CENTER);
      text("amount " + sorted[i] + "  ->  rank " + (i + 1), 320, y + 5);
      y += 28;
    }
    y += 20;
  }

  fill(200);
  textAlign(LEFT, TOP);
  textSize(10);
  text("each partition ranks 1, 2, 3... independently of the other", 20, 230);
}
```

:::tip[Analyst's tip]
`PARTITION BY` restarts the calculation for every group, the same way `GROUP BY` does — the
difference is that a window function still returns one output row per input row instead of
collapsing them. Forget `PARTITION BY` and your "per-user" rank or running total quietly
becomes a global one across the whole table.
:::
