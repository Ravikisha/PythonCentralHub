A string is just an array of characters — but Python makes that array
**immutable**, and that single fact quietly shapes almost every string
pattern you'll write.

## What you'll learn

- Why strings are immutable, and why that makes `s += chunk` in a loop
  $O(n^2)$ overall.
- Why building a list of pieces and calling `"".join(...)` is $O(n)$.
- `ord`/`chr`, ASCII, slicing, and one-line reversal.
- Complexity of common string operations.
- The anagram and palindrome patterns, runnable and ready to reuse.
- LeetCode-style problems to drill the pattern.

## The cue

:::tip[The one thing that makes Python strings different: immutability]
Every "modification" allocates a new string. That single fact drives almost
every performance decision here:

- `s += ch` in a loop is $O(n^2)$ — each concatenation copies the whole string.
  Collect into a list and `"".join(parts)` at the end for $O(n)$.
- Slicing copies. `s[1:]` inside a recursion is a hidden $O(n^2)$; pass indices
  instead.
- In-place two-pointer algorithms need `list(s)` first, then `"".join`.

Otherwise treat a string as an array of characters with the usual patterns —
two pointers, sliding window, frequency maps — and remember that a bounded
alphabet is what makes those frequency maps $O(1)$ space.
:::

## Strings are immutable

Every "modification" of a Python `str` actually builds a **brand-new**
string — the original is never changed in place.

```python title="immutability.py" showLineNumbers{1}
s = "hello"
t = s.upper()

print("original s:", s)   # unchanged
print("new string t:", t)
print("same object?", s is t)

# there is no s[0] = "H" — strings don't support item assignment
try:
    s[0] = "H"
except TypeError as e:
    print("TypeError:", e)
```

## The `+=` trap: O(n) per step, O(n^2) total

Because each `+=` builds a whole new string, concatenating in a loop copies
more and more characters every iteration.

```python title="concat_trap.py" showLineNumbers{1}
# O(n^2) total: each += copies the ENTIRE string built so far
def build_slow(n):
    s = ""
    for i in range(n):
        s += str(i)   # new string of growing length, every time
    return s


# O(n) total: collect pieces, join ONCE
def build_fast(n):
    parts = []
    for i in range(n):
        parts.append(str(i))   # O(1) amortized append to a list
    return "".join(parts)       # one O(n) join at the end


print(build_slow(5))
print(build_fast(5))
print(build_slow(5) == build_fast(5))
```

$$
\underbrace{1 + 2 + 3 + \dots + n}_{\text{copy cost per } \texttt{+=}} = O(n^2)
\qquad\text{vs.}\qquad
\underbrace{O(n)}_{\text{one join}}
$$

:::caution[The single most common string mistake]
`s += chunk` inside a loop looks harmless and passes on small inputs. On a
judge with large `n` it silently becomes $O(n^2)$ and times out. Always
collect pieces in a list and `"".join(...)` once.
:::

## `ord`, `chr`, and ASCII

Characters are just small integers under the hood — `ord` and `chr` convert
between a character and its code point.

```python title="ord_chr.py" showLineNumbers{1}
print(ord("a"), ord("z"), ord("A"))
print(chr(97), chr(122), chr(65))

# classic trick: map a lowercase letter to an index 0-25
def letter_index(c):
    return ord(c) - ord("a")

print(letter_index("a"), letter_index("m"), letter_index("z"))

# shift a letter (Caesar-cipher style), wrapping within a-z
def shift_letter(c, k):
    base = ord("a")
    return chr((ord(c) - base + k) % 26 + base)

print(shift_letter("x", 3))   # wraps past 'z'
```

## Slicing and reversal

Slicing works on strings exactly like it does on lists — and reversal is
one line.

```python title="string_slicing.py" showLineNumbers{1}
s = "algorithms"

print(s[1:5])     # substring
print(s[::-1])    # reversed copy, O(n)
print(s[-3:])     # last 3 characters
print(s[::2])     # every other character

print(s == s[::-1])   # palindrome check in one line
```

## Complexity of common string operations

| Operation | Example | Complexity |
| --- | --- | --- |
| Index access | `s[i]` | $O(1)$ |
| Slice of length $k$ | `s[a:b]` | $O(k)$ |
| Concatenation | `s1 + s2` | $O(n + m)$ |
| `+=` in a loop, $n$ times | `s += chunk` | $O(n^2)$ total |
| `"".join(parts)` | one call | $O(n)$ total |
| Search substring | `x in s` | $O(n \cdot m)$ worst case |
| Length | `len(s)` | $O(1)$ |

## Pattern: anagram check

Two strings are anagrams if they contain the same characters with the same
frequency. Sorting both is the simplest correct approach; counting is
faster for long strings.

```python title="anagram_check.py" showLineNumbers{1}
from collections import Counter


def is_anagram_sort(a, b):
    # O(n log n) — simple and clear
    return sorted(a) == sorted(b)


def is_anagram_count(a, b):
    # O(n) — compare character frequency counts
    return Counter(a) == Counter(b)


print(is_anagram_sort("listen", "silent"))
print(is_anagram_count("listen", "silent"))
print(is_anagram_count("rat", "car"))
```

## Pattern: palindrome check

A palindrome reads the same forwards and backwards. Two pointers converging
from both ends avoid building a reversed copy.

```python title="palindrome_check.py" showLineNumbers{1}
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True


def is_palindrome_alnum_only(s):
    # ignore case and non-alphanumeric characters, e.g. "A man, a plan..."
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]


print(is_palindrome("racecar"))
print(is_palindrome("hello"))
print(is_palindrome_alnum_only("A man, a plan, a canal: Panama"))
```

### LC 344 -- Reverse String · Easy

<summary>Editorial</summary>

Swap the outermost pair and move inward. `while left < right` handles both
parities: for an odd length the pointers land on the same index and the loop stops,
correctly leaving the middle character alone.

**Time** $O(n)$. **Space** $O(1)$.

Python's own `s.reverse()` is the idiomatic in-place answer, and `s[::-1]`
allocates a copy so it violates the stated constraint. Say both, then write the
loop -- the question exists to check the pointer mechanics.

### LC 14 -- Longest Common Prefix · Easy

**Problem.** Find the longest common prefix shared by all strings in an array.
Return `""` if there is none.

**Constraints.** `1 <= len(strs) <= 200`, `0 <= len(strs[i]) <= 200`, lowercase
letters.

**Examples.** `["flower","flow","flight"]` gives `"fl"` ·
`["dog","racecar","car"]` gives `""`

<DataCampExercise
  lang="python"
  hint={`Take the first string as a candidate prefix, then for each remaining word shrink the candidate from the right until the word starts with it. Return early if the candidate becomes empty. No sorting is needed -- and the empty-string case falls out naturally.`}
  code={`class Solution:
    def longestCommonPrefix(self, strs):
        # TODO: start with strs[0] as the candidate prefix and shrink it
        # until every word starts with it. Bail out early when it empties.
        pass


sol = Solution()
cases = [["flower", "flow", "flight"], ["dog", "racecar", "car"], ["a"], ["ab", "a"]]
print([sol.longestCommonPrefix(c) for c in cases])
# expect ['fl', '', 'a', 'a']`}
  solution={`class Solution:
    def longestCommonPrefix(self, strs):
        if not strs:
            return ""
        prefix = strs[0]
        for w in strs[1:]:
            while not w.startswith(prefix):
                prefix = prefix[:-1]        # shrink from the right
                if not prefix:
                    return ""
        return prefix


sol = Solution()
cases = [["flower", "flow", "flight"], ["dog", "racecar", "car"], ["a"], ["ab", "a"]]
print([sol.longestCommonPrefix(c) for c in cases])`}
  sct={`test_output_contains("['fl', '', 'a', 'a']")
success_msg("Shrink a candidate rather than growing one -- the early exit keeps it fast.")
`}
  height={280}
/>

<details>
<summary>Editorial</summary>

The answer can never be longer than the first string, so use it as an upper bound
and trim it against each word.

**Time** $O(\text{total characters})$ in the worst case. **Space** $O(1)$ beyond
the output.

`["ab","a"]` giving `"a"` is the case worth checking: the shorter word forces the
prefix down, so nothing may assume the first string is the shortest.

The vertical-scanning alternative -- compare character `i` across all words, stop
at the first mismatch -- is equally good and often clearer. A third option is to
sort and compare only the first and last strings, since they differ most; that is
$O(n \log n)$ but a nice observation.

**Follow-ups:** "Longest common *suffix*?" -- reverse everything and reuse this.
"Many queries against a growing dictionary?" -- a
[trie](../../phase-05-patterns-arrays-and-strings/trie-patterns/): the common
prefix is the path before the first branch. "Longest common *substring*?" -- a
much harder DP problem.

</details>

<details>
<summary>Editorial</summary>

`s.split()` with no separator splits on arbitrary whitespace runs and drops leading
and trailing empties, which is precisely the normalisation the problem asks for.

**Time** $O(n)$. **Space** $O(n)$.

The distinction that matters: `"a  b".split()` gives `['a', 'b']`, while
`"a  b".split(" ")` gives `['a', '', 'b']`. The second form keeps the empty token
and would put a stray double space in the output. Knowing that difference *is* the
Python content of this problem.

Because Python strings are immutable, a genuinely $O(1)$-space in-place solution is
not possible here. In C++ the expected approach is to reverse the whole string, then
reverse each word in place -- a neat trick worth describing if asked, and it is the
reason this problem is rated Medium.

**Follow-ups:** "Do it in $O(1)$ space?" -- impossible with immutable strings;
describe the reverse-all-then-reverse-each approach for a mutable buffer. "Reverse
the characters of each word but keep word order (LC 557)?" -- split, reverse each,
rejoin. "Without built-ins?" -- scan manually for word boundaries and build a list.

## Dry run

**Why `+=` in a loop is quadratic.** Building a 5-character string:

| step | operation | characters copied |
| --- | --- | --- |
| 1 | `"" + "a"` | 1 |
| 2 | `"a" + "b"` | 2 |
| 3 | `"ab" + "c"` | 3 |
| 4 | `"abc" + "d"` | 4 |
| 5 | `"abcd" + "e"` | 5 |

Total 15 copies for 5 characters — the sum $1 + 2 + \dots + n$, which is
$O(n^2)$. With `"".join(parts)` there is one allocation and $n$ copies.

At $n = 10^5$ that is 5 billion character copies versus 100,000 — the difference
between a TLE and an instant pass, from one line.

:::note[CPython sometimes optimises `s += ch`, and you should not rely on it]
When a string has exactly one reference, CPython can resize in place, making the
loop look linear. The optimisation silently disappears if anything else holds a
reference — so the quadratic behaviour is real, just intermittent. Use `join`.
:::

## The variant map

| Task | Approach | Complexity |
| --- | --- | --- |
| Build a string piecewise | list of parts + `"".join` | $O(n)$ |
| Reverse, or palindrome check | two pointers on `list(s)` | $O(n)$ time, $O(n)$ space in Python |
| Count characters | `collections.Counter` | $O(n)$ time, $O(1)$ space for a bounded alphabet |
| Anagram grouping | sorted string, or a 26-tuple, as the key | $O(n \log k)$ or $O(n)$ per word |
| Substring search | `in` (uses a tuned algorithm), or KMP by hand | $O(n + m)$ |
| Longest palindromic substring | expand around centre | $O(n^2)$ time, $O(1)$ space |
| Tokenise or parse | a stack, character by character | $O(n)$ |

Python specifics worth stating: `str.split()` with no argument splits on any
whitespace *and* drops empties, which is usually what you want; `str.isalnum()`
and `str.lower()` handle the LC 125 skip conditions without manual ASCII
arithmetic; and `ord(c) - ord('a')` is the index into a 26-slot count array.

## Interview follow-ups

| They ask | What they're checking | The answer |
| --- | --- | --- |
| "Why is `s += ch` in a loop slow?" | Immutability awareness | Each concatenation copies the whole string, so total work is $1 + 2 + \dots + n = O(n^2)$. Use a list and `join` |
| "Reverse a string in place" | Language honesty | Impossible in Python — strings are immutable. Convert with `list(s)`, two-pointer swap, then `"".join`. Say the $O(n)$ space is a language cost, not an algorithmic one |
| "Space complexity of your frequency map?" | Precision | $O(1)$ **for a bounded alphabet** — at most 26 keys. For arbitrary Unicode it is $O(\min(n, \lvert\Sigma\rvert))$ |
| "Is `in` for substring search $O(n \cdot m)$?" | Depth | CPython uses a tuned mixed algorithm that is effectively linear in practice. Worst case is not the naive bound, but if asked to implement it, write KMP |
| "Handle Unicode" | Care | Python 3 strings are already code points, so indexing is fine. Combining characters and normalisation are the real complications — mention `unicodedata.normalize` |
| "Compare two strings ignoring case and punctuation" | Practical fluency | Two pointers with `isalnum()` skips and `lower()`, in one pass and $O(1)$ space — no pre-filtered copy needed |

## Recall card

- **The governing fact** — Python strings are **immutable**. Every modification
  allocates.
- **Never `s += ch` in a loop** — that is $O(n^2)$. Collect into a list and
  `"".join(parts)`.
- **Slicing copies.** Pass indices in recursion rather than `s[1:]`.
- **In-place algorithms need `list(s)`** first, then join. Say that the $O(n)$
  space is a language cost.
- **Frequency maps are $O(1)$ space only for a bounded alphabet.** State the
  precondition.
- **Useful built-ins** — `split()`, `isalnum()`, `lower()`,
  `ord(c) - ord('a')` for a 26-slot count array.

## Recap

- Strings are immutable — every "change" builds a new string.
- `+=` in a loop is $O(n^2)$ total; collect pieces in a list and
  `"".join(...)` once for $O(n)$.
- `ord`/`chr` convert between characters and their integer code points.
- Anagram check: compare `Counter`s ($O(n)$) or sorted copies
  ($O(n \log n)$).
- Palindrome check: two pointers converging from both ends, $O(n)$ time,
  $O(1)$ extra space.
