:::note[Verified, including the stability guarantee]
```python
L = [3, 1, 2]
L.sort()          # returns None; L is now [1, 2, 3]
sorted([3,1,2])   # returns [1, 2, 3]; the input is unchanged
[1,2,3].reverse() # returns None
reversed([1,2,3]) # <list_reverseiterator ...>  -- not a list
```

**Python's sort is stable**, which is a documented guarantee and not an accident of the
implementation. Sorting `[('b',1), ('a',1), ('c',0)]` by the number gives:

```text
[('c', 0), ('b', 1), ('a', 1)]
```

`('b',1)` is still before `('a',1)` — their original order survived because their keys tied.

That is what makes multi-key sorting work by sorting more than once: sort by the *least*
significant key first, then by the most significant, and the earlier order is preserved within
ties. It is also why `sorted(rows, key=lambda r: r.name)` followed by
`sorted(rows, key=lambda r: r.dept)` gives departments in order with names ordered inside each.
:::
