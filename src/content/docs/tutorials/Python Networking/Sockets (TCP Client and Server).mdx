:::caution[TCP has no messages — measured]
A client sent two separate calls:

```python
c.sendall(b"HELLO")
c.sendall(b"WORLD")
```

A receiver looping on `recv(4)` got:

```text
[b'HELL', b'O', b'WORL']
```

Neither `sendall` arrived as a unit. The first was split across two reads, and the second began
in the middle of a read. **TCP guarantees the bytes arrive in order and intact; it guarantees
nothing about where they are divided.**

So `recv(n)` returning fewer than `n` bytes is normal, not an error, and two sends can arrive as
one read. Any protocol you build on a socket has to say where a message ends, and there are only
three ways to do it:

- **a length prefix** — send four bytes of length, then that many bytes;
- **a delimiter** — newline-terminated, and you buffer until you see one;
- **close the connection** to mean "that was everything".

A loop that assumes one `recv` equals one message works on localhost with small payloads and
fails as soon as there is real latency or a larger body.
:::

## What is a socket?

A **socket** is an endpoint for network communication.

For TCP:

- server listens on (host, port)
- client connects to (host, port)

## Simple TCP server

```python title="tcp_server.py" showLineNumbers{1}
import socket
import Quiz from "../../../../components/Quiz.astro";

HOST = "127.0.0.1"
PORT = 5050

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.bind((HOST, PORT))
    s.listen()
    print(f"Listening on {HOST}:{PORT}")

    conn, addr = s.accept()
    with conn:
        print("Connected by", addr)
        data = conn.recv(1024)
        print("received:", data.decode())
        conn.sendall(b"Hello client")
```

## Simple TCP client

```python title="tcp_client.py" showLineNumbers{1}
import socket

HOST = "127.0.0.1"
PORT = 5050

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.connect((HOST, PORT))
    s.sendall(b"Hello server")
    data = s.recv(1024)

print("received:", data.decode())
```

## Tips

- Use `127.0.0.1` for local experiments.
- Choose ports above 1024.
- Add timeouts (`s.settimeout(5)`) to avoid hanging.
