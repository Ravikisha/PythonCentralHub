**Big-O** notation answers one question: as the input gets bigger, how fast does the work
grow? It ignores constants and hardware and focuses on the *shape* of the growth — which is
what decides whether your code still works at a million items.

## What you'll learn

- what O(1), O(log n), O(n), and O(n²) mean in practice
- how dramatically they diverge as `n` grows
- how to spot each one in real code

## The common complexities

| Big-O | Name | Grows | Example |
|---|---|---|---|
| **O(1)** | constant | not at all | dict/set lookup, `list[i]` |
| **O(log n)** | logarithmic | very slowly | binary search |
| **O(n)** | linear | steadily | scanning a list, `x in list` |
| **O(n²)** | quadratic | explosively | nested loops, bubble sort |

## Watch them diverge

Same axes, four growth rates. At small `n` they look similar — but `O(n²)` shoots off the
chart almost immediately while `O(1)` and `O(log n)` barely move:

```p5 title="How algorithms scale with n" desc="O(1) stays flat, O(log n) crawls, O(n) rises steadily, and O(n squared) explodes off the chart." height="300"
function setup() {
  createCanvas(600, 300);
  textFont("monospace");
}
function draw() {
  background(13, 17, 23);
  const padL = 46, padB = 40, padT = 18, padR = 14;
  const gx = padL, gy = padT, gw = width - padL - padR, gh = height - padT - padB;
  stroke(60, 70, 84);
  strokeWeight(1);
  line(gx, gy + gh, gx + gw, gy + gh);
  line(gx, gy, gx, gy + gh);
  noStroke();
  fill(120);
  textSize(11);
  textAlign(CENTER, TOP);
  text("input size  n  →", gx + gw / 2, gy + gh + 16);
  push();
  translate(13, gy + gh / 2);
  rotate(-HALF_PI);
  textAlign(CENTER, CENTER);
  text("work  →", 0, 0);
  pop();
  const N = 40;
  const maxY = N;
  function plot(fn, col, label, ly) {
    stroke(col);
    strokeWeight(2.5);
    noFill();
    beginShape();
    for (let n = 1; n <= N; n++) {
      const v = min(fn(n), maxY);
      const x = gx + (n / N) * gw;
      const y = gy + gh - (v / maxY) * gh;
      vertex(x, y);
    }
    endShape();
    noStroke();
    fill(col);
    textAlign(LEFT, CENTER);
    textSize(12);
    text(label, gx + gw - 92, ly);
  }
  plot(function (n) { return 1; }, color(120, 200, 120), "O(1)", gy + 14);
  plot(function (n) { return Math.log2(n); }, color(107, 169, 221), "O(log n)", gy + 34);
  plot(function (n) { return n; }, color(75, 139, 190), "O(n)", gy + 54);
  plot(function (n) { return n * n; }, color(255, 211, 67), "O(n²)", gy + 74);
}
```

The lesson: an `O(n²)` algorithm that's fine for 100 items can be hopeless at 100,000. When
your data can grow, the Big-O is what matters — not how fast the code feels on a small test.
