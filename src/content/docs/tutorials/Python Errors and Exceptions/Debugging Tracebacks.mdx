:::note[Frame order, verified]
For `a()` calling `b()` calling `c()`, which raises:

```text
Traceback (most recent call last):
  File "<stdin>", line 17, in <module>     <- where it started
  File "<stdin>", line 14, in a
  File "<stdin>", line 15, in b
  File "<stdin>", line 16, in c            <- where it was RAISED
ValueError: boom                           <- what went wrong
```

The header says it: *most recent call last*. The bottom is the interesting end.

For a long traceback through a framework, the practical trick is to scan upward from the bottom
for the **first frame in a file you wrote**. Everything below it is usually library code doing
what it was told, and the mistake is normally in your frame or in the arguments it passed.

When two tracebacks are printed, the phrasing between them tells you which to read first:
*"During handling of the above exception, another exception occurred"* means the second one is
incidental, while *"The above exception was the direct cause"* means the first one is the real
story.
:::

## A repeatable debugging process

When you see an exception:

1. **Read the last line** (exception type + message)
2. **Go to the line number** where it occurred
3. Check the types/values of variables
4. Create a minimal reproduction
5. Fix and re-run

## Example traceback

```python title="bug.py" showLineNumbers{1}
def avg(nums):
    return sum(nums) / len(nums)

print(avg([]))
```

```text title="Traceback" showLineNumbers{1}
Traceback (most recent call last):
  File "bug.py", line 4, in <module>
    print(avg([]))
  File "bug.py", line 2, in avg
    return sum(nums) / len(nums)
ZeroDivisionError: division by zero
```

## Fix approach

- The list is empty, so `len(nums)` is 0.
- Decide policy: return `None`, raise a clear error, or handle with default.

```python title="fix.py" showLineNumbers{1}
def avg(nums):
    if len(nums) == 0:
        raise ValueError("avg() requires at least one number")
    return sum(nums) / len(nums)

print(avg([10, 20]))
```

## Quick tip: print types

```python title="type_debug.py" showLineNumbers{1}
value = "10"
print(type(value), value)
print(int(value))
```

## Optional: use the debugger

Python has a built-in debugger.

```python title="pdb_example.py" showLineNumbers{1}
import pdb

x = 10
pdb.set_trace()
print(x)
```

Useful commands inside the debugger:

- `n` next
- `s` step into
- `p var` print variable
- `c` continue

```p5 title="Read a traceback from the bottom" desc="The frames are printed in call order, so where it started is at the top and where it exploded is at the bottom, with the exception itself on the last line. Scanning upward from the bottom for the first frame in code you wrote is the fastest route to the mistake, because everything below that is usually a library doing what it was told." height="400"
const FRAMES = [
  { txt: 'File "app.py", line 17, in <module>', mine: true,  label: "where the call chain began" },
  { txt: 'File "app.py", line 14, in a',        mine: true,  label: "" },
  { txt: 'File "lib/thing.py", line 88, in run', mine: false, label: "library code" },
  { txt: 'File "lib/thing.py", line 42, in _do', mine: false, label: "" },
  { txt: "ValueError: boom",                     mine: null,  label: "what actually went wrong" },
];
let step = 0, last = 0;
function setup() { createCanvas(620, 400); textFont("monospace"); }
function draw() {
  background(13, 17, 23);
  if (millis() - last > 1300) { last = millis(); step = (step + 1) % 4; }
  noStroke(); fill(200); textSize(12); textAlign(LEFT, TOP);
  text("Traceback (most recent call last):", 20, 14);

  // highlight order: 0 none, 1 exception, 2 lowest own frame, 3 all
  for (let i = 0; i < FRAMES.length; i++) {
    const f = FRAMES[i], y = 44 + i * 44;
    const isExc = f.mine === null;
    let on = false;
    if (step >= 1 && isExc) on = true;
    if (step >= 2 && i === 1) on = true;
    if (step >= 3) on = true;
    fill(on ? (isExc ? color(60,30,32) : color(30,44,38)) : color(20, 25, 31));
    rect(20, y, 460, 36, 4);
    fill(isExc ? color(255,123,114) : f.mine ? color(140,210,160) : color(90,100,112));
    rect(20, y, 4, 36, 2, 0, 0, 2);
    fill(on ? 215 : 92); textSize(12); textAlign(LEFT, CENTER);
    text(f.txt, 38, y + 18);
    if (f.label) {
      fill(isExc ? color(255,123,114) : color(110,120,132)); textSize(9); textAlign(LEFT, CENTER);
      text(f.label, 492, y + 18);
    }
  }

  const notes = [
    "the whole traceback",
    "1. read the LAST line first -- the type and the message",
    "2. scan UP for the lowest frame in code you wrote",
    "3. only then read the frames above it",
  ];
  fill(210, 200, 160); textSize(12); textAlign(LEFT, TOP);
  text(notes[step], 20, 276);

  stroke(50); line(20, 306, 600, 306); noStroke();
  fill(150); textSize(10); textAlign(LEFT, TOP);
  text("The header says it: most recent call LAST. The bottom is the interesting end.", 20, 318);
  fill(219,171,90); textSize(10);
  text("Two tracebacks printed together? The wording between them tells you which matters:", 20, 342);
  text("'During handling ... another exception occurred'  -- the second is incidental.", 20, 358);
  text("'The above exception was the direct cause'        -- read the FIRST block.", 20, 374);
}
```
