:::caution[A `return` inside `finally` silently discards the exception]
Verified:

```python
def h():
    try:
        raise ValueError("lost!")
    finally:
        return "finally won"

h()        # 'finally won'  -- the ValueError is GONE
```

No traceback, no logging, nothing. The same happens with `break` and `continue` in a `finally`
inside a loop. And a `return` in `finally` also overrides a `return` in `try`:

```python
def g():
    try: return "from try"
    finally: return "from finally"     # 'from finally'
```

Python 3.14 now warns about this at compile time — `SyntaxWarning: 'return' in a 'finally'
block` — which is a good reason not to suppress that warning.

The observed order, for reference:

| Situation | Blocks that ran |
| --- | --- |
| no exception | `try`, `else`, `finally` |
| exception raised and caught | `try`, `except`, `finally` |

Use `finally` for cleanup only. If you need to change what the function returns, do it in
`else` or after the whole statement.
:::

## else in try/except

`else` runs **only if no exception occurred**.

```python title="try_else.py" showLineNumbers{1}
try:
    x = int("42")
except ValueError:
    print("Invalid number")
else:
    print("Parsed successfully:", x)
```

## finally in try/except

`finally` runs **always** (success or error). This is useful for cleanup.

```python title="try_finally.py" showLineNumbers{1}
f = None
try:
    f = open("data.txt", "r")
    print(f.read())
except FileNotFoundError:
    print("File not found")
finally:
    if f is not None:
        f.close()
        print("File closed")
```

## Prefer context managers when possible

Instead of manual `.close()`, use `with`.

```python title="with_open.py" showLineNumbers{1}
try:
    with open("data.txt", "r") as f:
        print(f.read())
except FileNotFoundError:
    print("File not found")
```

## When is finally important?

- closing files
- releasing locks
- closing DB connections
- cleaning up temporary files
