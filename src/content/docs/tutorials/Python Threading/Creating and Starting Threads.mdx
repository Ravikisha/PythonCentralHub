Calling it yourself executes the body on whatever thread you called it from, which means no concurrency at all and no error to tell you. start() is the one that asks the operating system for a thread and then invokes run there."

:::caution[`run()` instead of `start()` silently removes the concurrency]
Verified by asking each target which thread it was on:

| Launched with | `current_thread().name` |
| --- | --- |
| `t.start()` | `Thread-1 (work)` |
| `t.run()` | **`MainThread`** |

No exception, no warning. The program still produces the right output — just one job at a time,
which is why this survives review and shows up later as "threading made no difference".

Two related facts, both measured:

- **A thread cannot be restarted.** Calling `start()` on one that has finished raises
  `RuntimeError: threads can only be started once`. Make a new `Thread` object per run.
- **`is_alive()` is `False` after `join()`**, which is the reliable way to check completion —
  not the absence of output.
:::

## Basic Thread usage

```python title="basic_thread.py" showLineNumbers{1}
import threading


def greet(name: str) -> None:
    print("Hello", name)


t = threading.Thread(target=greet, args=("Ravi",))
t.start()
t.join()
print("Main thread finished")
```

## Naming threads

Naming is helpful for logs.

```python title="thread_name.py" showLineNumbers{1}
import threading


def work():
    print("Running in:", threading.current_thread().name)


t = threading.Thread(target=work, name="worker-1")
t.start()
t.join()
```

## Common mistakes

### 1) Forgetting join()

If you don’t `join()`, the main program may exit early in some cases.

### 2) Sharing data without protection

Threads share memory. You need locks (next pages).
