:::note[Verified: `set()` releases all of them, and stays open]
Three threads called `wait()`, then one `set()`:

| Moment | Log |
| --- | --- |
| before `set()` | `w0 waiting, w1 waiting, w2 waiting` — all parked, `is_set()` is `False` |
| after `set()` | `w0 released, w1 released, w2 released` — **all three** |
| a fourth waiter, arriving afterwards | `wait()` returned in **0.0000 s** |

That last row is the important half. An `Event` is **level-triggered**: once set it stays set,
so late arrivals are not missed. Compare `Condition.notify()`, which is edge-triggered — a
thread that was not yet waiting when the notify happened simply never hears it.

So use an `Event` for a state that latches: *ready*, *shutting down*, *configuration loaded*.
Use a `Queue` when there is something to hand over, and a `Condition` when the predicate can go
back and forth.
:::

## What is an Event?

An `Event` is a simple flag:

- one thread sets it
- other threads wait until it’s set

## Example

```python title="event_example.py" showLineNumbers{1}
import threading
import Quiz from "../../../../components/Quiz.astro";
import time

ready = threading.Event()


def waiter():
    print("Waiting...")
    ready.wait()  # blocks
    print("Go!")


def setter():
    time.sleep(1)
    ready.set()


t1 = threading.Thread(target=waiter)
t2 = threading.Thread(target=setter)

t1.start(); t2.start()
t1.join(); t2.join()
```

## Resetting an event

- `event.clear()` resets it to false.
- Useful for repeated cycles.
