## What you'll learn

- what a callback is, and the built-in callbacks Keras ships with

- writing your own callback by subclassing `keras.callbacks.Callback`
- monitoring live training/validation curves with TensorBoard

## From paper airplane to drone

Launching `model.fit()` on a long run is, in François Chollet's words, a bit
like launching a paper airplane: once it leaves your hand, you have no control
over where it goes. A **callback** turns that into a drone instead — an object
that Keras hands control to at specific points during training, with full
access to the model's current state, so it can interrupt training, save
weights, or adjust a parameter on the fly.

```mermaid title="Callback hooks inside model.fit()" desc="Keras calls into every registered callback at each of these points during training."
flowchart TD
  A["on_train_begin"] --> B["on_epoch_begin"]
  B --> C["on_batch_begin"]
  C --> D["on_batch_end"]
  D -->|"more batches<br/>in this epoch"| C
  D -->|"epoch finished"| E["on_epoch_end<br/>(EarlyStopping / ModelCheckpoint<br/>check here)"]
  E -->|"more epochs<br/>to go"| B
  E -->|"training<br/>finished"| F["on_train_end"]
```

## EarlyStopping and ModelCheckpoint

You rarely know in advance exactly how many epochs a model needs. The standard
fix: **`EarlyStopping`** interrupts training once a monitored metric (usually
`val_loss` or `val_accuracy`) stops improving for `patience` epochs, and
**`ModelCheckpoint`** continuously saves the model — with `save_best_only=True`,
it only overwrites the file when the monitored metric actually improves, so you
always keep the best version seen during training, not just the last one.

```python title="EarlyStopping and ModelCheckpoint together" showLineNumbers{1}
import tensorflow as tf

callbacks_list = [
    tf.keras.callbacks.EarlyStopping(monitor="val_accuracy", patience=2),
    tf.keras.callbacks.ModelCheckpoint(
        filepath="checkpoint_path.keras",
        monitor="val_loss",
        save_best_only=True,
    ),
]

model = tf.keras.models.Sequential([
    tf.keras.layers.Dense(64, activation="relu", input_shape=(10,)),
    tf.keras.layers.Dense(1, activation="sigmoid"),
])
model.compile(optimizer="rmsprop", loss="binary_crossentropy", metrics=["accuracy"])

print([type(cb).__name__ for cb in callbacks_list])

# model.fit(X_train, y_train, epochs=10,
#           callbacks=callbacks_list,
#           validation_data=(X_val, y_val))
```

Note that `EarlyStopping` is watching `val_accuracy`, so `"accuracy"` must be
part of the model's `metrics` — and because both callbacks need validation
numbers to watch, you must pass `validation_data` to `fit()`.

## Writing your own callback

If nothing built-in covers what you need, subclass `keras.callbacks.Callback`
and implement any of `on_train_begin` / `on_train_end`, `on_epoch_begin` /
`on_epoch_end`, or `on_batch_begin` / `on_batch_end`. Every method receives a
`logs` dictionary with whatever metrics are available at that point.

```python title="A custom callback that logs per-batch loss" showLineNumbers{1}
import tensorflow as tf

class LossHistory(tf.keras.callbacks.Callback):
    def on_train_begin(self, logs=None):
        self.per_batch_losses = []

    def on_batch_end(self, batch, logs=None):
        self.per_batch_losses.append(logs.get("loss"))

    def on_epoch_end(self, epoch, logs=None):
        print(f"epoch {epoch}: collected {len(self.per_batch_losses)} batch losses")
        self.per_batch_losses = []
```

## Monitoring with TensorBoard

Metrics printed to a progress bar are easy to lose track of over a long
experiment. **TensorBoard** is a browser-based dashboard that reads the logs a
`TensorBoard` callback writes during training, and lets you watch live curves,
inspect the model graph, and explore activation/gradient histograms.

```python title="Monitoring training with TensorBoard" showLineNumbers{1}
import tensorflow as tf

tensorboard_cb = tf.keras.callbacks.TensorBoard(log_dir="./logs")

# model.fit(X_train, y_train, epochs=10,
#           validation_data=(X_val, y_val),
#           callbacks=[tensorboard_cb])

# then, from a terminal in the same directory:
# tensorboard --logdir ./logs
```

In a notebook (Colab or Jupyter), you can embed the dashboard directly instead
of opening a separate browser tab:

```python title="Embedding TensorBoard in a notebook" showLineNumbers{1}
# %load_ext tensorboard
# %tensorboard --logdir ./logs
```

:::tip[From the book]
Chollet frames TensorBoard as the missing half of "the loop of progress": Keras
takes you from idea to experiment fast, and a GPU takes you from experiment to
result fast — but without rich feedback on *what actually happened* during
training, you can't turn that result back into your next idea. Watching more
than just the final loss (per-layer activations, gradient histograms, live
curves) is what lets each experiment sharpen the next one, instead of just
producing a single accuracy number to squint at.
:::
