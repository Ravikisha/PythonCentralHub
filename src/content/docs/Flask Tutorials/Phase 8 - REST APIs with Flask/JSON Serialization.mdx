JSON serialization is the process of converting Python data into JSON.

```mermaid title="what a view is allowed to return" desc="Flask accepts several shapes and converts each into a Response. ```

## What works out of the box

JSON supports:

- strings
- numbers
- booleans
- null
- arrays
- objects

In Python terms:

- str, int, float, bool, None
- list/tuple
- dict

## What does NOT serialize automatically

Common non-serializable types:

- `datetime`
- database model objects
- Decimal

You must convert them.

## Serialization strategies

### 1) Manual dict conversion

```python
user_dict = {"id": user.id, "username": user.username}
return user_dict
```

### 2) Helper method on model

```python
class User(db.Model):
    # ...
    def to_dict(self):
        return {"id": self.id, "username": self.username}
```

### 3) Schema libraries (later)

For larger APIs, people use:

- Marshmallow
- Pydantic

This tutorial track keeps it simple: manual `to_dict()` is fine.

## Error response shape (recommended)

Try to keep error responses consistent:

```json
{ "error": "validation_error", "message": "Email is required" }
```

Consistency makes frontend/mobile clients much easier to build.

## Why serialization is a decision

A JSON response is text. Before it can be sent, every Python value in it has to become one of the six JSON types. Strings, numbers, booleans, `None`, lists, and dictionaries convert on their own. Everything else does not, and Flask raises `TypeError: Object of type datetime is not JSON serializable`. The error tells you a value has no JSON form, and it is a good moment to decide what the client should see.

That decision is also a security choice. If you could dump a whole `User` object, the response would include `password_hash`. Building the dictionary by hand means only the fields you list are sent.

## A worked example

```python title="serialize.py" showLineNumbers{1}
from datetime import datetime, timezone
from decimal import Decimal


class Order:
    def __init__(self, id, total, created_at, secret_note):
        self.id = id
        self.total = total
        self.created_at = created_at
        self.secret_note = secret_note   # must NOT be exposed

    def to_dict(self):
        return {
            "id": self.id,
            "total": str(self.total),                # Decimal -> string keeps exact cents
            "created_at": self.created_at.isoformat(),  # datetime -> ISO 8601 text
        }


@app.get("/api/orders/<int:order_id>")
def get_order(order_id):
    order = Order(order_id, Decimal("19.99"), datetime.now(timezone.utc), "internal")
    return order.to_dict()
```

The response looks like `{"created_at": "2026-09-29T10:15:00+00:00", "id": 7, "total": "19.99"}`. Dates become ISO 8601 strings, which JavaScript and most languages can parse. `Decimal` becomes a string because converting it to a float could change the value, which matters for money. The secret field is never mentioned, so it is never sent.

For a list, build it with a comprehension: `return {"items": [o.to_dict() for o in orders]}`. Wrapping a list in an object gives you room to add fields like `total_count` later without breaking clients.

## Naming and shape

Pick one naming style for keys and keep it, for example `created_at` everywhere. Do not send a bare list at the top level when you may need extra fields later. Keep errors in one consistent shape, as shown above, so clients write one error handler.

## Common mistakes

- **Returning a model object directly.** It is not serializable and may contain sensitive fields.
- **Using `str(datetime)`.** It gives a space-separated format. `isoformat()` is the standard one.
- **Converting money to float.** Rounding errors appear. Send strings or integer cents.
- **Changing key names between endpoints.** Clients then need special cases.

## How it connects

The previous lesson, Building a Simple API, returned plain dictionaries. Here you handle the harder types from a real database. Later, when the API grows, libraries such as Marshmallow or Pydantic automate the same `to_dict` idea.
