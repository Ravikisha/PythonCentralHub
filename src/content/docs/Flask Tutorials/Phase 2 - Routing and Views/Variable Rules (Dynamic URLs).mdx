Dynamic routes let you capture parts of the URL.

```mermaid title="a converter validates before your view runs" desc="The type in a rule is not documentation -- it is a filter. A request whose segment does not fit the converter never reaches the function, so the view can assume the value is already the right type. That is why a bad id returns 404 rather than raising inside your code."
flowchart TD
  A["GET /post/abc"] --> B["match against /post/&lt;int:pid&gt;"]
  B --> C{"does 'abc' parse as an int?"}
  C -->|no| D["404 -- the view is never called"]
  C -->|yes| E["pid = 42, a real int"]
  E --> F["your view runs"]
  G["converters"] --> H["string  -- default, no slashes"]
  G --> I["int / float -- numeric, and converted"]
  G --> J["path -- like string but DOES match slashes"]
  G --> K["uuid -- a canonical UUID"]
```

## Basic dynamic route

```python
from flask import Flask

app = Flask(__name__)


@app.route("/user/<username>")
def user_profile(username: str):
    return f"Hello, {username}!"
```

- `/user/ravi` → `username = "ravi"`

## Type converters

Flask supports converters that validate and convert values:

- `<int:id>`
- `<float:price>`
- `<path:subpath>` (can include slashes)

Example:

```python
@app.route("/post/<int:post_id>")
def post_detail(post_id: int):
    return f"Post id: {post_id}"
```

Now:

- `/post/10` works
- `/post/abc` returns 404 (no match)

## Multiple variables

```python
@app.route("/category/<string:name>/page/<int:page>")
def category(name, page):
    return {"category": name, "page": page}
```

## Common pitfalls

- Using `<path:...>` when you don’t want slashes (it can match too much)
- Forgetting to validate values when types are not enough (e.g., allowed usernames)
- Returning user input directly without escaping in HTML templates (XSS risk)

## Why dynamic URLs matter

A site with a page for every user, product, or article cannot define one route per item. You would need thousands of functions. A variable rule lets one function serve them all: the part of the URL in angle brackets becomes an argument of your view, and Flask fills it in for each request.

Think of the rule as a pattern with a hole in it. `/user/<username>` matches `/user/ravi`, `/user/asha`, and anything else with one segment after `/user/`. The matched text is passed to `user_profile(username)` as a keyword argument, so the name inside the brackets must match the parameter name exactly.

## A worked example

```python title="blog_routes.py" showLineNumbers{1}
from flask import Flask

app = Flask(__name__)

POSTS = {1: "Hello world", 2: "Learning Flask", 3: "Routing tips"}


@app.route("/post/<int:post_id>")
def show_post(post_id):
    title = POSTS.get(post_id)
    if title is None:
        return "No such post", 404
    return f"Post {post_id}: {title}"


@app.route("/files/<path:subpath>")
def files(subpath):
    return f"You asked for: {subpath}"
```

A request to `/post/2` calls `show_post(2)` with a real integer, so you can use it as a dictionary key without converting it. A request to `/post/abc` never reaches your function at all. The converter fails and Flask answers 404 on its own. A request to `/files/img/logo.png` gives `subpath = "img/logo.png"` because `path` is the one converter that accepts slashes.

## Choosing a converter

Use `int` for database ids, `float` for numeric values, `uuid` for random identifiers, and the default string for names and slugs. Pick the strictest converter that fits. It removes a whole class of bad input before your code runs.

## Common mistakes

- **Mismatched names.** `<int:post_id>` with `def show_post(id)` raises a `TypeError`.
- **Assuming a matching type means valid data.** `/post/99999` is a valid int, but no such post exists. You still need to check and return 404 yourself.
- **Using `path` too freely.** It swallows slashes, so it can capture more of the URL than you intended.
- **Trusting the value.** A string from the URL is user input. Escape it in HTML, and never build file paths or SQL from it directly.

## How it connects

The previous lesson, Basic Routing, matched fixed URLs. Here the URL carries data. A later lesson, URL Building with `url_for`, does the reverse: you give Flask the values and it builds the URL for you, so links never go stale when a rule changes.
