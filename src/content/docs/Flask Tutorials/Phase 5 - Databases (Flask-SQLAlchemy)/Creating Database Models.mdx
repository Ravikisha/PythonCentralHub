A model is a Python class that represents a database table.

## Example: User model

```python
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()


class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)

    def __repr__(self):
        return f"<User {self.username}>"
```

## Key concepts

- `User` maps to a table (by default: `user`)
- each attribute maps to a column
- each instance maps to a row

## Naming tables explicitly

```python
class User(db.Model):
    __tablename__ = "users"
    # columns...
```

This avoids surprises, especially in bigger projects.

## Nullable vs required

- `nullable=False` means the DB will reject NULLs

In practice:

- validate in forms (nice UX)
- enforce at database level too (data integrity)

## From class to table

An ORM lets you describe a table as a Python class instead of writing `CREATE TABLE` by hand. Each class that inherits from `db.Model` becomes a table. Each `db.Column` becomes a column, with a type and options such as `primary_key`, `unique`, and `nullable`. Each instance you create later is one row.

Defining a model does not touch the database. It only tells SQLAlchemy what the table should look like. The table is created in a later step (`db.create_all()` or a migration), and rows are only written when you add an instance to the session and commit.

## A worked example

```python title="models.py" showLineNumbers{1}
from datetime import datetime, timezone
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///demo.db"
db = SQLAlchemy(app)


class User(db.Model):
    __tablename__ = "users"

    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)
    created_at = db.Column(db.DateTime, default=lambda: datetime.now(timezone.utc))

    def __repr__(self):
        return f"<User {self.username}>"


with app.app_context():
    db.create_all()
    u = User(username="ravi", email="ravi@example.com")
    db.session.add(u)
    db.session.commit()
    print(u.id, u)
```

After the commit, `u.id` holds the value the database generated, and `__repr__` gives readable output in the shell instead of an object address.

## Choosing column options

- `primary_key=True` gives each row a unique identity. Every model needs one.
- `unique=True` makes the database refuse duplicates. Use it for usernames and emails.
- `nullable=False` makes the column required at the database level.
- `default=` is applied by SQLAlchemy when you do not pass a value. Pass a function, not a call, so it runs per row.

## Common mistakes

- **Expecting the table to exist after defining the class.** You must create it.
- **Changing a model and expecting the table to change.** `create_all` does not alter existing tables. Migrations do that, later in this phase.
- **Using `default=datetime.now()`.** The call runs once at import time, so every row gets the same timestamp.
- **Relying only on form validation.** Add `unique` and `nullable` constraints so bad data cannot get in through another route.
