## Basic lookups

```python
user = User.query.get(1)
```

- Returns the user with primary key `1` or `None`

## Filter by column

```python
user = User.query.filter_by(username="ravi").first()
```

- `first()` returns one row or `None`

## Get all rows

```python
users = User.query.all()
```

## Ordering

```python
users = User.query.order_by(User.username.asc()).all()
```

## Common pattern: 404 if not found

In routes, you often want “not found” to return a 404.

Flask-SQLAlchemy provides:

```python
user = User.query.get_or_404(user_id)
```

That’s very convenient for web apps.

## Performance note

`all()` loads everything into memory.

For very large tables, use pagination (limit/offset) or streaming approaches.

## Choosing the right query

Every read starts from a question. "Give me the record with this id" is a primary key lookup. "Give me the record whose username is ravi" is a filter. "Show me everything" is a full scan. Picking the right method makes the code clearer and avoids surprises.

The important difference is what comes back. `first()` returns one object or `None`. `all()` returns a list, which is empty when nothing matches. `get_or_404()` returns one object or stops the request with a 404. Forgetting that `first()` can return `None` is the most common source of `AttributeError: 'NoneType' object has no attribute ...` in Flask apps.

## A worked example

```python title="read_routes.py" showLineNumbers{1}
@app.route("/users")
def list_users():
    users = User.query.order_by(User.username.asc()).all()
    return {"users": [u.username for u in users]}


@app.route("/users/<int:user_id>")
def show_user(user_id):
    user = db.get_or_404(User, user_id)
    return {"id": user.id, "username": user.username}


@app.route("/search")
def search():
    name = request.args.get("name", "")
    user = User.query.filter_by(username=name).first()
    if user is None:
        return {"error": "not found"}, 404
    return {"id": user.id}
```

The first route returns a list, sorted. The second uses the id from the URL and lets Flask answer 404 for a missing user. The third reads a search term from the query string and handles the empty result explicitly.

A note on versions: `User.query.get(1)` still works but is marked legacy in SQLAlchemy 2.0. The modern equivalents are `db.session.get(User, 1)` and `db.get_or_404(User, 1)`. You will see both styles in existing code.

## Filtering

`filter_by(username="ravi")` takes keyword arguments and only checks equality. For other comparisons use `filter` with column expressions, for example `User.query.filter(User.username.like("r%"))`. You can chain several filters and they are combined with AND.

## Common mistakes

- **Using the result without checking for `None`.** Use `get_or_404` in routes, or test explicitly.
- **Calling `all()` on a big table.** Everything loads into memory. Paginate instead.
- **Forgetting the terminating call.** `User.query.filter_by(...)` is only a query object. Nothing runs until you call `first()`, `all()`, or iterate over it.
- **Passing a comparison to `filter_by`.** Use `filter_by(name="x")`. Comparisons like `User.name == "x"` belong in `filter`.
