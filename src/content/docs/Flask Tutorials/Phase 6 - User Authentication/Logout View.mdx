Logging out means removing the user id from the session.

Flask-Login provides:

- `logout_user()`

```mermaid title="logging out is about clearing state, not showing a page" desc="logout_user removes the user id from the session. The remember-me cookie has to be cleared too, or the very next request logs them straight back in -- which is the bug people hit when they only pop the session key by hand."
flowchart LR
  A["POST /logout"] --> B["logout_user()"]
  B --> C["remove user_id from the session"]
  B --> D["clear the remember-me cookie"]
  C --> E["current_user is anonymous"]
  D --> E
  E --> F["redirect to a public page"]
  F --> G["the next request has no identity"]
```

## Example

```python
from flask import redirect, url_for
from flask_login import logout_user, login_required


@app.route("/logout")
@login_required
def logout():
    logout_user()
    return redirect(url_for("home"))
```

## Why protect logout with login_required?

It’s not strictly required, but:

- it keeps behavior consistent
- it avoids confusion when anonymous users hit `/logout`

## UX note

It’s common to flash a message:

- “You’ve been logged out.”

And redirect to home.

## What logout does

Logging out means the server forgets who the browser is. `logout_user()` removes the user id from the session, and clears the remember-me cookie if there is one. After that, `current_user` is an anonymous user again and any `@login_required` route sends the visitor to the login page.

Logout does not delete the user, close the database, or invalidate the cookie on other devices. It only changes the session in this browser.

## A worked example

A safer version uses POST, because a logout link that works with GET can be triggered by any page on the web. An attacker can embed an image whose source is your `/logout` URL, and every visitor who is logged in to your site is logged out. It is a minor attack, but the fix is cheap.

```python title="logout_view.py" showLineNumbers{1}
from flask import redirect, url_for, flash
from flask_login import logout_user, login_required


@app.route("/logout", methods=["POST"])
@login_required
def logout():
    logout_user()
    flash("You have been logged out.")
    return redirect(url_for("home"))
```

The link in your navigation bar becomes a small form:

```html
<form method="post" action="{{ url_for('logout') }}">
  <button type="submit">Log out</button>
</form>
```

If you use Flask-WTF's global CSRF protection, add `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` inside the form. The version in the earlier example, with the default GET method, also works and is fine for learning, but prefer POST in real apps.

## Common mistakes

- **Returning a page instead of redirecting.** After logout, redirect to a public page. Showing a private template would render with an anonymous user and probably break.
- **Redirecting to a `@login_required` page.** The visitor bounces straight to the login screen with an odd `next` value.
- **Clearing only part of the state.** If you store extra data in the session yourself, `logout_user()` does not know about it. Call `session.clear()` if you want to remove it all.
- **Assuming logout signs the user out everywhere.** Other browsers keep their own cookies.
