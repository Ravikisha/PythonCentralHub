By default, login state ends when the browser closes (session cookie).

“Remember me” uses a longer-lived cookie so users stay logged in.

```mermaid title="why remember me is a second, longer-lived credential" desc="The session cookie dies when the browser closes. Remember-me is a separate cookie with its own long lifetime, and Flask-Login uses it to rebuild the session when the session cookie is gone. That is convenient and it is also a bigger window for a stolen cookie, which is why sensitive actions should re-ask for the password."
flowchart TD
  A["login_user(user, remember=True)"] --> B["session cookie -- dies with the browser"]
  A --> C["remember cookie -- lives for REMEMBER_COOKIE_DURATION"]
  D["a later request"] --> E{"session cookie present?"}
  E -->|yes| F["logged in normally"]
  E -->|no| G{"remember cookie present and valid?"}
  G -->|yes| H["Flask-Login restores the session"]
  H --> I["current_user is set, but this is a 'remembered' login"]
  G -->|no| J["anonymous -- send to the login page"]
  I --> K["require a fresh login before changing a password or email"]
```

## Using remember=True

```python
from flask_login import login_user

login_user(user, remember=True)
```

Often the user chooses this via a checkbox.

## Security tradeoffs

Remember-me is convenient but can be risky:

- if someone gains access to the device, they stay logged in

Mitigations:

- allow users to revoke sessions
- set reasonable expiration times
- require re-auth for sensitive actions

## Configure duration

Flask-Login allows setting:

- `REMEMBER_COOKIE_DURATION`

You can set it in app config.

## Best practice

For banking/high-security apps:

- avoid long remember sessions
- require multi-factor authentication (MFA)

For normal apps:

- remember-me is common and acceptable.

## Two kinds of login

After `login_user(user)`, Flask-Login stores the user id in the session cookie. That cookie has no expiry date, so the browser throws it away when the browser closes. The next visit starts logged out. That is the default, and it is the safest choice on shared computers.

"Remember me" adds a second cookie, the remember cookie, with a real expiry date. When the session cookie is gone, Flask-Login sees the remember cookie and logs the user back in on the next request. The user stays signed in for days or weeks, even after restarting the browser.

## A worked example

The choice normally comes from a checkbox on the login form:

```html
<form method="post">
  <input name="username" />
  <input name="password" type="password" />
  <label><input type="checkbox" name="remember" /> Remember me</label>
  <button type="submit">Log in</button>
</form>
```

```python title="remember_login.py" showLineNumbers{1}
from datetime import timedelta
from flask import request, redirect, url_for
from flask_login import login_user

app.config["REMEMBER_COOKIE_DURATION"] = timedelta(days=14)
app.config["REMEMBER_COOKIE_HTTPONLY"] = True
app.config["REMEMBER_COOKIE_SECURE"] = True   # only sent over HTTPS


@app.route("/login", methods=["POST"])
def login():
    user = check_credentials(request.form)     # your own function
    if user:
        remember = request.form.get("remember") == "on"
        login_user(user, remember=remember)
        return redirect(url_for("dashboard"))
    return "Invalid credentials", 401
```

An unchecked checkbox sends nothing at all, so `request.form.get("remember")` is `None`. A checked one sends the value `"on"`. Comparing to `"on"` gives a clean boolean.

The default duration is 365 days, which is longer than most sites want. Set `REMEMBER_COOKIE_DURATION` explicitly. With `REMEMBER_COOKIE_SECURE`, the cookie is only sent over HTTPS. Use that setting in production, and leave it off during local development on plain `http://`, or the cookie will never be sent.

## The security trade-off

Anyone who can use the browser can use the account, and the remember cookie makes that window last for weeks. Reduce the risk by keeping the duration short, asking for the password again before sensitive actions such as changing an email address, and giving users a way to log out. Do not turn remember-me on by default.

## Common mistakes

- **Setting `remember=True` for everyone.** Let the user choose.
- **Leaving the default 365 days.** Choose a duration on purpose.
- **Testing over HTTP with `REMEMBER_COOKIE_SECURE=True`.** The cookie is not sent and remember-me seems broken.
- **Forgetting that logout must clear it.** `logout_user()` does, but custom session tricks may not.
