Flask-Login is the standard extension for login/session management.

It helps you:

- log users in and out
- remember users across requests
- access `current_user`
- protect routes with `@login_required`

## Install

```bash
pip install Flask-Login
```

## Minimal setup

```python
from flask import Flask
from flask_login import LoginManager

app = Flask(__name__)
app.config["SECRET_KEY"] = "dev-key"

login_manager = LoginManager()
login_manager.init_app(app)

# where to redirect when login is required
login_manager.login_view = "login"
```

## User model requirement

Your user model must implement:

- `is_authenticated`
- `is_active`
- `is_anonymous`
- `get_id()`

The easiest way is to inherit:

```python
from flask_login import UserMixin

class User(UserMixin, db.Model):
    ...
```

## current_user

Flask-Login provides:

```python
from flask_login import current_user
```

`current_user` represents the user for the current request.

If not logged in, it’s an AnonymousUser object.

## What problem Flask-Login solves

HTTP has no memory. Each request arrives on its own, so the server has no built-in way to know that the request for `/dashboard` comes from the same person who logged in a minute ago. The previous lesson, Cookies vs Sessions, showed the answer: after login, store something in the signed session cookie, and read it on every later request.

Flask-Login is a small extension that does this bookkeeping for you. It stores the user's id in the session, loads the matching user on each request, exposes that user as `current_user`, and offers `@login_required` to guard routes. It does not create users, hash passwords, or build login forms. Those remain your job.

## The pieces you must provide

Flask-Login needs three things from your app:

1. A `SECRET_KEY`, because the session cookie is signed with it. Without it, sessions do not work.
2. A user model with the four properties Flask-Login expects. Inheriting from `UserMixin` supplies them.
3. A user loader function that turns a stored id back into a user (next lesson).

## A worked example

```python title="auth_setup.py" showLineNumbers{1}
from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_login import LoginManager, UserMixin, current_user

app = Flask(__name__)
app.config["SECRET_KEY"] = "dev-key"
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///auth.db"

db = SQLAlchemy(app)
login_manager = LoginManager(app)
login_manager.login_view = "login"


class User(UserMixin, db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)


@app.route("/whoami")
def whoami():
    if current_user.is_authenticated:
        return f"Signed in as {current_user.username}"
    return "You are not signed in"
```

`current_user` is safe to use on any route. When nobody is logged in it is an anonymous user object, whose `is_authenticated` is `False`, so you can test it without a try/except. Only after a successful `login_user()` does it point at a real `User`.

## Common mistakes

- **Forgetting `SECRET_KEY`.** Logging in appears to work, then the user is logged out on the next request or an error is raised.
- **Not inheriting from `UserMixin`.** Flask-Login raises errors about missing `is_active` or `get_id`.
- **Expecting Flask-Login to check passwords.** It only tracks who is logged in. You verify the password yourself, then call `login_user`.
- **Hardcoding the secret key in production.** Read it from an environment variable.
