Flask-Login stores a user id in the session.

On the next request, it needs to turn that id into a User object.

That’s what the **user loader** does.

```mermaid title="the user_loader runs once per request, not once per login" desc="The session only stores an id. On every single request Flask-Login takes that id and calls your user_loader to turn it back into a user object -- which is why the function must be cheap, and why returning None for a deleted user is what logs them out."
sequenceDiagram
  participant B as Browser
  participant F as Flask-Login
  participant L as your user_loader
  participant D as Database
  B->>F: request with session cookie
  F->>F: read user_id from the session
  F->>L: user_loader("7")
  L->>D: User.query.get(7)
  alt row exists
    D-->>L: User
    L-->>F: User object
    F-->>B: current_user is that user
  else row is gone
    D-->>L: None
    L-->>F: None
    F-->>B: current_user is anonymous -- effectively logged out
  end
```

## Example

```python
from flask_login import LoginManager

login_manager = LoginManager()


@login_manager.user_loader
def load_user(user_id: str):
    return User.query.get(int(user_id))
```

## Important notes

- `user_id` comes from the session, so it’s a string.
- Convert types carefully.
- Return `None` if the user doesn’t exist.

## Common pitfalls

- Forgetting to register the loader → Flask-Login can’t restore sessions
- Querying with the wrong type
- Returning something that isn’t a User model/UserMixin

## Where to put this code

In larger apps, user loader registration usually lives in:

- `auth` blueprint
- app factory initialization

So it’s registered exactly once.
