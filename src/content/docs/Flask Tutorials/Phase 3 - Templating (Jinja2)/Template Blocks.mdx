## Defining blocks

```html
<!-- base.html -->
{% block content %}{% endblock %}
```

## Overriding blocks

```html
<!-- page.html -->
{% extends "base.html" %}

{% block content %}
  <h1>Page content</h1>
{% endblock %}
```

## Using multiple blocks

Base templates often have blocks like:

- `title`
- `content`
- `scripts`

```html
{% block scripts %}{% endblock %}
```

Child template:

```html
{% block scripts %}
  <script src="{{ url_for('static', filename='app.js') }}"></script>
{% endblock %}
```

## Extending a block (super)

If you want to add to a parent block rather than replace it:

```html
{% block scripts %}
  {{ super() }}
  <script src="{{ url_for('static', filename='extra.js') }}"></script>
{% endblock %}
```

That’s useful for base scripts shared across pages.

## Blocks are the contract between layout and page

Template inheritance has two halves. The base template holds what every page shares: the doctype, the navigation, the footer. The child template fills in what differs. A block is the agreement between them. The base marks a named hole, `{% block content %}{% endblock %}`, and the child supplies content for exactly that name.

Anything in the child that is outside a block is ignored. This surprises beginners who write a paragraph after `{% extends %}` and wonder why it never appears. Everything the child wants displayed must sit inside a block that the base defines.

## A worked example

Here is a base with four blocks. The `title` block has a default, so a child that says nothing still gets a sensible title:

```html title="templates/base.html" showLineNumbers{1}
<!doctype html>
<html>
  <head>
    <title>{% block title %}Python Central Hub{% endblock %}</title>
    {% block head %}
      <link rel="stylesheet" href="{{ url_for('static', filename='site.css') }}">
    {% endblock %}
  </head>
  <body>
    <main>{% block content %}{% endblock %}</main>
    {% block scripts %}
      <script src="{{ url_for('static', filename='site.js') }}"></script>
    {% endblock %}
  </body>
</html>
```

```html title="templates/article.html" showLineNumbers{1}
{% extends "base.html" %}

{% block title %}{{ article.headline }} | Python Central Hub{% endblock %}

{% block content %}
  <h1>{{ article.headline }}</h1>
  <p>{{ article.body }}</p>
{% endblock %}

{% block scripts %}
  {{ super() }}
  <script src="{{ url_for('static', filename='article.js') }}"></script>
{% endblock %}
```

The article page replaces `title` and `content`. It does not mention `head`, so the base version is kept. For `scripts` it calls `super()`, which outputs the parent's block first, and then adds its own script. Without `super()` the site-wide script would disappear from this page.

## How to decide what to make a block

A block is a decision about what pages may change. Common ones are `title`, `head` for extra styles, `content`, and `scripts`. Too few blocks and children have to duplicate layout. Too many and the base stops being a layout. Start with these four and add more only when a real page needs it.

Blocks can also be nested, and a block can be printed twice with `{{ self.title() }}`, useful for repeating the page title as a heading.

## Common mistakes

- **Content outside any block.** It is silently dropped.
- **A block name that the base does not define.** The child's block never renders.
- **`{% extends %}` not on the first line.** It must come first in the child.
- **Forgetting `super()`.** The parent's content is replaced instead of extended.
- **Naming two blocks the same in one template.** Jinja raises an error.
