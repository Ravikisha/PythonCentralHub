Filters let you transform values at render time.

Syntax:

```html
{{ value | filter_name }}
```

```mermaid title="escaping, and the two ways to switch it off" desc="With autoescaping on, a value containing markup is neutralised on the way into the page. ## Common built-in filters

```html
<p>{{ username | lower }}</p>
<p>{{ username | upper }}</p>
<p>{{ items | join(", ") }}</p>
```

## Default values

```html
<p>{{ bio | default("No bio yet") }}</p>
```

## length

```html
<p>Count: {{ items | length }}</p>
```

## Important security note: safe

`|safe` tells Jinja “don’t escape this value”.

Only use it if you’re absolutely sure the HTML is trusted.

Never mark raw user input as safe.

## What a filter is

Data in your view is often not in the shape you want to show. A name may be lowercase, a list needs commas between items, a number needs two decimal places, or a value may be missing. You could fix each of these in Python before rendering, but display formatting is a template concern. A filter transforms a value at the moment it is printed, using a pipe: `{{ value | filter }}`.

Filters can take arguments in parentheses, and they can be chained. The chain runs left to right, each filter receiving the result of the one before it.

## A worked example

```python title="filters_demo.py" showLineNumbers{1}
from flask import Flask, render_template_string

app = Flask(__name__)


@app.route("/")
def home():
    return render_template_string(
        """
        <p>{{ username | title }}</p>
        <p>{{ tags | join(", ") }}</p>
        <p>{{ bio | default("No bio yet", true) }}</p>
        <p>{{ price | round(2) }}</p>
        <p>{{ description | truncate(30) }}</p>
        <p>{{ items | length }} items</p>
        <p>{{ note | e }}</p>
        """,
        username="ravi kishan",
        tags=["flask", "jinja", "python"],
        bio="",
        price=19.98765,
        description="Jinja filters format values without changing your Python code.",
        items=[1, 2, 3],
        note="<b>bold</b>",
    )
```

The output is: `Ravi Kishan`, then `flask, jinja, python`, then `No bio yet`, then `19.99`, then a description cut at 30 characters ending in `...`, then `3 items`, and finally `&lt;b&gt;bold&lt;/b&gt;`, which the browser shows as literal text.

Two details are easy to miss. `default("No bio yet")` only replaces an undefined value. An empty string `""` is defined, so it stays empty unless you pass `true` as the second argument, as done above. And `| e` escapes HTML, although `{{ }}` already does that automatically in Flask templates, so you rarely need it by hand.

## Other useful filters

`lower`, `upper`, `capitalize`, `trim`, `first`, `last`, `sort`, `reverse`, `sum`, `int`, `float`, `list`, `tojson` and `urlencode`. The Jinja documentation lists them all. For anything missing, the next lesson shows how to write a custom filter.

## The safe filter

Flask escapes every printed value, so `<script>` from a user appears as harmless text. `| safe` switches that protection off for one value. Use it only for HTML you produced yourself, never for text a visitor typed, or you open the door to cross-site scripting.

## Common mistakes

- **Using `| safe` on user input.** This is the classic XSS bug.
- **Calling a filter like a function.** `{{ upper(name) }}` fails. Write `{{ name | upper }}`.
- **Expecting `default` to catch empty strings.** Pass `true`.
- **Doing heavy logic in filters.** Compute it in the view instead.

## How it connects

Earlier you printed variables with `{{ }}`. Filters shape those values. Custom Filters, later in this phase, lets you add your own.
