## HTML form

```html
<form method="post" enctype="multipart/form-data">
  <input type="file" name="photo" />
  <button type="submit">Upload</button>
</form>
```

## Flask route

```python
from flask import Flask, request

app = Flask(__name__)


@app.route("/upload", methods=["GET", "POST"])
def upload():
    if request.method == "POST":
        file = request.files.get("photo")
        if not file:
            return "No file uploaded", 400

        # saving comes next (see secure filenames)
        return "File received", 200

    return "Upload form"
```

## Why request.form doesn’t contain files

Files are streamed separately and exposed via:

- `request.files`

## Common pitfalls

- Forgetting `enctype="multipart/form-data"` → files missing
- Not setting size limits
- Accepting any file type blindly

In a real app, validate:

- allowed file extensions
- MIME type
- file size

## How a file travels

An ordinary form sends its fields as short text pairs, which Flask puts in `request.form`. A file is different: it can be large and binary. Browsers send it using `multipart/form-data`, a format that splits the body into parts, one per field or file. If you leave out `enctype="multipart/form-data"` on the form, the browser sends only the file name as text, and `request.files` stays empty. There is no error, which is why this mistake takes so long to find.

Each uploaded file arrives as a `FileStorage` object with a `filename`, a `content_type`, and a `save()` method. Nothing is written to disk until you call `save()`.

## A worked example

This version enforces a size limit and an extension whitelist, and saves the file:

```python title="upload_demo.py" showLineNumbers{1}
import os
from flask import Flask, request
from werkzeug.utils import secure_filename

app = Flask(__name__)
app.config["MAX_CONTENT_LENGTH"] = 2 * 1024 * 1024      # 2 MB
UPLOAD_DIR = os.path.join(app.instance_path, "uploads")
os.makedirs(UPLOAD_DIR, exist_ok=True)
ALLOWED = {".png", ".jpg", ".jpeg", ".gif"}


@app.route("/upload", methods=["GET", "POST"])
def upload():
    if request.method == "POST":
        file = request.files.get("photo")
        if file is None or file.filename == "":
            return "No file selected", 400

        name = secure_filename(file.filename)
        ext = os.path.splitext(name)[1].lower()
        if ext not in ALLOWED:
            return "File type not allowed", 400

        file.save(os.path.join(UPLOAD_DIR, name))
        return "Saved", 201

    return (
        '<form method="post" enctype="multipart/form-data">'
        '<input type="file" name="photo"> <button>Upload</button></form>'
    )


@app.errorhandler(413)
def too_large(error):
    return "File too big (limit 2 MB)", 413
```

Follow one upload. The browser posts the body. Flask checks its size against `MAX_CONTENT_LENGTH` and answers 413 if it is too big, before your view runs. Otherwise `request.files.get("photo")` finds the part named `photo`. When the user pressed upload without choosing a file, the browser still sends an empty part with an empty file name, so the `filename == ""` test is needed. Then `secure_filename` cleans the name, the extension is checked, and the file is saved.

## Why the checks matter

A file name comes from the visitor. Without `secure_filename`, a name like `../../app.py` could write outside your upload folder. The next lesson explains that function in detail. An extension check is only a first filter, because anyone can rename a file. For images, open the file with a library such as Pillow to confirm it is really an image. Never serve uploaded files from a folder where the web server would run them as code. Store them outside your source tree or in object storage.

## Common mistakes

- **Missing `enctype`.** `request.files` is empty and nothing tells you why.
- **A missing `name` attribute on the input.** The file is not sent.
- **Not handling the empty selection.** You get a file object with no name.
- **No size limit.** One large upload can fill your disk or memory.
- **Saving under the original name.** Clean it, and consider generating your own unique name.
