Validation ensures:

- required fields are present
- values match expected patterns (email)
- lengths/ranges are safe

## Common validators

WTForms ships many validators:

- `DataRequired()` / `InputRequired()`
- `Email()`
- `Length(min=, max=)`
- `NumberRange(min=, max=)`
- `Regexp()`

Example:

```python
from wtforms.validators import DataRequired, Length

username = StringField("Username", validators=[DataRequired(), Length(min=3, max=20)])
```

## Validation errors

When validation fails, errors are stored per field:

- `form.username.errors`

You can show them in templates:

```html
{% for error in form.username.errors %}
  <p class="error">{{ error }}</p>
{% endfor %}
```

## Custom validation

You can add custom validation methods:

```python
class RegisterForm(FlaskForm):
    username = StringField("Username", validators=[DataRequired()])

    def validate_username(self, field):
        if " " in field.data:
            raise ValidationError("Username cannot contain spaces")
```

Custom validators are great for business rules.

## Why validation matters

A form can be submitted with anything in it. A required field can be empty, an email can be `hello`, and a number can be negative or enormous. The browser's own checks, such as the `required` attribute, are only a courtesy. Anyone can bypass them with a script or a tool like curl. Validation on the server is the only check you can rely on.

WTForms, which powers Flask-WTF, lets you declare the rules next to each field. Calling `form.validate_on_submit()` in your view does two things: it confirms the request is a POST, and it runs every validator. If any fail, it returns `False` and fills `form.<field>.errors` with messages.

## A worked example

```python title="register_form.py" showLineNumbers{1}
from flask import Flask, render_template, redirect, url_for, flash
from flask_wtf import FlaskForm
from wtforms import StringField, PasswordField
from wtforms.validators import DataRequired, Email, Length, EqualTo, ValidationError

app = Flask(__name__)
app.config["SECRET_KEY"] = "change-me"


class RegisterForm(FlaskForm):
    username = StringField("Username", validators=[DataRequired(), Length(min=3, max=20)])
    email = StringField("Email", validators=[DataRequired(), Email()])
    password = PasswordField("Password", validators=[DataRequired(), Length(min=8)])
    confirm = PasswordField("Confirm", validators=[EqualTo("password")])

    def validate_username(self, field):
        if " " in field.data:
            raise ValidationError("Username cannot contain spaces")


@app.route("/register", methods=["GET", "POST"])
def register():
    form = RegisterForm()
    if form.validate_on_submit():
        flash("Account created")
        return redirect(url_for("register"))
    return render_template("register.html", form=form)
```

If the form is invalid, the view falls through to `render_template`, and the template shows each field's `errors`. The user's earlier input is kept, so they only fix what is wrong.

## Common mistakes

- **Using `form.validate()` on GET.** A fresh form always fails because nothing was submitted. Use `validate_on_submit()`.
- **Forgetting to show errors.** The form re-renders silently and users cannot tell why it failed.
- **Missing the email package.** The `Email()` validator needs the `email-validator` package installed.
- **Treating validation as the only defence.** Validation checks shape. You still need to hash passwords and escape output.
