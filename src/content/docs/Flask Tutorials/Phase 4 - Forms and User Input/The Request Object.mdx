Every HTTP request has:

- method (GET/POST/...)
- URL path
- query string
- headers
- optional body (form data / JSON)

In Flask, you access request data through `flask.request`.

## Importing request

```python
from flask import request
```

`request` is a **context-local** proxy that points to the current request.

## Common request attributes

- `request.method` — HTTP method
- `request.args` — query parameters (MultiDict)
- `request.form` — form fields from POST body (MultiDict)
- `request.files` — uploaded files
- `request.json` / `request.get_json()` — JSON payload
- `request.headers` — request headers
- `request.cookies` — cookies

## Quick demo route

```python
from flask import Flask, request

app = Flask(__name__)


@app.route("/inspect", methods=["GET", "POST"])
def inspect():
    return {
        "method": request.method,
        "args": request.args,
        "form": request.form,
        "content_type": request.content_type,
    }
```

Note: `request.args` and `request.form` are MultiDict objects; Flask can serialize them in JSON responses, but you may want to cast them to dict for clarity.

## Important security idea

Treat **everything** from `request` as untrusted:

- validate type
- validate allowed values
- sanitize output

Later, Flask-WTF + validators automate a lot of this.

## One object, many sources

An HTTP request carries data in several places at once: the URL path, the query string after the `?`, the headers, and an optional body. Flask gathers all of it into one object, `request`. You do not create it or pass it around. You import it and read from it inside a view.

The important skill is picking the right attribute, because each one holds a different part. Asking `request.form` for something the client sent as JSON, or `request.args` for something in a POST body, gives an empty result and no error.

## A worked example

This endpoint accepts data from every source, so you can see where each goes:

```python title="request_demo.py" showLineNumbers{1}
from flask import Flask, request

app = Flask(__name__)


@app.route("/inspect", methods=["GET", "POST"])
def inspect():
    return {
        "method": request.method,
        "path": request.path,
        "query": request.args.to_dict(),
        "form": request.form.to_dict(),
        "json": request.get_json(silent=True),
        "user_agent": request.headers.get("User-Agent"),
        "session_cookie": request.cookies.get("session"),
    }
```

Try it with three commands:

```bash
curl "http://127.0.0.1:5000/inspect?page=2"
curl -X POST -d "name=Ravi" http://127.0.0.1:5000/inspect
curl -X POST -H "Content-Type: application/json" -d '{"name": "Ravi"}' http://127.0.0.1:5000/inspect
```

The first shows `page` under `query`. The second shows `name` under `form`. The third shows the body under `json`, and `form` stays empty. That last result is the one that catches people out: a JSON body is not form data.

## Reading values safely

`request.args` and `request.form` behave like dictionaries. Use `.get("key", default)`, which returns a default when the key is missing. Square brackets raise a 400 error. Everything arrives as a string, so convert with care: `request.args.get("page", 1, type=int)` converts and falls back to the default when the value is not a number.

## The request is context-local

`request` looks like a global variable, but it is a proxy for the request being handled by the current thread. Two visitors at the same time each see their own data. This is why it only works inside a view or other code running during a request. Outside one, you get `RuntimeError: Working outside of request context`.

## Common mistakes

- **Using `request.form` for a JSON API.** Use `get_json()`.
- **Reading `request.args["page"]` without a default.** A missing key raises 400.
- **Forgetting values are strings.** `"2" + 1` fails.
- **Trusting any of it.** Headers, cookies and the body are all controlled by the client, so validate them.
