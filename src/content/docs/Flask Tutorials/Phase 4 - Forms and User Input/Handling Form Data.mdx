HTML forms usually submit data using **POST** with a content type like:

- `application/x-www-form-urlencoded`
- `multipart/form-data` (required for file uploads)

```mermaid title="POST then redirect then GET, and why the redirect is not optional" desc="If a POST responds with HTML directly, the browser remembers the POST. Reloading that page re-submits the form, and the back button offers to do it again -- so the order is placed twice. Answering with a redirect means the address the browser ends up on is a plain GET, which is safe to reload and safe to bookmark."
flowchart TD
  A["GET /contact"] --> B["render the empty form"]
  B --> C["POST /contact with the data"]
  C --> D{"valid?"}
  D -->|no| E["re-render the form with errors"]
  E --> C
  D -->|yes| F["do the work: save, send, charge"]
  F --> G["flash a message"]
  G --> H["redirect (302) to a GET route"]
  H --> I["GET /thanks"]
  I --> J["reload is now harmless -- it repeats the GET, not the POST"]
```

## Minimal example (no Flask-WTF yet)

Template `templates/contact.html`:

```html
<form method="post">
  <input type="text" name="name" placeholder="Your name" />
  <input type="email" name="email" placeholder="Email" />
  <button type="submit">Send</button>
</form>
```

Route:

```python
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/contact", methods=["GET", "POST"])
def contact():
    if request.method == "POST":
        name = request.form.get("name", "")
        email = request.form.get("email", "")

        # TODO: validate input here
        return f"Thanks {name}, we received {email}!"

    return render_template("contact.html")
```

## Common pitfalls

- Missing `methods=["GET", "POST"]` → POST returns 405
- Forgetting to validate user input
- Returning a success page directly after POST (refresh resubmits)

## Best practice: PRG pattern

After a successful POST:

- save/process data
- `redirect()` to a GET route

This prevents double submission on refresh.

## How form data reaches your view

When a user presses Submit on a form with `method="post"`, the browser packs every input into the request body as name and value pairs. Flask parses that body and exposes it as `request.form`, a dictionary-like object. The key for each value is the `name` attribute of the input. An input with no `name` is never sent, which is a very common reason a value seems to go missing.

Read values with `request.form.get("field", "")`. Square brackets, as in `request.form["field"]`, raise a 400 Bad Request error if the field is absent. That may be what you want in some cases, but `get` lets you decide what to do.

## A worked example with validation and redirect

```python title="contact_app.py" showLineNumbers{1}
from flask import Flask, request, render_template, redirect, url_for, flash

app = Flask(__name__)
app.secret_key = "dev-only"


@app.route("/contact", methods=["GET", "POST"])
def contact():
    if request.method == "POST":
        name = request.form.get("name", "").strip()
        email = request.form.get("email", "").strip()

        if not name or "@" not in email:
            flash("Please enter a name and a valid email.")
            return render_template("contact.html"), 400

        # save or send the message here
        flash(f"Thanks {name}, we received your message.")
        return redirect(url_for("thanks"))

    return render_template("contact.html")


@app.route("/thanks")
def thanks():
    return "Message sent"
```

Notice the two exits. Bad input re-renders the form with a 400 status so the user can try again. Good input ends in a redirect to a separate GET route. That is the Post/Redirect/Get pattern from the diagram above. If the success branch returned a page directly, pressing reload would make the browser offer to send the form again, and you would process the same message twice.

## Common mistakes

- **Missing `methods=["GET", "POST"]`.** The form submits and you get 405 Method Not Allowed.
- **No `name` on inputs.** The field is silently left out of `request.form`.
- **Using `request.form` for uploads or JSON.** Files live in `request.files`, and a JSON body is read with `request.get_json()`.
- **Trusting the data.** Strip whitespace, check lengths, and escape anything you print back.
