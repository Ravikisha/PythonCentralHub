**CSRF** (Cross-Site Request Forgery) is a common web attack.

It happens when:

- a user is logged in to your site
- a malicious site tricks their browser into sending a POST request to your site
- the browser includes your user’s cookies automatically

If you don’t validate a CSRF token, the request may look “legitimate”.

## How Flask-WTF protects you

Flask-WTF adds a hidden token field to your form.

On submit, it verifies:

- the token matches the user session
- the request is coming from your site

## Enabling CSRF

If you use `FlaskForm` and set `SECRET_KEY`, CSRF is enabled by default.

## Include the hidden token in templates

In your HTML form, add:

```html
<form method="post">
  {{ form.hidden_tag() }}
  <!-- fields... -->
</form>
```

`hidden_tag()` includes the CSRF token.

## If you forget hidden_tag()

You’ll typically see:

- “The CSRF token is missing.”

This is a common beginner error.

## Why cookies alone are not proof

When you log in, the browser stores a session cookie. From then on it attaches that cookie to every request to your domain, automatically. That includes requests started by a different website. The server sees a valid cookie and cannot tell whether the user clicked a button on your page or a hidden form on someone else's.

CSRF protection breaks that tie. The server puts a secret, unpredictable token in each form it serves. A real submission sends the token back. A forged request from another site cannot include it, because the browser's same-origin rules stop that site from reading your pages, so it has no way to learn the token.

## A worked example

Set a secret key, and use a `FlaskForm`. Protection is then on:

```python title="csrf_demo.py" showLineNumbers{1}
from flask import Flask, render_template, redirect, url_for
from flask_wtf import FlaskForm
from wtforms import StringField, SubmitField
from wtforms.validators import DataRequired

app = Flask(__name__)
app.config["SECRET_KEY"] = "change-me"


class NoteForm(FlaskForm):
    text = StringField("Note", validators=[DataRequired()])
    submit = SubmitField("Save")


@app.route("/note", methods=["GET", "POST"])
def note():
    form = NoteForm()
    if form.validate_on_submit():
        return redirect(url_for("note"))
    return render_template("note.html", form=form)
```

```html title="templates/note.html" showLineNumbers{1}
<form method="post">
  {{ form.hidden_tag() }}
  {{ form.text.label }} {{ form.text() }}
  {{ form.submit() }}
</form>
```

`hidden_tag()` renders the token as a hidden input. When the form is posted, `validate_on_submit()` compares that token with the one tied to the user's session. If it is missing or wrong, validation fails and `form.errors` contains a `csrf_token` entry.

## Protecting forms that are not FlaskForms

For plain HTML forms and JavaScript requests, enable protection app-wide with `CSRFProtect`:

```python
from flask_wtf.csrf import CSRFProtect

csrf = CSRFProtect(app)
```

Then include `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` in each form. For `fetch` calls, send the token in an `X-CSRFToken` header.

## Which requests need it

Any request that changes state, so POST, PUT, PATCH, and DELETE. GET requests must never change data, which is one more reason logout and delete actions should be POST forms and not links.

## Common mistakes

- **No `hidden_tag()` in the template.** Every submission fails with "The CSRF token is missing."
- **No `SECRET_KEY`.** The token cannot be generated.
- **Disabling CSRF to make an error go away.** That removes the protection. Find out why the token is absent.
- **Expiring tokens.** A form left open for over an hour fails by default. Reload the page or extend `WTF_CSRF_TIME_LIMIT`.
- **Exempting routes casually.** Use `@csrf.exempt` only for APIs that use another proof of identity, such as token headers.
