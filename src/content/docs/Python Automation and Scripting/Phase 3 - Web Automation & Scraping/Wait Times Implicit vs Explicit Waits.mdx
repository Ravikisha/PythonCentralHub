## Why waits matter

Dynamic pages load elements later.

If you try to locate elements too early, you get:

- `NoSuchElementException`
- `ElementNotInteractableException`

## Implicit wait

```python title="implicit_wait.py" showLineNumbers{1}
from selenium import webdriver


driver = webdriver.Chrome()
driver.implicitly_wait(5)  # seconds
```

It applies to element lookups globally.

## Explicit wait (recommended)

```python title="explicit_wait.py" showLineNumbers{1}
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


driver = webdriver.Chrome()
try:
    driver.get("https://example.com")

    h1 = WebDriverWait(driver, 10).until(
        EC.visibility_of_element_located((By.TAG_NAME, "h1"))
    )
    print(h1.text)
finally:
    driver.quit()
```

## Tip

Prefer explicit waits for specific elements.

## The problem waits solve

When `driver.get()` returns, the page has loaded, but the JavaScript may still be adding elements. If you look for one too early, Selenium raises `NoSuchElementException`. If the element exists but is hidden or covered, you get `ElementNotInteractableException`. The naive fix is `time.sleep(5)`. It is always slower than needed, and still fails on a slow day.

## The three kinds of waiting

- **`time.sleep(n)`** waits exactly n seconds. Use it only for polite delays between requests, never to wait for the page.
- **Implicit wait** (`driver.implicitly_wait(5)`) is set once. Every `find_element` then retries for up to 5 seconds before failing. It only knows about presence in the DOM.
- **Explicit wait** (`WebDriverWait(driver, 10).until(condition)`) waits for one named condition on one element. It polls every half second and returns as soon as the condition is true, or raises `TimeoutException` after the limit.

Use explicit waits. They say what you are waiting for, and they can wait for more than presence.

## Useful conditions

| Condition | Use it when |
| --- | --- |
| `presence_of_element_located` | the element must exist in the DOM |
| `visibility_of_element_located` | you need to read visible text |
| `element_to_be_clickable` | you are about to click |
| `invisibility_of_element_located` | waiting for a spinner to go away |
| `text_to_be_present_in_element` | waiting for a value to change |
| `staleness_of` | waiting for the old page to be replaced |

Each takes a locator tuple such as `(By.ID, "result")`. Note the double brackets: one pair for the call, one for the tuple.

## A reusable helper

```python title="wait_helpers.py" showLineNumbers{1}
from selenium.common.exceptions import TimeoutException
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait


def click_when_ready(driver, css: str, timeout: int = 10) -> None:
    try:
        element = WebDriverWait(driver, timeout).until(
            EC.element_to_be_clickable((By.CSS_SELECTOR, css))
        )
    except TimeoutException:
        driver.save_screenshot("timeout.png")
        raise RuntimeError(f"{css} was not clickable after {timeout}s")
    element.click()


def wait_for_text(driver, css: str, expected: str, timeout: int = 10):
    return WebDriverWait(driver, timeout).until(
        EC.text_to_be_present_in_element((By.CSS_SELECTOR, css), expected)
    )
```

A clear error message and a screenshot on timeout turn "the script failed sometimes" into something you can debug.

## Why not mix implicit and explicit

The Selenium documentation warns against setting both. The timeouts can add up in ways that are hard to predict: an explicit wait that polls for a missing element may spend the implicit wait on each poll. Pick explicit waits and leave the implicit wait at its default of zero.

## Common mistakes

- **Wrapping everything in `time.sleep`.**
- **Passing a locator without the tuple**, as in `EC.presence_of_element_located(By.ID, "x")`. It needs `(By.ID, "x")`.
- **Waiting for presence, then clicking.** Wait for clickable.
- **A huge timeout** that hides a real problem. Ten to twenty seconds is plenty.
- **Catching `TimeoutException` and continuing** as though it succeeded.
