All three were measured on the same small tree."

:::caution[Measured on one tree: `glob` and `rglob` do not agree]
Files present: `a.txt`, `b.TXT`, `.hidden.txt`, `sub/c.txt`, `sub/deep/d.txt`, `sub/e.md`.

| Call | Returns |
| --- | --- |
| `glob("*.txt")` | `a.txt`, `b.TXT` |
| `glob("**/*.txt")` | `sub/c.txt` — **one level**, `**` behaved like `*` |
| `glob("**/*.txt", recursive=True)` | `a.txt`, `b.TXT`, `sub/c.txt`, `sub/deep/d.txt` |
| `Path(".").rglob("*.txt")` | the same **plus `.hidden.txt`** |

Three separate traps in one table.

**`**` does nothing without `recursive=True`.** The pattern is accepted either way, so the
script runs and silently processes a fraction of the files.

**Dotfiles are invisible to `glob`** — `.hidden.txt` is absent from `*.txt` and needs a pattern
starting with a literal dot. `pathlib.rglob` does **not** share that behaviour and returns it.

**Case sensitivity is the filesystem's, not the pattern's.** `b.TXT` matched `*.txt` here on
Windows and would not on Linux — so a script tested on one and deployed on the other silently
processes a different set of files.
:::

## What glob does

`glob` finds files using wildcard patterns:

- `*.txt`
- `data_??.csv`
- recursive patterns with `**`

## Using `glob` module

```python title="glob_basic.py" showLineNumbers{1}
from glob import glob

for path in glob("*.py"):
    print(path)
```

## Recursive glob

```python title="glob_recursive.py" showLineNumbers{1}
from glob import glob

for path in glob("**/*.md", recursive=True):
    print(path)
```

## Prefer pathlib

`pathlib.Path.rglob` is often cleaner.
