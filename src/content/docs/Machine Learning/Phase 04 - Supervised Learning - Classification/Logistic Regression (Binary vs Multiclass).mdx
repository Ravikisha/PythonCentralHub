## What you'll learn

- why a classifier is named "regression", and what it is actually regressing
- the sigmoid derived from **log-odds**, not pulled out of the air
- **log loss**, why it is convex, and why it punishes confident mistakes so harshly
- a full gradient step computed **by hand** on four rows
- **softmax regression** for more than two classes, and why it is not the same as multilabel
- how moving the threshold trades precision against recall on a real dataset

## Intuition

A linear model outputs any real number. A probability has to live between 0 and 1. Logistic
regression is the smallest possible bridge between the two: compute the linear score exactly as in
Phase 3, then squash it.

The squashing function is not arbitrary. Ask instead: what quantity *can* a linear model predict
without bounds? The answer is the **log-odds**. Odds run from 0 to infinity; their logarithm runs
from $-\infty$ to $+\infty$ — exactly the range a linear model produces. So model the log-odds
linearly, then invert to recover the probability. The inverse *is* the sigmoid.

  Z --> S["Sigmoid<br/>p = 1 / (1 + e^-z)"]
  S --> P["Probability p"]
  P --> T["Threshold (default 0.5)"]
  T --> Y["Predicted class"]
```

## The math

### From odds to the sigmoid

For a probability $p$, the **odds** are $p/(1-p)$ and the **log-odds** (or *logit*) are their
logarithm. Model that linearly:

$$
\operatorname{logit}(p) = \log\frac{p}{1-p} = \mathbf{w}^\top\mathbf{x} + b = z
$$

Solve for $p$:

$$
\frac{p}{1-p} = e^{z}
\;\Longrightarrow\;
p = e^{z} - p\,e^{z}
\;\Longrightarrow\;
p\left(1 + e^{z}\right) = e^{z}
\;\Longrightarrow\;
p = \frac{e^{z}}{1 + e^{z}} = \frac{1}{1 + e^{-z}}
$$

$$
\boxed{\;\sigma(z) = \frac{1}{1 + e^{-z}}\;}
$$

The sigmoid is not a design choice; it is what you get by insisting that a linear model predicts
log-odds. This also hands you the interpretation of a coefficient: **$w_j$ is the change in
log-odds per unit of $x_j$**, so $e^{w_j}$ is the multiplicative change in the odds.

### Log loss

Squared error against a sigmoid output is non-convex, so gradient descent could get stuck. Instead
use the negative log-likelihood of a Bernoulli outcome:

$$
J(\mathbf{w}, b) = -\frac{1}{m}\sum_{i=1}^{m}\left[
y^{(i)}\log p^{(i)} + \left(1 - y^{(i)}\right)\log\left(1 - p^{(i)}\right)
\right]
$$

Only one term is ever active per row: if $y = 1$ the cost is $-\log p$, if $y = 0$ it is
$-\log(1-p)$. Both blow up as the model becomes confidently wrong.

### The gradient — the surprise

Differentiate log loss with respect to the weights and, after the algebra cancels, you get:

$$
\frac{\partial J}{\partial w_j} = \frac{1}{m}\sum_{i=1}^{m}\left(p^{(i)} - y^{(i)}\right)x_j^{(i)}
$$

That is **exactly the linear regression gradient**, with the prediction replaced by the sigmoid
output. The messy $\sigma'(z) = \sigma(z)(1-\sigma(z))$ term produced by the chain rule cancels
against the derivative of the logarithm. Log loss is the loss that makes logistic regression as
simple to optimise as least squares — a strong argument that it is the *right* loss, not merely a
convenient one.

There is no closed form, but $J$ is convex in $(\mathbf{w}, b)$, so
[gradient descent](/machine-learning/phase-03---supervised-learning---regression/gradient-descent-explained/)
always reaches the global minimum.

## Worked example by hand

Four emails, one feature: the number of links. Start from $w = 1.0$, $b = -2.5$.

| $i$ | links $x$ | true $y$ | $z = x - 2.5$ | $p = \sigma(z)$ | loss |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 0 | −1.5 | 0.1824 | $-\log(0.8176) = 0.2014$ |
| 2 | 2 | 0 | −0.5 | 0.3775 | $-\log(0.6225) = 0.4741$ |
| 3 | 3 | 1 | +0.5 | 0.6225 | $-\log(0.6225) = 0.4741$ |
| 4 | 4 | 1 | +1.5 | 0.8176 | $-\log(0.8176) = 0.2014$ |

**Step 1 — the cost.**

$$
J = \frac{0.2014 + 0.4741 + 0.4741 + 0.2014}{4} = 0.3377
$$

**Step 2 — the errors $p - y$.**

$$
p - y = [\,0.1824,\; 0.3775,\; -0.3775,\; -0.1824\,]
$$

**Step 3 — the gradients.**

$$
\frac{\partial J}{\partial w} = \frac{1}{4}\Big[(0.1824)(1) + (0.3775)(2) + (-0.3775)(3) + (-0.1824)(4)\Big] = -0.2312
$$

$$
\frac{\partial J}{\partial b} = \frac{0.1824 + 0.3775 - 0.3775 - 0.1824}{4} = 0.0000
$$

**Step 4 — one step at $\alpha = 1$.**

$$
w \leftarrow 1.0 - (1)(-0.2312) = 1.2312,
\qquad
b \leftarrow -2.5 - (1)(0) = -2.5
$$

The intercept gradient is exactly zero because the data is symmetric about $x = 2.5$, which is
where $b = -2.5$ already places the boundary. Only the slope needs to grow — the model is being
told to become *more confident*, not to move the boundary. Left running, $w$ diverges toward
infinity, because perfectly separable data has no finite maximum-likelihood solution. Regularisation
is what stops that, which is why scikit-learn applies an $\ell_2$ penalty by default.

## From scratch

```python title="logistic_from_scratch.py" showLineNumbers{1}
import numpy as np


def sigmoid(z):
    return 1 / (1 + np.exp(-z))


def log_loss(y, p, eps=1e-15):
    p = np.clip(p, eps, 1 - eps)          # never take log(0)
    return float(-(y * np.log(p) + (1 - y) * np.log(1 - p)).mean())


x = np.array([1.0, 2.0, 3.0, 4.0])
y = np.array([0.0, 0.0, 1.0, 1.0])
w, b = 1.0, -2.5

p = sigmoid(w * x + b)
print(p.round(4))                     # [0.1824 0.3775 0.6225 0.8176]
print(round(log_loss(y, p), 4))       # 0.3377

grad_w = float(((p - y) * x).mean())
grad_b = float((p - y).mean())
print(round(grad_w, 4), round(grad_b, 4))   # -0.2312 0.0

w, b = w - 1.0 * grad_w, b - 1.0 * grad_b
print(round(w, 4), round(b, 4))             # 1.2312 -2.5
print(round(log_loss(y, sigmoid(w * x + b)), 4))   # 0.318 — the cost fell
```

Every figure matches the hand calculation, and the cost drops from 0.3377 to 0.3180 in one step.

## With scikit-learn

### Binary: one feature, one boundary

```python title="iris_binary.py" showLineNumbers{1}
import numpy as np
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression

iris = load_iris()
X = iris.data[:, 3:]                      # petal width only
y = (iris.target == 2).astype(int)        # 1 if Iris virginica

model = LogisticRegression().fit(X, y)

print(model.predict([[1.7], [1.5]]))          # [1 0]
print(model.predict_proba([[2.0]]).round(3))  # [[0.187 0.813]]

boundary = -model.intercept_[0] / model.coef_[0][0]
print(f"p = 0.5 at petal width {boundary:.4f} cm")   # 1.6603 cm
```

The boundary is where $z = 0$, so $x = -b/w$ — a number you can read off the coefficients directly
and quote to a botanist.

### Multiclass: softmax regression

For $k$ classes the model computes one score per class and normalises them:

$$
p_k = \frac{\exp(s_k(\mathbf{x}))}{\sum_{j=1}^{K}\exp(s_j(\mathbf{x}))},
\qquad
s_k(\mathbf{x}) = \mathbf{w}_k^\top\mathbf{x} + b_k
$$

The predicted class is $\arg\max_k p_k$, and the loss generalises to **cross entropy**, which
reduces to ordinary log loss when $K = 2$.

```python title="iris_softmax.py" showLineNumbers{1}
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression

iris = load_iris()
X = iris.data[:, (2, 3)]                  # petal length, petal width
y = iris.target                           # three classes

model = LogisticRegression(C=10, max_iter=1000).fit(X, y)

print(model.predict([[5, 2]]))                  # [2]  -> virginica
print(model.predict_proba([[5, 2]]).round(3))   # [[0.    0.057 0.943]]
print(f"training accuracy {model.score(X, y):.4f}")   # 0.9600
```

:::caution[Softmax is not multilabel]
Softmax forces the probabilities to sum to 1, so the classes compete. It is correct only when
exactly one label applies. For "this photo contains a dog *and* a beach", train one independent
sigmoid per label instead.
:::

## Pitfalls

:::caution[`C` runs backwards]
Everywhere else in scikit-learn, `alpha` is regularisation strength. In `LogisticRegression` and
`SVC` the parameter is `C`, the *inverse*. `C=0.01` is heavy regularisation; `C=100` is almost
none. Grid searches over `C` should span log space, e.g. `np.logspace(-3, 3, 13)`.
:::

:::caution[Scale your features]
The default `lbfgs` solver converges slowly on unscaled data and often emits a
`ConvergenceWarning`. Worse, the L2 penalty is applied to coefficients whose size depends on the
feature units, so regularisation becomes arbitrary. Always put a `StandardScaler` in front.
:::

:::caution[Perfect separation makes the coefficients explode]
If a feature separates the classes exactly, the maximum-likelihood weights run to infinity —
on the four-row example above, unregularised fitting reaches $w \approx 18$. The default L2
penalty prevents this. If you set `C` very high and see enormous coefficients, that is what
happened.
:::

:::danger[A probability is only useful if it is calibrated]
Logistic regression is usually well calibrated out of the box, which is its main advantage over
SVMs and boosted trees. But heavy regularisation or resampling for class imbalance both distort the
probabilities. Check with a calibration curve before treating 0.7 as "70% of these are positive".
:::

## Recap

- Model the **log-odds** linearly and invert; the sigmoid falls out of the algebra.
- Log loss is the negative Bernoulli log-likelihood, convex, and it punishes confident errors
  without limit.
- Its gradient is $\frac{1}{m}\sum(p - y)x$ — the same shape as least squares, because the sigmoid
  and log derivatives cancel.
- Hand-worked on four rows: cost 0.3377, $\partial J/\partial w = -0.2312$, $\partial J/\partial b = 0$.
- Softmax extends to $K$ mutually exclusive classes; independent sigmoids handle multilabel.
- The threshold is a post-training decision. On the breast-cancer model it moves precision from
  0.82 to 1.00 while recall falls from 0.98 to 0.88.
- `C` is the *inverse* of regularisation strength, and features must be scaled.
