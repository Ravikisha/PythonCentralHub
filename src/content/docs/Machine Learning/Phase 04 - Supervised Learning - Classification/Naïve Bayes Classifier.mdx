## What you'll learn

- how Bayes' theorem turns "prior belief + new evidence" into a probability
- why the "naïve" independence assumption is almost always false, yet still works
- the three common variants — Gaussian, Multinomial, Bernoulli — and when to use each
- how a Naïve Bayes model reaches a decision without any gradient descent at all

## The big idea

Naïve Bayes doesn't fit a boundary the way Logistic Regression or an SVM does.
Instead, for every class it asks a purely probabilistic question:

> "Given these features, how likely is it that this instance belongs to this class?"

It then predicts whichever class comes out most likely. The "naïve" part is a
simplifying assumption: it treats every feature as **conditionally independent**
of every other feature, given the class. In reality, features are rarely truly
independent (in a spam email, "free" and "prize" tend to show up together) — but
the model is so fast and so hard to overfit that it remains a strong baseline
even when the assumption is technically wrong.

## Bayes' theorem

Everything here comes from one formula:

`P(class | features) = P(features | class) * P(class) / P(features)`

Since `P(features)` is the same constant for every class, it doesn't change
*which* class wins — so in practice Naïve Bayes only needs the numerator:

`P(class | features) ∝ P(features | class) * P(class)`

- `P(class)` is the **prior** — how common that class is before you look at any evidence
- `P(features | class)` is the **likelihood** — how typical these features are for that class
- The class with the highest `prior × likelihood` product wins

Because of the independence assumption, the likelihood of *all* features
together is just the product of each individual feature's likelihood:

`P(features | class) = P(feature_1 | class) * P(feature_2 | class) * ...`

```mermaid title="How Naïve Bayes decides" desc="Bayes theorem combines a class prior with per-feature likelihoods, multiplies them for every class, and picks the highest score."
flowchart LR
  P["Prior P(class)"] --> M["Multiply"]
  L["Likelihood P(feature | class)<br/>(assumed independent per feature)"] --> M
  M --> S["Score per class"]
  S --> A["argmax over classes"]
  A --> Y["Predicted class"]
```

### A tiny worked example

Say you're filtering spam. Before reading a word, 40% of your inbox is spam
(`P(spam) = 0.4`). You observe the word "free". Historically, "free" shows up in
80% of spam emails but only 10% of real ("ham") emails:

- `P(spam) * P("free" | spam) = 0.4 * 0.8 = 0.32`
- `P(ham) * P("free" | ham) = 0.6 * 0.1 = 0.06`

Normalizing so the two add up to 1: `0.32 / (0.32 + 0.06) ≈ 0.842`. So after
seeing just one word, the model is already 84.2% confident this is spam — and
it got there with nothing but multiplication.

## Why it's popular for text

Text turns into a **bag of words**: a huge, sparse vector of word counts (or
presence/absence flags) per document. Most entries are zero, and the vocabulary
can run into the tens of thousands of columns. Naïve Bayes handles this kind of
high-dimensional, sparse data cheaply — no iterative optimization, no matrix
inversion, just counting.

## Common variants

Scikit-learn ships three flavors, chosen by what your features look like:

- **GaussianNB** — continuous features (assumes each feature is normally
  distributed within a class — think sensor readings, or the iris measurements)
- **MultinomialNB** — word/event counts (classic choice for text: TF or
  word-count features)
- **BernoulliNB** — binary features (word present/absent, rather than how many
  times)

## Scikit-learn example

```python title="GaussianNB on the iris dataset" showLineNumbers{1}
from sklearn.datasets import load_iris
from sklearn.naive_bayes import GaussianNB

X, y = load_iris(return_X_y=True)

nb = GaussianNB()
nb.fit(X, y)

print("Training accuracy:", round(nb.score(X, y), 4))
# Training accuracy: 0.96

print(nb.predict([[5.0, 3.4, 1.5, 0.2]]))
# [0]  -> Iris setosa

print(nb.predict_proba([[6.0, 2.9, 4.5, 1.5]]).round(3))
# [[0.    0.986 0.014]]  -> 98.6% confident it's Iris versicolor
```

Notice there's no `loss`, no learning rate, no iterations — `fit()` just
computes the mean and standard deviation of each feature per class, then
`predict()` plugs new values into those Gaussians and compares.

## Pros and cons

Pros:

- extremely fast to train and predict — a single pass over the data
- works well even with relatively little training data
- naturally handles more than two classes, no OvR/OvO trick needed
- a strong, cheap baseline before reaching for anything heavier

Cons:

- the independence assumption can cap accuracy when features are correlated
- `predict_proba()` outputs are often overconfident (poorly calibrated), even
  when the predicted class is correct

:::tip[From the book]
Géron's classification chapter notes that some algorithms — SGD classifiers,
Random Forest classifiers, and **naive Bayes classifiers** — are capable of
handling multiple classes natively. Others, like Logistic Regression and SVM
classifiers, are strictly binary and need a One-vs-Rest or One-vs-One wrapper
to handle more than two classes. Naïve Bayes skips that step entirely, which
is part of why it's such a convenient baseline for multiclass problems like
document categorization.
:::
