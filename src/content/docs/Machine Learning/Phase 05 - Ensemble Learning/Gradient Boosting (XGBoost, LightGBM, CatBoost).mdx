## What you'll learn

- why fitting the **residual** is gradient descent, taken in function space
- three boosting stages computed **by hand**, with the MSE at each one
- shrinkage measured: ten times smaller steps need roughly ten times more of them
- **early stopping** via `staged_predict`, and why it is not optional here
- how XGBoost, LightGBM and CatBoost actually differ, and when the difference matters
- an honest comparison where a boosted model does *not* win

## Intuition

[AdaBoost](/machine-learning/phase-05---ensemble-learning/boosting-introduction-to-adaboost/)
made the next learner focus on hard cases by reweighting the samples. Gradient boosting does the
same thing with a change that turns out to be far more general: instead of reweighting, **the next
learner is fitted directly to what is left over.**

Predict the mean. Look at the residuals. Fit a small tree to the residuals. Add it. Look at the new
residuals. Repeat.

That reframing is what lets gradient boosting handle any differentiable loss — squared error,
absolute error, log loss, Poisson, quantile — with no change to the algorithm. AdaBoost's
reweighting turns out to be the special case for exponential loss.

```mermaid
flowchart LR
  F0["F&#8320; = mean(y)"] --> R1["residual r&#8321; = y - F&#8320;"]
  R1 --> H1["fit tree h&#8321; to r&#8321;"]
  H1 --> F1["F&#8321; = F&#8320; + &eta;&middot;h&#8321;"]
  F1 --> R2["residual r&#8322; = y - F&#8321;"]
  R2 --> H2["fit tree h&#8322; to r&#8322;"]
  H2 --> F2["F&#8322; = F&#8321; + &eta;&middot;h&#8322;"]
  F2 --> D["... repeat"]
```

## The math

### Why the residual is a gradient

Take squared error as the loss for a single observation:

$$
L(y, F) = \tfrac{1}{2}\left(y - F\right)^2
$$

Differentiate with respect to the **prediction** $F$, not with respect to any parameter:

$$
\frac{\partial L}{\partial F} = -(y - F)
\qquad\Longrightarrow\qquad
-\frac{\partial L}{\partial F} = y - F = \text{residual}
$$

**The residual is the negative gradient of the loss with respect to the prediction.** So fitting a
tree to the residuals is fitting a tree to the direction of steepest descent, and adding it is a
gradient step:

$$
F_{m}(\mathbf{x}) = F_{m-1}(\mathbf{x}) + \eta \, h_m(\mathbf{x})
$$

Compare that with the parameter update from
[Gradient Descent Explained](/machine-learning/phase-03---supervised-learning---regression/gradient-descent-explained/):
$\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} - \alpha\nabla J$. Same shape. The difference is
that the step is a whole function rather than a parameter vector — hence "gradient descent in
function space".

### The general algorithm

For any differentiable loss $L$:

1. $F_0(\mathbf{x}) = \arg\min_c \sum_i L(y_i, c)$ — the best constant.
2. For $m = 1, \ldots, M$:
   - compute pseudo-residuals $r_{im} = -\left[\partial L(y_i, F(\mathbf{x}_i)) / \partial F(\mathbf{x}_i)\right]_{F = F_{m-1}}$
   - fit a regression tree $h_m$ to the $r_{im}$
   - update $F_m = F_{m-1} + \eta\, h_m$

Swap the loss and only the pseudo-residual changes:

| Loss | Pseudo-residual | Use |
| --- | --- | --- |
| Squared error | $y - F$ | Regression, default |
| Absolute error | $\operatorname{sign}(y - F)$ | Regression with outliers |
| Huber | $y - F$ clipped at $\delta$ | Regression, robust and smooth |
| Log loss | $y - \sigma(F)$ | Binary classification |
| Quantile | asymmetric sign | Prediction intervals |

Notice the log-loss row: the pseudo-residual is $y - \sigma(F)$, exactly the gradient from
[logistic regression](/machine-learning/phase-04---supervised-learning---classification/logistic-regression-binary-vs-multiclass/).
The same expression appears for a third time, and for the same reason.

## Worked example by hand

Three points: $x = [1, 2, 3]$, $y = [10, 20, 30]$. Learning rate $\eta = 0.5$, and each $h_m$ is a
depth-1 stump.

**Stage 0 — the constant.** For squared error the best constant is the mean:

$$
F_0 = \frac{10 + 20 + 30}{3} = 20,
\qquad
\text{MSE} = \frac{100 + 0 + 100}{3} = 66.667
$$

**Stage 1 — fit the residuals.** $r_1 = y - F_0 = [-10, 0, +10]$. A stump splitting at $x \le 1.5$
gives the left leaf $-10$ and the right leaf $\frac{0 + 10}{2} = 5$:

$$
h_1 = [-10,\; 5,\; 5]
\qquad
F_1 = F_0 + 0.5\,h_1 = [15,\; 22.5,\; 22.5]
$$

$$
r_2 = y - F_1 = [-5,\; -2.5,\; +7.5],
\qquad
\text{MSE} = \frac{25 + 6.25 + 56.25}{3} = 29.167
$$

**Stage 2 — fit those residuals.** A stump splitting at $x \le 2.5$ gives the left leaf
$\frac{-5 + (-2.5)}{2} = -3.75$ and the right leaf $7.5$:

$$
h_2 = [-3.75,\; -3.75,\; 7.5]
\qquad
F_2 = F_1 + 0.5\,h_2 = [13.125,\; 20.625,\; 26.25]
$$

$$
r_3 = [-3.125,\; -0.625,\; +3.75],
\qquad
\text{MSE} = 8.073
$$

| Stage | Prediction | MSE | Reduction |
| --- | --- | --- | --- |
| 0 | 20.000, 20.000, 20.000 | 66.667 | — |
| 1 | 15.000, 22.500, 22.500 | 29.167 | 56% |
| 2 | 13.125, 20.625, 26.250 | 8.073 | 72% |

Two things to notice. The predictions are walking toward $[10, 20, 30]$ without ever jumping there
— that is $\eta = 0.5$ holding them back. And no individual stump is any good: the best of them
predicts three distinct values. **The ensemble is good; no member is.**

## See it move

Stage by stage, the ensemble grows toward the data while the residuals collapse toward zero.

```p5 title="Residuals shrinking, stage by stage" desc="The green curve is the running ensemble and the amber stems are the residuals it has not yet explained. Each stage adds one shallow stump and the stems get shorter." height="340"
let pts = [], stage = 0, t = 0;
let fitted = [];
const LR = 0.5, STAGES = 8;
function target(x) { return 0.55 * x * x + 0.6 * Math.sin(2.4 * x); }
function genPts() {
  pts = [];
  for (let i = 0; i < 34; i++) {
    const x = -2.4 + (4.8 * i) / 33;
    pts.push({ x, y: target(x) + randomGaussian(0, 0.18) });
  }
  fitted = pts.map(() => 0);
  stage = 0;
  t = 0;
}
function setup() {
  createCanvas(600, 340);
  textFont("monospace");
  genPts();
}
function addStump() {
  // a depth-1 stump on the current residuals: best of a few candidate splits
  const resid = pts.map((p, i) => p.y - fitted[i]);
  let best = null;
  for (let s = 1; s < pts.length - 1; s++) {
    const L = resid.slice(0, s), R = resid.slice(s);
    const lm = L.reduce((a, b) => a + b, 0) / L.length;
    const rm = R.reduce((a, b) => a + b, 0) / R.length;
    let sse = 0;
    for (const v of L) sse += (v - lm) ** 2;
    for (const v of R) sse += (v - rm) ** 2;
    if (!best || sse < best.sse) best = { s, lm, rm, sse };
  }
  for (let i = 0; i < pts.length; i++) {
    fitted[i] += LR * (i < best.s ? best.lm : best.rm);
  }
  stage++;
}
function draw() {
  background(13, 17, 23);
  const ox = 50, oy = 46, w = width - 100, h = 210;
  const px = (x) => ox + (x + 2.6) / 5.2 * w;
  const py = (y) => oy + h - (y + 1.6) / 6.0 * h;

  stroke(60, 70, 84);
  strokeWeight(1);
  line(ox, py(0), ox + w, py(0));

  // residual stems
  for (let i = 0; i < pts.length; i++) {
    stroke(255, 211, 67, 190);
    strokeWeight(1.6);
    line(px(pts[i].x), py(pts[i].y), px(pts[i].x), py(fitted[i]));
  }
  // data and ensemble
  noStroke();
  for (const p of pts) { fill(75, 139, 190); ellipse(px(p.x), py(p.y), 7, 7); }
  stroke(120, 200, 120);
  strokeWeight(2.4);
  noFill();
  beginShape();
  for (let i = 0; i < pts.length; i++) vertex(px(pts[i].x), py(fitted[i]));
  endShape();

  const mse = pts.reduce((a, p, i) => a + (p.y - fitted[i]) ** 2, 0) / pts.length;
  noStroke();
  fill(107, 169, 221);
  textSize(13);
  textAlign(LEFT, TOP);
  text("stage " + stage + " of " + STAGES, ox, 16);
  fill(255, 211, 67);
  textAlign(RIGHT, TOP);
  text("residual MSE " + mse.toFixed(4), ox + w, 16);
  fill(140);
  textSize(10);
  textAlign(LEFT, BOTTOM);
  text("amber stems = what the ensemble has not yet explained    (click to restart)",
       ox, height - 12);

  t++;
  if (t % 42 === 0) {
    if (stage < STAGES) addStump();
    else genPts();
  }
}
function mousePressed() { genPts(); }
```

## Shrinkage

<Figure

Measured on 1,560 held-out rows of the Hastie benchmark:

| Learning rate | Best error | Trees needed |
| --- | --- | --- |
| 1.0 | **0.0679** | 381 |
| 0.3 | 0.0786 | 1,193 |
| 0.1 | 0.0714 | 1,199 |
| 0.03 | 0.0833 | 936 (not converged) |

### Reading the plot

1. **Smaller learning rates need proportionally more trees.** Roughly, $\eta \times M$ is
   conserved: 1.0 at 381 trees and 0.1 at 1,199 land within 0.4 points of each other.
2. **They did not reach a lower floor here.** The common claim that shrinkage always improves
   generalisation is not supported by this run — lr=1.0 was the best of the four. Shrinkage buys
   *stability and control*, not a guaranteed better score.
3. **lr=0.03 has not converged at 1,200 trees.** Its curve is still descending. Reporting it as
   "worse" would be reporting an unfinished experiment.
4. **The practical rule survives**: set a low learning rate, use early stopping to decide the tree
   count, and let the compute budget cap it. Just do not expect the low rate to pay for itself
   automatically.

## Early stopping

`n_estimators` in a boosted model **can** overfit, so it must be chosen rather than set. `staged_predict`
replays the ensemble one tree at a time:

```python title="early_stopping.py" showLineNumbers{1}
import numpy as np
from sklearn.datasets import make_hastie_10_2
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import train_test_split

X, y = make_hastie_10_2(n_samples=2400, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.35, random_state=0)

model = GradientBoostingClassifier(n_estimators=1200, learning_rate=0.1,
                                   max_depth=3, random_state=0).fit(X_tr, y_tr)

errors = [1 - (pred == y_te).mean() for pred in model.staged_predict(X_te)]
best_n = int(np.argmin(errors)) + 1

print(f"best error {min(errors):.4f} at {best_n} trees")
print(f"error at 1200 trees {errors[-1]:.4f}")
```

Or let scikit-learn stop for you, which avoids fitting trees you will discard:

```python
GradientBoostingClassifier(
    n_estimators=2000,
    validation_fraction=0.15,     # hold out 15% internally
    n_iter_no_change=25,          # stop after 25 rounds without improvement
    tol=1e-4,
)
```

## HistGradientBoosting: the fast default

scikit-learn's `HistGradientBoosting*` bins continuous features into 255 buckets before searching
splits, which turns the split search from $O(m \log m)$ into $O(\text{bins})$. It is the same idea
LightGBM introduced, and it is dramatically faster on anything over a few thousand rows.

```python title="histgb.py" showLineNumbers{1}
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import (HistGradientBoostingClassifier,
                              RandomForestClassifier)
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)

models = {
    "HistGradientBoosting": HistGradientBoostingClassifier(random_state=0),
    "RandomForest": RandomForestClassifier(n_estimators=200, random_state=0, n_jobs=-1),
    "LogisticRegression": make_pipeline(StandardScaler(),
                                        LogisticRegression(max_iter=5000)),
}

for name, model in models.items():
    print(f"{name:<22} CV {cross_val_score(model, X, y, cv=5).mean():.4f}")

# HistGradientBoosting   CV 0.9648
# RandomForest           CV 0.9596
# LogisticRegression     CV 0.9807
```

:::caution[Boosting is not automatically the winner]
On this dataset **logistic regression beats both ensembles** — 0.9807 against 0.9648 and 0.9596.
Thirty well-behaved, largely linear features on 569 rows is a linear model's ideal case. Gradient
boosting dominates *many* tabular problems, not all of them, and the cheap baseline is worth
running first.
:::

`HistGradientBoosting` also handles missing values natively — it learns which side of each split a
NaN should go — so no imputer is required.

## The four libraries

| | scikit-learn `HistGB` | XGBoost | LightGBM | CatBoost |
| --- | --- | --- | --- | --- |
| Tree growth | Level-wise, binned | Level-wise (depth-wise) | **Leaf-wise** (best-first) | **Symmetric / oblivious** |
| Speed on large data | Fast | Fast | **Fastest** | Fast |
| Categorical features | Limited | Needs encoding | Native | **Native, ordered target stats** |
| Missing values | Native | Native | Native | Native |
| Default quality | Good | Good, needs tuning | Good, needs tuning | **Best out of the box** |
| GPU | No | Yes | Yes | Yes |
| Extra dependency | **None** | Yes | Yes | Yes |

The differences that actually matter in practice:

- **LightGBM grows leaf-wise**: it splits whichever leaf reduces loss most, rather than completing
  each level. Deeper, more unbalanced trees, faster convergence — and easier overfitting on small
  data, so `num_leaves` needs care.
- **CatBoost uses ordered target statistics** for categorical features, which is target encoding
  done with a scheme that provably avoids the leakage a naive `groupby().mean()` introduces. If
  your data is categorical-heavy, this is the reason to pick it.
- **XGBoost adds explicit regularisation** to the objective (`lambda`, `alpha`, `gamma`) and was the
  first to popularise the second-order (Newton) approximation of the loss.

**Start with `HistGradientBoosting`.** No new dependency, competitive accuracy, and if it is not
enough you now know what you are shopping for.

## Pitfalls

:::danger[Setting `n_estimators` without early stopping]
Unlike a random forest, more boosting rounds eventually hurt. Always use `staged_predict` or
`n_iter_no_change` to find the turning point.
:::

:::caution[Deep trees in a boosted model]
Depth 20 makes each learner strong, which defeats the premise. Boosting needs weak learners; depth
3 to 8 is the usable range.
:::

:::caution[Tuning `learning_rate` and `n_estimators` separately]
They trade against each other directly. Halving the learning rate roughly doubles the trees needed.
Search them together, or fix a low rate and let early stopping pick the count.
:::

:::caution[Assuming boosting always wins]
Logistic regression beat both ensembles on breast cancer, 0.9807 to 0.9648. Run the cheap baseline
first, every time.
:::

## Compare

| | Random Forest | AdaBoost | Gradient Boosting |
| --- | --- | --- | --- |
| Members | Deep trees | Stumps | Shallow trees |
| Next member sees | A bootstrap sample | Reweighted samples | **Residuals** |
| Loss functions | Fixed | Exponential only | **Any differentiable** |
| Parallel training | Yes | No | No |
| More members overfit | No | Yes | **Yes** |
| Tuning burden | Low | Low | **High** |
| Typical tabular accuracy | Very good | Good | **Best** |

## Recap

- The residual is the negative gradient of squared loss with respect to the prediction, so boosting
  is gradient descent in function space.
- Swapping the loss changes only the pseudo-residual, which is why gradient boosting handles log
  loss, Huber, quantile and Poisson with one algorithm.
- Hand-worked: MSE 66.667 → 29.167 → 8.073 in two stages, from stumps that individually predict two
  values each.
- Shrinkage trades against tree count roughly reciprocally — 1.0 peaked at 381 trees, 0.1 at 1,199 —
  and did **not** reach a lower floor in this run.
- `n_estimators` can overfit. Use `staged_predict` or `n_iter_no_change`.
- Start with `HistGradientBoosting`; reach for LightGBM on very large data and CatBoost on
  categorical-heavy data.
- Logistic regression beat both ensembles on breast cancer. Run the cheap baseline first.
