## What you'll learn

- how boosting differs from bagging: learners trained **one after another**, not in parallel
- how AdaBoost re-weights training instances to force new learners to focus on hard cases
- the predictor-weight formula Géron walks through in Chapter 7, and why a predictor that
  is wrong more often than not gets a **negative** weight
- how scikit-learn's `AdaBoostClassifier` implements all of this in a few lines
- a live comparison: one decision stump vs. 200 boosted stumps on the same data

## What boosting is

Bagging trains many models **in parallel** on random subsets and lets them vote.
Boosting takes a different approach: it trains models **sequentially**, and each new
model pays extra attention to the examples the previous models got wrong.

Géron calls this "hypothesis boosting" — the general idea behind every boosting method
is to combine several **weak learners** (models barely better than a coin flip) into one
**strong learner**, by chaining them so each one corrects its predecessor.

```mermaid title="AdaBoost: sequential weighted learners" desc="Each new learner focuses more on the training points the previous learners got wrong."
flowchart LR
  D["Training data (equal weights)"] --> M1["Learner 1"]
  M1 --> W1["Reweight: boost misclassified points"]
  W1 --> M2["Learner 2 (focuses on hard points)"]
  M2 --> W2["Reweight again"]
  W2 --> M3["Learner 3"]
  M1 -- "weight α1" --> C["Weighted vote"]
  M2 -- "weight α2" --> C
  M3 -- "weight α3" --> C
  C --> P["Final prediction"]
```

## AdaBoost intuition

AdaBoost (short for **Adaptive Boosting**) works like this:

1. Every training instance starts with the same weight, `1/m`.
2. Train a base classifier (often a shallow tree, or even just a **decision stump** —
   a tree with `max_depth=1`) and measure its **weighted error rate**.
3. Give that classifier a **predictor weight**: the more accurate it is, the higher its
   weight; a classifier that's no better than random guessing gets a weight near zero,
   and one that's *worse* than random guessing gets a **negative** weight.
4. **Boost the weights of the misclassified instances**, so the next classifier is
   forced to work harder on them.
5. Repeat steps 2-4 until you hit `n_estimators`, or a perfect predictor is found.

To predict, AdaBoost doesn't just average — it takes a **weighted vote** across all
learners, using each learner's predictor weight from step 3.

:::note
This has echoes of Gradient Descent — instead of tweaking one model's parameters to
shrink the error, AdaBoost keeps *adding* predictors to the ensemble, each one nudging
the whole thing to be a little better.
:::

## The predictor-weight formula

Géron's Equation 7-2 is worth internalizing, because it explains *why* boosting works.
For a predictor with weighted error rate `r`, its predictor weight (often called `alpha`,
`α`) is:

```
alpha = log((1 - r) / r)
```

- if `r` is small (the predictor is accurate), `alpha` is large — it gets a big say in
  the final vote
- if `r = 0.5` (pure random guessing), `alpha = 0` — it's ignored entirely
- if `r > 0.5` (worse than random!), `alpha` goes **negative** — the ensemble literally
  flips that learner's vote

```python title="Predictor weight from error rate" showLineNumbers{1}
import numpy as np

for r in (0.05, 0.2, 0.3, 0.49):
    alpha = np.log((1 - r) / r)
    print(f"error rate {r:>4} -> predictor weight {alpha:.3f}")
```

```
error rate 0.05 -> predictor weight 2.944
error rate  0.2 -> predictor weight 1.386
error rate  0.3 -> predictor weight 0.847
error rate 0.49 -> predictor weight 0.040
```

Every misclassified instance then has its weight multiplied by `exp(alpha)` before the
weights get renormalized — the more trustworthy the predictor, the harder it boosts the
points it got wrong.

## Scikit-learn example

Scikit-learn's `AdaBoostClassifier` (and `AdaBoostRegressor` for regression) hides all of
this bookkeeping behind `.fit()`. The default base estimator is already a decision stump
(`max_depth=1`), and modern scikit-learn always uses the probability-aware "SAMME"
algorithm internally — no `algorithm=` argument needed anymore.

```python title="AdaBoost vs. a single stump" showLineNumbers{1}
from sklearn.ensemble import AdaBoostClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

# a single decision stump on its own
stump = DecisionTreeClassifier(max_depth=1, random_state=42)
stump.fit(X_train, y_train)
print("single stump accuracy:", round(accuracy_score(y_test, stump.predict(X_test)), 3))

# 200 stumps, boosted
ada_clf = AdaBoostClassifier(
    estimator=DecisionTreeClassifier(max_depth=1, random_state=42),
    n_estimators=200,
    learning_rate=0.5,
    random_state=42,
)
ada_clf.fit(X_train, y_train)
print("AdaBoost accuracy:   ", round(accuracy_score(y_test, ada_clf.predict(X_test)), 3))
```

```
single stump accuracy: 0.824
AdaBoost accuracy:    0.896
```

200 weak stumps, chained together and reweighted, beat the single stump by a wide
margin — none of them alone is a strong model, but the sequence is.

:::tip[From the book]
AdaBoost has one real drawback compared to bagging: it **can't be parallelized**. Each
learner depends on the reweighted output of the one before it, so training happens one
step at a time. If your AdaBoost ensemble is *overfitting*, Géron's advice is to reduce
`n_estimators` or regularize the base estimator more strongly (e.g. shrink `max_depth`).
:::

## Watch the weights shift

Every round, the points a learner gets wrong grow heavier (bigger circles below), and
the points it already handles well shrink back down — until the next round reshuffles
who's "hard."

```p5 title="Reweighting hard examples across rounds" desc="Amber circles are the current round's misclassified points — watch their weight grow, then reset as a new round begins." height="300"
const M = 30;
let weights = [];
let hard = [];
let round = 1;
let t = 0;
const ROUND_LEN = 90;

function initRound() {
  weights = new Array(M).fill(1 / M);
  hard = [];
  for (let i = 0; i < M; i++) {
    if ((i * 7 + round * 3) % M < 6) hard.push(i);
  }
  t = 0;
}

function setup() {
  createCanvas(600, 300);
  textFont("monospace");
  initRound();
}

function boostStep() {
  for (const i of hard) weights[i] *= 1.06;
  const total = weights.reduce((a, b) => a + b, 0);
  for (let i = 0; i < M; i++) weights[i] /= total;
}

function draw() {
  background(13, 17, 23);
  const cols = 10, rows = 3;
  const cellW = (width - 60) / cols, cellH = 150 / rows;

  const maxW = Math.max(...weights);
  for (let i = 0; i < M; i++) {
    const cx = 30 + (i % cols) * cellW + cellW / 2;
    const cy = 60 + Math.floor(i / cols) * cellH + cellH / 2;
    const isHard = hard.includes(i);
    const r = 6 + (weights[i] / maxW) * 16;
    noStroke();
    fill(isHard ? color(255, 211, 67) : color(75, 139, 190, 190));
    ellipse(cx, cy, r * 2, r * 2);
  }

  fill(210);
  textSize(13);
  textAlign(LEFT, TOP);
  text("Round " + round + " — amber = misclassified this round (weight growing)", 30, 16);
  fill(150);
  textSize(11);
  text("bigger circle = higher instance weight w(i)", 30, 250);

  t++;
  if (t % 6 === 0) boostStep();
  if (t > ROUND_LEN) {
    round++;
    initRound();
  }
}

function mousePressed() {
  round = 1;
  initRound();
}
```

## Pros and cons

Pros:

- often reaches strong accuracy with very simple base learners
- few hyperparameters to tune (`n_estimators`, `learning_rate`, base estimator)

Cons:

- sensitive to noisy labels and outliers — a mislabeled point just keeps getting
  boosted, round after round
- can't be parallelized like bagging or Random Forests
