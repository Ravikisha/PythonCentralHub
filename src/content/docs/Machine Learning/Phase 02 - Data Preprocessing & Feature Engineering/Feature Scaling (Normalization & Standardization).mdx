## What you'll learn

- why features on very different scales hurt most ML algorithms
- min-max scaling (normalization) with `MinMaxScaler`
- standardization with `StandardScaler`
- how outliers affect each method differently
- why you fit scalers on the training set only, then transform everything

## Why scaling matters

Look at two columns from the housing data: `total_rooms` ranges roughly from 6 to
39,320, while `median_income` ranges from about 0 to 15. With few exceptions, ML
algorithms don't perform well when input features are on such different scales — one
column can dominate a distance calculation or a gradient step purely because its
numbers are bigger, not because it's more important.

Note that you generally do **not** need to scale the *target* value (`median_house_value`
here) — only the input features.

There are two common approaches: **min-max scaling** and **standardization**.

## Min-max scaling (normalization)

`MinMaxScaler` shifts and rescales values so they land between 0 and 1 (or a custom
range via `feature_range`):

```python title="MinMaxScaler" showLineNumbers{1}
from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
scaler.fit(housing_num_train)  # fit on the TRAINING set only

X_train_scaled = scaler.transform(housing_num_train)
X_test_scaled = scaler.transform(housing_num_test)
```

The math is simple: subtract the minimum, divide by `(max - min)`. That simplicity is
also its weakness — a single extreme outlier stretches the range and crushes every
other value toward 0.

## Standardization

`StandardScaler` subtracts the mean (so the result always has zero mean) and divides
by the standard deviation (so the result has unit variance). It doesn't bound values
to a fixed range, which can be an issue for algorithms that expect inputs in `[0, 1]`
(e.g., some neural networks) — but it's **much less sensitive to outliers**.

```python title="StandardScaler" showLineNumbers{1}
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
scaler.fit(housing_num_train)

X_train_scaled = scaler.transform(housing_num_train)
X_test_scaled = scaler.transform(housing_num_test)
```

Consider a district with a median income mistakenly recorded as `100` (instead of a
normal range of roughly 0–15). Min-max scaling would compress every legitimate value
from `0–15` down into a tiny sliver of the `0–1` range near zero — one bad data point
distorts everything else. Standardization barely notices it, since a single outlier
barely moves the mean or standard deviation of a large dataset.

```mermaid title="Choosing a scaler" desc="MinMaxScaler bounds to a fixed range; StandardScaler is robust to outliers."
flowchart TD
  A["Numeric feature, wide scale"] --> B{"Outliers present?"}
  B -->|"Few / none"| C["MinMaxScaler<br/>bounds to [0, 1]"]
  B -->|"Yes, some extreme values"| D["StandardScaler<br/>zero mean, unit variance"]
  C --> E["fit() on TRAIN only,<br/>transform() everywhere"]
  D --> E
```

## Fit on the training set, always

Just like the imputer, scalers must be **fit on the training data only**. Fitting on
the full dataset (including the test set) leaks test-set statistics — its min, max,
mean, or standard deviation — into the transformation, which is a subtle form of data
snooping. Once fit, use the *same* fitted scaler to `transform()` the training set,
the test set, and any future data.

## Visualize it

```p5 title="Before and after StandardScaler" desc="Same 8 values, on a raw scale up top - watch each one slide down to its standardized position (zero mean, unit variance), then slide back so you can see the round trip." height="260"
let raw = [6, 500, 1200, 3000, 8000, 39320, 15000, 2000];
let scaled = [];
let rawMin, rawMax, scaledMin, scaledMax;

function setup() {
  createCanvas(600, 260);
  textFont("monospace");

  const mean = raw.reduce((a, b) => a + b, 0) / raw.length;
  const variance = raw.reduce((a, b) => a + (b - mean) ** 2, 0) / raw.length;
  const std = Math.sqrt(variance);
  scaled = raw.map((v) => (v - mean) / std);

  rawMin = Math.min(...raw);
  rawMax = Math.max(...raw);
  scaledMin = Math.min(...scaled);
  scaledMax = Math.max(...scaled);
}

function axisX(v, minV, maxV) {
  const x0 = 60, x1 = 560;
  return x0 + ((v - minV) / (maxV - minV)) * (x1 - x0);
}

function draw() {
  background(13, 17, 23);

  const rawY = 80, scaledY = 190;

  stroke(60, 70, 84);
  line(60, rawY, 560, rawY);
  line(60, scaledY, 560, scaledY);
  noStroke();

  fill(200);
  textAlign(LEFT, CENTER);
  textSize(12);
  text("raw total_rooms (6 - 39,320)", 60, rawY - 18);
  text("standardized (mean 0, std 1)", 60, scaledY - 18);

  const PERIOD = 200;
  for (let i = 0; i < raw.length; i++) {
    const rx = axisX(raw[i], rawMin, rawMax);
    const sx = axisX(scaled[i], scaledMin, scaledMax);

    // faint ghost markers at each end, so start/end positions still read mid-slide
    fill(75, 139, 190, 90);
    ellipse(rx, rawY, 7, 7);
    fill(255, 211, 67, 90);
    ellipse(sx, scaledY, 7, 7);

    // staggered ping-pong: each point slides down to its scaled spot, then back up
    const stagger = i * 10;
    const phase = ((frameCount + stagger) % PERIOD) / PERIOD;
    const ping = sin(phase * PI); // smooth 0 -> 1 -> 0, no easing needed

    const x = lerp(rx, sx, ping);
    const y = lerp(rawY, scaledY, ping);

    fill(lerpColor(color(75, 139, 190), color(255, 211, 67), ping));
    ellipse(x, y, 10, 10);
  }

  fill(180);
  textAlign(LEFT, TOP);
  textSize(11);
  text("Every point slides from its raw position to its standardized one, and back.", 60, 230);
}
```

:::tip[From the book]
Géron sums up the trade-off cleanly: min-max scaling "crushes" other values when an
outlier is present, while standardization "would not be much affected." His example is
a district with median income mistakenly recorded as `100` — proof that the *type* of
scaling you choose should depend on how clean you expect your data to be, not just on
habit.
:::
