## Goal

Build a mini project with:

- calculator functions
- test suite
- edge cases

## Suggested features

Calculator operations:

- add, subtract, multiply, divide
- divide-by-zero handling

## Test cases to include

- normal cases
- negative numbers
- floats
- divide by zero raises

## Stretch goals

- add GitHub Actions workflow
- add coverage reporting

## Scenario

Build a small calculator module and a test suite that would catch the mistakes people make in arithmetic code. The project is small on purpose, so you can focus on choosing test cases, not on the application.

## Step 1: the module

```python title="calculator.py" showLineNumbers{1}
def add(a, b):
    return a + b


def subtract(a, b):
    return a - b


def multiply(a, b):
    return a * b


def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("cannot divide by zero")
    return a / b
```

## Step 2: pick cases deliberately

For each function, think in classes of input, not random numbers:

- typical values: `add(2, 3)`
- zero, which is the identity for addition and the annihilator for multiplication
- negatives, and mixed signs
- floats, where `0.1 + 0.2` is not exactly `0.3`
- large values
- invalid input, such as `divide(1, 0)` or a string

## Step 3: a pytest suite

```python title="test_calculator.py" showLineNumbers{1}
import pytest

from calculator import add, subtract, multiply, divide


@pytest.mark.parametrize(
    "a, b, expected",
    [(2, 3, 5), (0, 0, 0), (-2, -3, -5), (-2, 3, 1), (10**12, 1, 10**12 + 1)],
)
def test_add(a, b, expected):
    assert add(a, b) == expected


def test_add_floats_uses_approx():
    assert add(0.1, 0.2) == pytest.approx(0.3)


@pytest.mark.parametrize("a, b, expected", [(5, 3, 2), (3, 5, -2), (0, 4, -4)])
def test_subtract(a, b, expected):
    assert subtract(a, b) == expected


def test_multiply_by_zero():
    assert multiply(123, 0) == 0


def test_divide():
    assert divide(9, 3) == 3
    assert divide(1, 4) == 0.25


def test_divide_by_zero_raises():
    with pytest.raises(ZeroDivisionError, match="zero"):
        divide(1, 0)
```

Notice `pytest.approx` for floats. Comparing `0.1 + 0.2 == 0.3` fails, which is one of the most common mistakes in numeric tests.

## Step 4: the same tests in unittest

Rewrite two tests as a `unittest.TestCase` class, using `assertEqual`, `assertAlmostEqual` and `assertRaises`. Doing both shows what pytest removes and what the standard library already gives you.

## Step 5: measure and challenge the suite

Run `pytest --cov=calculator --cov-report=term-missing`. Then check whether the tests are actually strong: change `subtract` to `return b - a` and confirm a test fails. If none do, the suite has a gap. This is a manual version of mutation testing.

## Stretch goals

- Add a `power` function with tests for a negative exponent and `0 ** 0`.
- Add a GitHub Actions workflow that runs the suite.
- Add a coverage threshold that fails the build.

## Common mistakes

Copying the implementation into the test, such as `assert add(a, b) == a + b`, which cannot fail. Testing only the happy path. Chasing 100 percent coverage while asserting nothing.
