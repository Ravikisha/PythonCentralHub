## Goal

Create a pipeline that runs:

- linting
- unit tests
- integration tests
- (optional) deployment to a staging environment

## Suggested steps

1. Build a simple Flask API
2. Add pytest tests
3. Add GitHub Actions workflow
4. Add coverage reporting

## Tips

- keep secrets out of git
- use environment variables in CI
- deploy only from main branch

## Scenario

You have a small Flask API and want every pull request to be checked automatically, and main to be deployable at any time. You will build the app, tests and pipeline in small steps, with a working state after each one.

## Step 1: a testable app

Use an application factory, so tests can create an isolated app.

```python title="app.py" showLineNumbers{1}
from flask import Flask, jsonify


def create_app():
    app = Flask(__name__)

    @app.get("/health")
    def health():
        return jsonify(status="ok")

    @app.get("/add/<int:a>/<int:b>")
    def add(a, b):
        return jsonify(result=a + b)

    return app
```

## Step 2: tests with the Flask test client

```python title="test_app.py" showLineNumbers{1}
import pytest

from app import create_app


@pytest.fixture
def client():
    return create_app().test_client()


def test_health(client):
    r = client.get("/health")
    assert r.status_code == 200
    assert r.get_json() == {"status": "ok"}


def test_add(client):
    assert client.get("/add/2/3").get_json() == {"result": 5}


def test_add_rejects_text(client):
    assert client.get("/add/two/3").status_code == 404
```

The test client calls the app in-process, with no server and no network, so it is fast and belongs with unit tests.

## Step 3: local quality checks

Add `black`, `flake8` and `pytest-cov` to a `requirements-dev.txt`, with pinned versions. Get all of `black --check .`, `flake8 .` and `pytest --cov=app` to pass locally before you touch CI.

## Step 4: the workflow

```yaml
name: ci
on:
  pull_request:
  push:
    branches: [main]

jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: black --check .
      - run: flake8 .
      - run: pytest --cov=app --cov-fail-under=80
```

`--cov-fail-under=80` fails the build if coverage drops below 80 percent, which acts as a floor, not a goal.

## Step 5: deployment on main only

Add a `deploy` job with `needs: quality` and `if: github.ref == 'refs/heads/main'`. Read the deploy token from `secrets`. For practice, the job can push a Docker image to a registry or call a staging platform, and afterwards run a smoke test against `/health`.

## Checklist

- A pull request with a failing test shows a red check.
- Branch protection requires the `quality` job.
- Secrets are never printed or committed.
- Deployment is skipped for pull requests from forks.

## Common mistakes

Unpinned dependencies make CI fail with no code change. Deploying from every branch pushes half-finished work. A pipeline that takes 15 minutes because nothing is cached tempts people to skip it.
