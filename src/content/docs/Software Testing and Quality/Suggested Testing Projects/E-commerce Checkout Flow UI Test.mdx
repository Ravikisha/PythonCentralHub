## Goal

Automate a critical user flow:

- browse product
- add to cart
- checkout

## Requirements

- use explicit waits
- use stable selectors (`data-testid`)
- implement Page Objects

## Suggested structure

- `pages/` (page objects)
- `tests/` (test scenarios)

## CI tip

Run UI tests in headless mode and store screenshots on failure.

## Scenario

A shop lets visitors browse products, add one to the cart and pay. Automate this journey in a real browser with Playwright or Selenium, structured so a UI change breaks one file, not the whole suite. This is the type of test the test pyramid says to keep few but valuable.

## Choose the target

Use a public demo shop, such as one built for automation practice, or run a small shop of your own locally. Do not test a real shop with real payments. If you write your own, add `data-testid` attributes to the elements you will use.

## Plan the structure

```text
checkout_tests/
  pages/
    product_page.py
    cart_page.py
    checkout_page.py
  tests/
    test_checkout.py
  conftest.py
```

Each page object exposes actions (`add_to_cart`, `proceed_to_checkout`, `fill_shipping`, `place_order`) and state (`cart_count`, `order_confirmation_text`). Tests assert, and page objects never do.

## Example with Playwright

```python title="pages/product_page.py" showLineNumbers{1}
from playwright.sync_api import Page


class ProductPage:
    def __init__(self, page: Page):
        self.page = page

    def open(self, base_url: str, slug: str):
        self.page.goto(f"{base_url}/products/{slug}")

    def add_to_cart(self):
        self.page.get_by_test_id("add-to-cart").click()

    def cart_count(self) -> str:
        return self.page.get_by_test_id("cart-count").inner_text()
```

```python title="tests/test_checkout.py" showLineNumbers{1}
from playwright.sync_api import expect

from pages.product_page import ProductPage


def test_add_product_updates_cart(page, base_url):
    product = ProductPage(page)
    product.open(base_url, "blue-mug")
    product.add_to_cart()
    expect(page.get_by_test_id("cart-count")).to_have_text("1")
```

Extend the test to reach the confirmation page. Use `expect` for anything that appears after a click, and never `sleep`.

## Data and state

Do not click through the UI for setup when an API call can do it. For example, create the user or the cart through the API, then start the browser test at checkout. Use a fresh user per run, or reset the database, so tests do not depend on what previous runs left behind.

## Failure evidence

Configure the run to keep a trace or screenshot on failure, and upload it as a CI artifact. Run headless in CI, and headed locally when debugging.

## Stretch goals

- Add a negative test: an invalid card shows an error and creates no order.
- Run the same test in Chromium and Firefox.
- Add one smoke test that only checks the home page loads, and run it after each deployment.

## Common mistakes

Fixed sleeps, selectors copied from the browser as long XPaths, one giant test for the whole journey, and testing every discount rule through the UI. Discount rules belong in unit tests.
