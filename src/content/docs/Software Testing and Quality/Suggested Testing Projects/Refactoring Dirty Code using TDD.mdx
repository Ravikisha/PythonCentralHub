## Goal

Practice real-world refactoring:

1. write characterization tests (what the code does today)
2. refactor in small steps
3. keep tests green

## Approach

- find a messy function (long, many branches)
- write tests for current behavior
- refactor into smaller functions

## Tips

- don’t change behavior while refactoring
- use coverage to find untested paths
- commit frequently

## Scenario

You inherit a function that works, nobody dares to touch, and has no tests. Your job is to make it cleaner without changing what it does. The order matters: first pin the behaviour with tests, then change the structure in small steps.

## The dirty code

```python title="legacy.py" showLineNumbers{1}
def calc(o):
    t = 0
    for i in o["items"]:
        t = t + i["p"] * i["q"]
    if o["c"] == "GOLD":
        t = t - t * 0.2
    elif o["c"] == "SILVER":
        t = t - t * 0.1
    if t > 100:
        t = t - 5
    return round(t, 2)
```

The names are cryptic, the rules are hidden, and the function does three things at once.

## Step 1: characterization tests

You do not know the intended rules, so write tests that record what the code does today. Run it with several inputs and copy the results into asserts.

```python title="test_legacy.py" showLineNumbers{1}
import pytest

from legacy import calc


def order(customer, *lines):
    return {"c": customer, "items": [{"p": p, "q": q} for p, q in lines]}


@pytest.mark.parametrize(
    "o, expected",
    [
        (order("NONE", (10, 2)), 20.0),
        (order("GOLD", (10, 2)), 16.0),
        (order("SILVER", (10, 2)), 18.0),
        (order("NONE", (60, 2)), 115.0),
        (order("GOLD", (100, 2)), 155.0),
        (order("NONE"), 0.0),
    ],
)
def test_current_behaviour(o, expected):
    assert calc(o) == expected
```

These tests tell you that the flat 5 discount applies after the tier discount, and that an empty order gives 0. If any behaviour looks like a bug, note it in a comment and keep the test, then decide separately whether to fix it.

## Step 2: refactor in small steps

Run the tests after every change.

1. Rename `calc` to `order_total` and the variables to `subtotal`, `lines`, and so on.
2. Extract `subtotal(items)`.
3. Extract `tier_discount(customer)` using a dictionary.
4. Extract the threshold rule into `apply_bulk_discount`.

```python title="refactored.py" showLineNumbers{1}
TIER_DISCOUNT = {"GOLD": 0.2, "SILVER": 0.1}
BULK_THRESHOLD = 100
BULK_DISCOUNT = 5


def subtotal(items):
    return sum(i["p"] * i["q"] for i in items)


def order_total(order):
    total = subtotal(order["items"])
    total -= total * TIER_DISCOUNT.get(order["c"], 0)
    if total > BULK_THRESHOLD:
        total -= BULK_DISCOUNT
    return round(total, 2)
```

Point the same tests at `order_total`. When they pass, the behaviour is unchanged.

## Step 3: new behaviour with the real TDD loop

Now that the code is clean, add a feature test-first: "PLATINUM customers get 30 percent". Write the failing test, add the entry to the dictionary, then run everything.

## Use coverage as a guide

Run `pytest --cov --cov-branch --cov-report=term-missing`. Any branch not exercised by the characterization tests, such as an unknown customer tier, is a place where your refactor could change behaviour unnoticed. Add a test for it before you touch that line.

## Common mistakes

Changing behaviour and structure in the same commit. Refactoring without a passing test run after each step. Rewriting the whole function at once. Commit after every green step so you can go back to the last good state.
