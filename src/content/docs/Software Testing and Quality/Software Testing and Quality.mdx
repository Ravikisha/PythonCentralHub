## What you’ll learn

This module covers both:

- **QA theory** (how teams ensure quality)
- **hands-on testing in Python** (unittest, pytest, automation)

## Why this matters

Testing is how engineers ship changes confidently.

Good testing practices reduce:

- production bugs
- incident time
- expensive rework

Start with **Phase 1** to understand the fundamentals, then move into unit testing and automation.

## How the module is organised

The module has seven phases plus a set of projects. Each phase builds on the one before it.

| Phase | Focus | You will be able to |
| --- | --- | --- |
| 1. Testing fundamentals | QA theory, principles, SDLC and STLC | Explain why and how teams test, and choose an approach |
| 2. Levels of testing | Unit, integration, system, UAT, regression, smoke | Pick the right level for a given risk |
| 3. unittest | Python's built-in framework | Write, organise and run test cases |
| 4. pytest | Fixtures, parametrization, mocks, coverage | Write concise, maintainable tests |
| 5. API and web automation | requests, Selenium, Playwright, BDD | Automate checks above the unit level |
| 6. Static analysis | Linting, formatting, types, security | Catch problems without running code |
| 7. CI/CD and workflow | GitHub Actions, TDD, bug reports | Run tests automatically and work like a QA team |

## How to work through it

Read Phase 1 first, even if you only want code. It gives you the vocabulary (verification, regression, smoke) that the later phases use without explanation. Then choose one of the two Python framework phases. Phase 3 shows the standard library, and Phase 4 is what most projects use today. Doing both is worthwhile, since pytest can run unittest tests and you will meet both in real code.

Type the examples. A test you have watched fail and then pass teaches more than one you have only read. Try changing the code under test to break it on purpose and see what the test says.

## What you need

Python 3.10 or later, a terminal, and a virtual environment. Install the tools when a phase asks for them:

```bash
python -m venv .venv
pip install pytest pytest-cov requests
```

Browser automation in Phase 5 also needs a browser, and the CI lessons assume a GitHub account. Most exercises in the lessons run in the browser sandbox and need no setup.

## Projects

The last section has five projects that combine several phases: a calculator test suite, an API validation suite, a UI checkout test, a CI pipeline for a Flask app, and a TDD refactoring exercise. Do at least one to check that the pieces fit together.

## A note on expectations

Testing does not prove there are no bugs, and this module will not make software perfect. It will help you find problems earlier, catch regressions automatically and describe quality with evidence.
