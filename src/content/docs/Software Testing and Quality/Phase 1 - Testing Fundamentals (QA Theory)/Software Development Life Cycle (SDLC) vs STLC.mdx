## SDLC (Software Development Life Cycle)

SDLC describes phases to build software:

1. requirements
2. design
3. implementation
4. testing
5. deployment
6. maintenance

## STLC (Software Testing Life Cycle)

STLC describes phases to plan and execute testing:

1. requirement analysis (testable acceptance criteria)
2. test planning (scope, tools, risk)
3. test case design
4. test environment setup
5. test execution
6. test closure (reports, lessons learned)

## Key takeaway

SDLC builds the product.

STLC ensures the product is verified systematically.

## How the two relate

SDLC answers "how do we build this?" and STLC answers "how do we check it?". The mistake is to read STLC as something that starts after implementation. In the diagram, requirement analysis runs alongside SDLC requirements, and test case design runs alongside design. Only execution waits for working code.

## A worked example

Suppose the requirement says "users can reset their password by email".

- **Requirement analysis (STLC 1).** A tester asks what "by email" means. How long is the link valid? What happens if the address is unknown? Each answer becomes a testable criterion. This is cheap here and expensive after coding.
- **Test planning (STLC 2).** Decide scope (web only, not mobile), tools (pytest plus a test mail server) and risks (account takeover is severe).
- **Test case design (STLC 3).** Write cases for a valid link, an expired link, a reused link and an unknown address.
- **Environment setup (STLC 4).** Provide a staging database and a fake mailbox, so no real emails are sent.
- **Execution (STLC 5).** Run the cases and log defects.
- **Closure (STLC 6).** Report results, remaining risks and lessons, for example "expiry logic was ambiguous in the requirements".

Test case design can be written down as tests before the feature exists:

```python title="test_password_reset.py" showLineNumbers{1}
import pytest


@pytest.mark.skip(reason="feature not built yet")
def test_expired_link_is_rejected():
    ...


@pytest.mark.skip(reason="feature not built yet")
def test_link_can_only_be_used_once():
    ...
```

Skipped tests are placeholders that record the design. They are removed as each one is implemented.

## What goes wrong

- **Testing joins late.** Requirements are ambiguous, bugs are found at the end and the release slips.
- **Environment setup is ignored.** Tests fail because staging differs from production, not because of a bug.
- **Closure is skipped.** The same lessons are relearned each release.
- **Treating STLC as a waterfall.** In agile teams the six stages happen inside every sprint, in a small form.
