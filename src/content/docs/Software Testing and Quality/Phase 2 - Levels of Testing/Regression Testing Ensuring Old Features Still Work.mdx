## What regression testing is

Regression testing ensures:

- new changes don’t break existing features

It’s triggered by:

- bug fixes
- refactors
- new features
- dependency upgrades

## Manual vs automated regression

- manual regression: slow but useful sometimes
- automated regression: fast and repeatable

## Build a regression suite

Start with:

- critical user flows
- high-risk modules
- recently buggy areas

## The idea

A regression is something that used to work and no longer does. Regression testing is re-running checks after a change to confirm nothing else moved. The changes that cause regressions look harmless: a refactor, a dependency upgrade, a one-line fix.

## The best regression test is a bug you already had

When you fix a bug, first write a test that fails because of it. Then fix the bug and watch the test pass. That test stays in the suite permanently.

```python title="test_regression_coupon.py" showLineNumbers{1}
def normalize_coupon(code: str) -> str:
    return "".join(code.split()).upper()


def test_coupon_with_spaces_regression():
    # Bug #412: "SAVE 10" caused a 500 at checkout
    assert normalize_coupon("SAVE 10") == "SAVE10"


def test_coupon_lowercase():
    assert normalize_coupon("save10") == "SAVE10"
```

Naming the bug in a comment tells the next person why the test exists and stops someone deleting it during cleanup. This links to the bug report lesson, where the same coupon case is used.

## Choosing what to run

Running everything is ideal and often possible for a fast suite. When the suite grows slow, choose by risk:

- **Full regression** before a release, usually in CI overnight.
- **Selective regression** on a pull request: tests covering the changed area plus critical flows.
- **Smoke tests** on every deployment, described in the next lesson.

pytest markers help here, for example `pytest -m "not slow"` on each commit and the full run nightly.

## What goes wrong

- **Suites nobody trusts.** Flaky tests make people rerun until green, and real regressions slip through.
- **Suites that only grow.** Duplicate and obsolete tests slow feedback. Review and delete tests that check removed behaviour.
- **Only automated.** New features need exploratory testing too, because regression tests only check what you already knew to check.
- **Fixing the test to make it pass.** If an old test fails, first decide whether the behaviour change was intended.

## Connections

Regression suites are the main reason to automate, as the manual versus automated lesson argues. CI runs them on every change. Coverage reports show which parts of the code no regression test protects.
