## Why Playwright?

Playwright is modern and provides:

- auto-waiting for elements
- browser contexts (isolated sessions)
- fast execution

## Example (sync API)

```python title="playwright_basic.py" showLineNumbers{1}
from playwright.sync_api import sync_playwright


def test_example():
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto("https://example.com")
        assert "Example" in page.locator("h1").inner_text()
        browser.close()
```

## Notes

- Playwright also supports async API.
- Prefer `data-testid` selectors for stability.

## What makes it different

Playwright drives Chromium, Firefox and WebKit through one API. Its biggest practical feature is **auto-waiting**: before clicking, it checks that the element is attached, visible, stable and enabled, and it waits for that to be true. Most of the timing code you write with Selenium is not needed.

The pytest plugin, `pytest-playwright`, supplies a ready-made `page` fixture, so tests are short. Install with:

```bash
pip install pytest-playwright
playwright install
```

The second command downloads the browsers.

## A test with the pytest plugin

```python title="test_playwright_login.py" showLineNumbers{1}
from playwright.sync_api import Page, expect


def test_login(page: Page):
    page.goto("https://staging.example.com/login")
    page.get_by_test_id("email").fill("qa@example.com")
    page.get_by_test_id("password").fill("S3cret!pw")
    page.get_by_role("button", name="Sign in").click()

    expect(page.get_by_role("heading", name="Dashboard")).to_be_visible()
```

Run it with `pytest --headed` to watch, or without flags for headless mode. Notice the last line. `expect(...)` is a web-first assertion that retries until it passes or times out, unlike a plain `assert` on text you read once. Prefer it for anything that appears after an action.

## Locators that survive change

`get_by_role`, `get_by_label` and `get_by_test_id` describe what the user sees or a stable attribute, and they are more robust than CSS chains. `get_by_role` also nudges you towards accessible markup, since an element with no role is hard to find.

## Contexts and speed

A browser **context** is an isolated profile with its own cookies and storage, and creating one takes milliseconds. The plugin gives every test a fresh context, so tests do not share logins. To skip the login screen, save the signed-in state once and reuse it, which cuts a lot of time from a suite.

## Debugging tools

- **Tracing** records screenshots, DOM snapshots and network calls, and you replay a failed run in the trace viewer. Run `pytest --tracing=retain-on-failure`.
- **Codegen** (`playwright codegen URL`) records your clicks as code, useful as a starting point but not as finished tests.
- **Screenshots and video** can be kept on failure with plugin flags.

## What goes wrong

Using `time.sleep` out of habit, reading text once and asserting on it instead of using `expect`, and writing long end-to-end flows that fail for unrelated reasons. As with Selenium, keep UI tests few and apply the Page Object idea when the suite grows.
