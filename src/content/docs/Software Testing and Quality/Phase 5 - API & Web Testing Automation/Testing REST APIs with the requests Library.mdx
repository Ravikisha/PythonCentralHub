## Basic API check

```python title="api_test_requests.py" showLineNumbers{1}
import requests


def test_status_and_json_shape():
    r = requests.get("https://httpbin.org/json", timeout=10)
    assert r.status_code == 200

    data = r.json()
    assert "slideshow" in data
    assert "title" in data["slideshow"]
```

## Use sessions for many calls

```python title="api_session.py" showLineNumbers{1}
import requests


def test_many_calls():
    with requests.Session() as s:
        s.headers.update({"User-Agent": "qa-suite/1.0"})
        r = s.get("https://httpbin.org/get", timeout=10)
        assert r.status_code == 200
```

## Tips

- Always set **timeouts**
- Prefer stable environments (staging)
- Validate both happy path and error responses

## Why the examples above use timeouts

`requests` waits forever by default. A test without a timeout can hang your CI job for hours when a server stalls. Always pass `timeout=`, as both examples do.

## Test the contract, not every value

Check the status code, the shape and types of the body, and important values. Avoid asserting on things that change, like timestamps or generated ids.

```python title="test_api_contract.py" showLineNumbers{1}
import requests

BASE = "https://httpbin.org"


def test_get_returns_expected_fields():
    r = requests.get(f"{BASE}/get", params={"q": "pytest"}, timeout=10)
    assert r.status_code == 200
    assert r.headers["Content-Type"].startswith("application/json")

    body = r.json()
    assert body["args"] == {"q": "pytest"}
    assert isinstance(body["headers"], dict)


def test_status_endpoint_reports_404():
    r = requests.get(f"{BASE}/status/404", timeout=10)
    assert r.status_code == 404
```

The second test checks the error path, which is as important as the happy path. Include bad input, missing auth, and a resource that does not exist.

## A test client fixture

Put the base URL and shared headers in one fixture, so tests stay short and you can point them at staging or local by changing an environment variable.

```python title="conftest.py" showLineNumbers{1}
import os

import pytest
import requests


@pytest.fixture(scope="session")
def api():
    s = requests.Session()
    s.headers["Authorization"] = "Bearer " + os.environ.get("API_TOKEN", "test-token")
    s.base_url = os.environ.get("API_URL", "http://localhost:8000")
    yield s
    s.close()
```

A `Session` does not have a `base_url` by default, so this sets it as a plain attribute and tests build URLs with `api.base_url + "/users"`. Sessions also reuse connections, which makes a suite faster.

## Checking a schema

Asserting key by key becomes long. For larger responses, validate against a schema with a library such as `jsonschema` or `pydantic`, so a renamed field fails in one place with a clear message.

## What goes wrong

- **Calling real services in CI.** The tests fail when the network or the service is down, and they can cost money. Use a local test server or recorded responses, as the API fundamentals lesson advised.
- **Tests that depend on order.** One test creates a record and the next reads it. Create what you need in each test, and clean up.
- **Only checking the status code.** A 200 with an empty or wrong body is still a bug.
- **Secrets in code.** Read tokens from environment variables.
