## When Selenium is the right tool

- you must test real browser rendering
- you need to click, type, and navigate
- pages are dynamic

## Minimal example

```python title="selenium_smoke.py" showLineNumbers{1}
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


def test_homepage_title():
    driver = webdriver.Chrome()
    try:
        driver.get("https://example.com")
        h1 = WebDriverWait(driver, 10).until(
            EC.visibility_of_element_located((By.TAG_NAME, "h1"))
        )
        assert "Example" in h1.text
    finally:
        driver.quit()
```

## Best practices

- Prefer **explicit waits**
- Use stable selectors (id, data-testid)
- Keep UI tests few (test pyramid)

## How Selenium works

Selenium sends commands from your Python code to a browser driver, which controls a real browser. Your test says "find the element with this locator and click it", and the browser does it. Recent Selenium versions download the matching driver for you, so `webdriver.Chrome()` usually works on its own.

Because the browser runs in a separate process, the page loads and updates asynchronously. Nearly every UI test failure comes from your code being faster than the page.

## Waits are the whole game

A fixed `time.sleep(3)` is either too short (test fails on a slow machine) or too long (suite crawls). An explicit wait polls until a condition is true, and continues at once.

```python title="test_login_ui.py" showLineNumbers{1}
import pytest
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


@pytest.fixture
def driver():
    opts = webdriver.ChromeOptions()
    opts.add_argument("--headless=new")
    d = webdriver.Chrome(options=opts)
    yield d
    d.quit()


def test_login_shows_dashboard(driver):
    driver.get("https://staging.example.com/login")
    wait = WebDriverWait(driver, 10)

    wait.until(EC.visibility_of_element_located((By.CSS_SELECTOR, "[data-testid=email]"))).send_keys("qa@example.com")
    driver.find_element(By.CSS_SELECTOR, "[data-testid=password]").send_keys("S3cret!pw")
    driver.find_element(By.CSS_SELECTOR, "[data-testid=submit]").click()

    heading = wait.until(EC.visibility_of_element_located((By.TAG_NAME, "h1")))
    assert heading.text == "Dashboard"
```

The driver is a fixture, so the browser is always closed, even when the test fails. Headless mode lets the same test run in CI without a display.

## Choosing locators

Prefer, in order: a dedicated attribute such as `data-testid`, then an id, then a short CSS selector. Avoid long XPath chains that copy the page structure, since they break when a designer adds a wrapper div. Text-based locators break when copy or language changes.

## What goes wrong

- **Flaky tests from timing.** Fix with waits for a specific condition, not sleeps.
- **Stale element errors.** The page re-rendered and your saved element is gone, so find it again.
- **Shared login state.** Each test logging in through the UI is slow. Log in through the API once, or reuse cookies.
- **Too many UI tests.** They are the slowest and most fragile layer, as the test pyramid says.
- **No evidence on failure.** Save a screenshot when a test fails, or you will spend time guessing.
