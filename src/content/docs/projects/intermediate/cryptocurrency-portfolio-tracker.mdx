## Abstract
This is the most ambitious project in the intermediate track — a full cryptocurrency portfolio platform that pulls live prices, stores your holdings and transactions in a relational database, computes professional risk and performance metrics, runs technical-analysis indicators, fires automated price alerts on a schedule, and serves it all through a Flask web dashboard. Rather than walk every line of 1,200+, this guide teaches it the way you'd actually understand a real codebase: **by its architecture**. Five focused classes, each with one job, wired together by a Flask app. Learn how they collaborate and you can extend any of them.

You will leave understanding:
- How to separate concerns across **API**, **database**, **analytics**, **technical-analysis**, and **alerting** layers.
- How a normalized SQLite schema models portfolios, holdings, and transactions.
- How financial metrics (P/L, allocation, Sharpe ratio, max drawdown, HHI diversification) are computed.
- How background scheduling powers live alerts and periodic snapshots.

## The Architecture

The app is five classes plus a Flask front end. Each layer depends only on the ones below it:

```
┌─────────────────────────────────────────┐
│ CryptoPortfolioApp (Flask routes + UI)   │
├───────────────┬───────────────┬──────────┤
│ PortfolioAnalyzer │ TechnicalAnalyzer │ AlertManager │
├───────────────┴───────────────┴──────────┤
│ CryptoDatabase (SQLite)   CryptoAPI (HTTP)│
└─────────────────────────────────────────┘
```
This separation is the real lesson: each class is independently testable and replaceable. Swap CoinGecko for Binance and only `CryptoAPI` changes.

## Layer 1: `CryptoAPI` — Data with Caching and Rate Limits

Talking to a public API responsibly means caching results and respecting rate limits:
```python title="cryptoportfoliotracker.py"
def _rate_limit_check(self):
    now = time.time()
    while self.api_calls and self.api_calls[0] <= now - 60:
        self.api_calls.popleft()                 # drop calls older than 60s
    if len(self.api_calls) >= self.max_calls_per_minute:
        time.sleep(60 - (now - self.api_calls[0]))
    self.api_calls.append(now)
```
A `deque` of timestamps enforces "max N calls per minute" — the sliding-window rate limiter every API client needs. Prices are also cached for 60 seconds, so repeated dashboard loads don't hammer CoinGecko:
```python title="cryptoportfoliotracker.py"
if symbol in self.price_cache:
    cache_time, price = self.price_cache[symbol]
    if time.time() - cache_time < self.cache_duration:
        cached_prices[symbol] = price            # serve from cache
```

## Layer 2: `CryptoDatabase` — A Real Schema

Eight related tables model the whole domain. The key relationships:
```python title="cryptoportfoliotracker.py"
# portfolios belong to users; holdings & transactions belong to portfolios
CREATE TABLE holdings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    portfolio_id INTEGER NOT NULL,
    symbol TEXT NOT NULL,
    amount REAL NOT NULL,
    average_cost REAL NOT NULL,
    ...
    FOREIGN KEY (portfolio_id) REFERENCES portfolios (id)
)
```
Note the design choices: `FOREIGN KEY` constraints enforce relationships, a `CHECK(transaction_type IN ('buy','sell',...))` validates enums at the DB level, and `portfolio_snapshots` stores point-in-time JSON so historical performance can be replayed. This is how you model financial data that has to stay consistent.

## Layer 3: `PortfolioAnalyzer` — The Money Math

This is where holdings become insight. For each holding it computes current value and profit/loss:
```python title="cryptoportfoliotracker.py"
current_value = amount * current_price
profit_loss = current_value - (amount * avg_cost)
profit_loss_pct = (profit_loss / (amount * avg_cost)) * 100 if avg_cost > 0 else 0
```
Then portfolio-level risk metrics from the snapshot history:
```python title="cryptoportfoliotracker.py"
# Annualized volatility from daily returns
snapshots_df['daily_return'] = snapshots_df['total_value'].pct_change()
volatility = snapshots_df['daily_return'].std() * np.sqrt(365) * 100

# Sharpe ratio (risk-adjusted return, 0% risk-free assumed)
sharpe_ratio = (snapshots_df['daily_return'].mean() * 365) / (volatility / 100)

# Maximum drawdown — worst peak-to-trough drop
running_max = snapshots_df['total_value'].expanding().max()
max_drawdown = ((snapshots_df['total_value'] - running_max) / running_max).min() * 100
```
And a **diversification score** using the Herfindahl-Hirschman Index — a real concentration metric from economics:
```python title="cryptoportfoliotracker.py"
allocations = holdings_df['allocation_percentage'].values / 100
hhi = np.sum(allocations ** 2)               # 1.0 = everything in one coin
diversification_score = (1 - hhi) * 100      # higher = better diversified
```

## Layer 4: `TechnicalAnalyzer` — Indicators and Signals

Standard trading indicators, computed with pandas:
```python title="cryptoportfoliotracker.py"
def _calculate_rsi(self, prices, period=14):
    delta = prices.diff()
    gain = (delta.where(delta > 0, 0)).rolling(period).mean()
    loss = (-delta.where(delta < 0, 0)).rolling(period).mean()
    rs = gain / loss
    return (100 - (100 / (1 + rs))).iloc[-1]   # <30 oversold, >70 overbought
```
RSI, MACD, Bollinger Bands, and moving averages each cast a vote; the majority becomes a buy/sell/hold **signal**:
```python title="cryptoportfoliotracker.py"
buy_signals = signals.count('buy')
sell_signals = signals.count('sell')
return 'buy' if buy_signals > sell_signals else 'sell' if sell_signals > buy_signals else 'hold'
```
This ensemble-of-indicators approach is exactly how simple trading bots make decisions.

## Layer 5: `AlertManager` — Background Scheduling

Alerts run on a timer in a daemon thread, so the web app stays responsive:
```python title="cryptoportfoliotracker.py"
schedule.every(1).minutes.do(self._check_alerts)
monitor_thread = threading.Thread(target=self._run_monitor, daemon=True)
monitor_thread.start()
```
Each check fetches current prices, tests every active alert's condition (`price_above`, `change_below`, …), and — crucially — **debounces** so you aren't spammed:
```python title="cryptoportfoliotracker.py"
if last_triggered and datetime.now() - last_trigger_time < timedelta(hours=1):
    continue            # already alerted within the last hour
```

## The Flask Layer Ties It Together

Routes are thin — they delegate to the classes above and render templates:
```python title="cryptoportfoliotracker.py"
@self.app.route('/portfolio/<int:portfolio_id>')
def portfolio_detail(portfolio_id):
    metrics = self.analyzer.calculate_portfolio_metrics(portfolio_id)
    performance = self.analyzer.generate_performance_report(portfolio_id)
    return render_template('portfolio_detail.html', metrics=metrics, performance=performance)
```
Adding a transaction recomputes holdings with proper **average-cost** accounting:
```python title="cryptoportfoliotracker.py"
new_amount = old_amount + amount
new_total_cost = old_total_cost + (amount * price)
new_avg_cost = new_total_cost / new_amount     # weighted average cost basis
```

## Security Notes (Important)

The starter code makes choices fine for a demo but **not** for production:

| Demo code | Production fix |
|---|---|
| `app.secret_key = 'crypto_portfolio_secret_2024'` | Load from an environment variable; make it random |
| `hashlib.sha256(password)` for passwords | Use `bcrypt`/`argon2` with a salt — SHA-256 is too fast |
| `debug=True` | Never in production (exposes a code-execution console) |
| API keys in the DB | Encrypt with the included `Fernet` setup; never log them |
| `ssl.CERT_NONE` on WebSocket | Verify certificates |

## Common Mistakes

| Problem | Cause | Fix |
|---|---|---|
| `429 Too Many Requests` | Ignoring API limits | Use the rate limiter + price cache (built in) |
| Wrong P/L after selling | Cost basis not recalculated | Use weighted average-cost accounting |
| Volatility/Sharpe are `0` | No snapshot history yet | Let the snapshot scheduler run first |
| Alerts fire repeatedly | No debounce | Skip if `last_triggered` within an hour |
| App hangs on startup | Blocking work on the main thread | Run monitoring/snapshots in daemon threads |
| `ta-lib` won't install | Needs a system C library | Use the pandas-based indicators (no `ta-lib`) |
