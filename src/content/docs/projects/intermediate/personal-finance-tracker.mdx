## Abstract
This is the project where the standard library finally feels like an *application platform*. You'll build a personal finance manager that records income and expenses in SQLite, organizes them by category, tracks budgets and savings goals, and surfaces everything in a tabbed Tkinter dashboard with **live matplotlib charts embedded right in the window**. It exports and imports CSV/JSON, fires budget alerts, and generates plain-language insights about your spending. One engine (`PersonalFinanceTracker`) drives two front ends (GUI and CLI) — a clean separation worth studying.

You will leave understanding:
- How to model a real domain with related SQLite tables and SQL aggregation.
- How to embed a matplotlib figure inside Tkinter with `FigureCanvasTkAgg`.
- The "data class + view class" split that keeps logic out of the UI.
- How `GROUP BY` + `CASE` turn raw transactions into budgets, reports, and insights.

## Architecture: One Engine, Two Front Ends

```
PersonalFinanceTracker   ← all logic + SQLite (no UI code)
        ▲           ▲
        │           │
FinanceTrackerGUI   CLI menu (in main)
```
`PersonalFinanceTracker` knows nothing about Tkinter or `print` — it just exposes methods like `add_transaction`, `get_balance_summary`, `check_budget_status`. Both the GUI and the CLI call those same methods. This is the lesson: **keep business logic out of the UI** so you can put any face on it.

## Step-by-Step Explanation

### 1. The schema models the domain
Five tables — `categories`, `transactions`, `budgets`, `goals`, `accounts` — with `CHECK` constraints enforcing valid values at the database level:
```python title="personalfinancetracker.py"
CREATE TABLE categories (
    ...
    type TEXT CHECK(type IN ('income', 'expense')) NOT NULL,
    ...
)
```
A category is either income or expense, full stop — the database refuses anything else. Transactions reference categories via a `FOREIGN KEY`. Defaults are seeded once on first run (`populate_default_categories`).

### 2. Summaries via SQL aggregation
The balance summary is pure SQL — let the database do the math:
```python title="personalfinancetracker.py"
SELECT COALESCE(SUM(t.amount), 0)
FROM transactions t
JOIN categories c ON t.category_id = c.id
WHERE c.type = 'income'
```
`COALESCE(SUM(...), 0)` is the key detail: `SUM` of zero rows is `NULL`, which would break arithmetic — `COALESCE` turns it into `0`. The same query with `type = 'expense'` gives expenses; net worth is the difference.

### 3. Charts inside the window
This is the standout technique. A matplotlib figure lives *inside* Tkinter:
```python title="personalfinancetracker.py"
from matplotlib.backends.backend_tkagg import FigureCanvasTkAgg
self.fig, (self.ax1, self.ax2) = plt.subplots(1, 2, figsize=(12, 6))
self.canvas = FigureCanvasTkAgg(self.fig, charts_frame)
self.canvas.get_tk_widget().pack(fill='both', expand=True)
```
To update, you `clear()` the axes, redraw, and call `self.canvas.draw()`. No saving PNGs, no separate windows — the chart is a native widget. This pattern powers most Python desktop dashboards.

### 4. Tabs with `ttk.Notebook`
```python title="personalfinancetracker.py"
self.notebook = ttk.Notebook(self.root)
self.notebook.add(dashboard_frame, text="Dashboard")
self.notebook.add(transactions_frame, text="Transactions")
```
Each feature gets its own tab (Dashboard, Transactions, Budgets, Goals, Reports). `Notebook` is Tkinter's tabbed-container widget — the cleanest way to organize a multi-feature app.

### 5. Budget tracking with alerts
```python title="personalfinancetracker.py"
spent = ...   # SUM of transactions in the budget's category and date range
percentage = (spent / amount) * 100 if amount > 0 else 0
status = {..., 'alert': percentage >= (threshold * 100)}
```
Each budget compares spending against its limit and flags an alert past the threshold (default 80%). That `if amount > 0` guard avoids a division-by-zero crash on a zero budget.

### 6. Insights from the data
```python title="personalfinancetracker.py"
if summary['monthly_expenses'] > summary['monthly_income']:
    insights['warnings'].append("⚠️ You're spending more than you earn this month!")
savings_rate = (summary['monthly_savings'] / summary['monthly_income']) * 100
```
No AI needed — a few rules over the aggregated numbers produce genuinely useful guidance (overspending warnings, savings-rate praise, biggest-category callouts). Rules-over-data is often all "insights" requires.

### 7. Export / import
CSV for spreadsheets, JSON for programs:
```python title="personalfinancetracker.py"
writer.writerow(['ID','Amount','Description','Category','Type','Date',...])
writer.writerows(transactions)
```
Import is the reverse, auto-creating any missing category. Round-tripping your data is what makes the tool trustworthy.

## A Correctness Note: Use Cents, Not Floats

Money in `REAL`/`float` columns invites rounding errors (`0.1 + 0.2 != 0.3`). For real finance code:
```python title="money.py"
# Store integer cents, format on display
amount_cents = round(dollars * 100)
display = f"${amount_cents / 100:.2f}"
```
The starter uses floats for simplicity; switching to integer cents (or `Decimal`) is the right move for anything beyond a demo.

## Common Mistakes

| Problem | Cause | Fix |
|---|---|---|
| Totals show `None` | `SUM` over zero rows is `NULL` | Wrap in `COALESCE(SUM(...), 0)` |
| Chart doesn't refresh | Forgot `canvas.draw()` | `clear()` axes, redraw, then `draw()` |
| Rounding drift in balances | Floats for money | Store integer cents or use `Decimal` |
| Crash on zero budget | Division by zero | Guard `if amount > 0` |
| DB locked errors | One shared connection across threads | One connection per thread, or serialize access |
| Import fails on new category | Category didn't exist | Auto-create it (the code does) |
