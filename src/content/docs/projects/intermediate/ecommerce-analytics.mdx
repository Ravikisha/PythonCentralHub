## Abstract
This is a data-science capstone disguised as a business app. You'll build the analytics brain behind an online store: an 8-table SQLite warehouse (customers, products, orders, sessions, campaigns…), a synthetic-data generator so there's something to analyze, and a suite of real analytics — period-over-period sales growth, **RFM customer segmentation**, product profitability, marketing-channel attribution, a **machine-learning sales forecast**, and **cohort retention** analysis — all surfaced through a Plotly-powered Flask dashboard (plus a CLI). It's the project that connects SQL, pandas, scikit-learn, and web dashboards into one pipeline.

You will leave understanding:
- How a star-schema-style warehouse models an e-commerce business.
- **RFM** (Recency, Frequency, Monetary) segmentation with pandas `qcut`.
- How to engineer time-series features (lags, moving averages) and train a `RandomForestRegressor` to forecast sales.
- What cohort analysis reveals about retention — and the pandas idioms behind it.

## Step-by-Step Explanation

### 1. A warehouse, not just tables
Eight related tables model the whole funnel: `customers → sessions → product_views → orders → order_items`, plus `products`, `campaigns`, and `inventory_movements`. This is how analytics systems are structured — separate facts (orders, sessions) from dimensions (customers, products) so you can slice any way. `generate_sample_data()` then fabricates a realistic dataset so every analysis has something to chew on.

### 2. Sales overview with growth
```python title="ecommerceanalytics.py"
# current period vs the immediately preceding period of equal length
for metric in ['total_orders', 'total_revenue', 'avg_order_value', 'unique_customers']:
    if previous[metric] > 0:
        growth_rates[f"{metric}_growth"] = ((current[metric] - previous[metric]) / previous[metric]) * 100
```
Every metric is reported *with its growth rate* — comparing this 30 days to the previous 30. A number without a trend is almost useless in business analytics.

### 3. RFM customer segmentation
The crown jewel. RFM scores each customer on **Recency** (how recently they bought), **Frequency** (how often), and **Monetary** (how much), then labels them:
```python title="ecommerceanalytics.py"
df['recency_score']   = pd.qcut(df['recency_days'], 5, labels=[5,4,3,2,1])   # recent = high
df['frequency_score'] = pd.qcut(df['frequency'].rank(method='first'), 5, labels=[1,2,3,4,5])
df['monetary_score']  = pd.qcut(df['total_spent'], 5, labels=[1,2,3,4,5])

def segment_customers(row):
    if row['recency_score'] >= 4 and row['frequency_score'] >= 4: return 'Champions'
    elif row['recency_score'] <= 2 and row['frequency_score'] >= 4: return 'At Risk'
    ...
```
`pd.qcut` splits a column into 5 equal-sized buckets (quintiles) — note recency is reversed (recent buyers score *high*). The result is actionable: "Champions" get loyalty perks, "At Risk" get win-back emails. This is real CRM analytics in ~40 lines.

### 4. Product performance with a single query
```python title="ecommerceanalytics.py"
COALESCE(SUM(oi.total_price - (p.cost * oi.quantity)), 0) as profit
...
df['profit_margin'] = np.where(df['revenue'] > 0, (df['profit'] / df['revenue']) * 100, 0)
df['inventory_turnover'] = np.where(df['stock_quantity'] > 0, df['units_sold'] / df['stock_quantity'], 0)
```
One `LEFT JOIN` across products→order_items→orders yields units sold, revenue, and profit per product; pandas then derives margin and turnover. `np.where` is the vectorized guard against divide-by-zero — far faster than a Python loop.

### 5. Machine-learning sales forecast
This is where it gets serious. The forecaster engineers time-series features and trains a random forest:
```python title="ecommerceanalytics.py"
df['revenue_lag_1'] = df['revenue'].shift(1)      # yesterday
df['revenue_lag_7'] = df['revenue'].shift(7)      # same day last week
df['revenue_ma_7']  = df['revenue'].rolling(7).mean()   # weekly trend
...
revenue_model = RandomForestRegressor(n_estimators=100, random_state=42)
revenue_model.fit(X_train, y_train)
revenue_r2 = r2_score(y_test, revenue_model.predict(X_test))
```
**Lag features** (yesterday, last week) and **moving averages** let a regressor learn seasonality and momentum. It reports R² so you know how much to trust it, then rolls forward day-by-day to predict the next 30. This is the standard recipe for tabular time-series forecasting.

### 6. Cohort retention
Group customers by signup month, then track what fraction return in each later month:
```python title="ecommerceanalytics.py"
df['registration_month'] = df['registration_date'].dt.to_period('M')
cohort_table = cohort_data.pivot(index='registration_month', columns='period_number', values='customer_id')
```

The pivot turns a flat event log into the classic triangular cohort grid — the single most revealing view of whether a business actually retains customers.

### 7. Dashboard: Python computes, JS renders
The Flask app exposes each analysis as a JSON API; the browser fetches and renders with Plotly + jQuery. Charts are serialized server-side with `PlotlyJSONEncoder` and re-hydrated client-side — clean separation of compute and presentation.

## Two Bugs to Fix in the Source

This code targets older library versions. On a current stack it breaks in two spots:

| Line | Bug | Fix |
|---|---|---|
| `df['week_of_year'] = df['date'].dt.week` | `.dt.week` was **removed** in pandas ≥1.1 | `df['date'].dt.isocalendar().week` |
| `(df['order_month'] - df['registration_month']).apply(attrgetter('n'))` | `attrgetter` is **never imported** → `NameError` | `from operator import attrgetter`, or `.apply(lambda x: x.n)` |

Spotting version-rot like this is a real maintenance skill — the fix is small but the app won't run without it.

## Common Mistakes

| Problem | Cause | Fix |
|---|---|---|
| `AttributeError: 'dt' ... week` | Removed pandas accessor | Use `.dt.isocalendar().week` |
| `NameError: attrgetter` | Missing import | `from operator import attrgetter` |
| `qcut` "bin edges not unique" | Too many tied values for 5 bins | `rank(method='first')` first (the code does for frequency) |
| Forecast returns an error | < ~20 clean daily rows | Need more history; widen the date range |
| Misleading R² | Random forest overfits small data | More data; cross-validate; try simpler models |
| Dashboard charts blank | API error or empty data | Check the `/api/...` endpoints return JSON |
